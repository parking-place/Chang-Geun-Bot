# 02 — 타입 명령 등록부와 공통 실행 서비스

- 상태: **PLANNED**
- 선행: [01 계약](01_baseline_and_contracts.md).
- 명세: 4절·9절. 시험: R120-04/05.

## 목표

슬래시·자연어·Jev 질문·LLM 스키마가 같은 규격을 읽고, 어떤 입력 방식이든 같은 권한/데이터 변경/응답 기능에 도달하게 한다. 기존 `natural.py`의 정규식·서비스 실행·UI 혼합을 단계적으로 분리한다.

## 작업

1. 각 명령에 내부 ID, 기존 C-ID, 표시명/별칭/차별 설명, 인수 순서·타입·필수·nullable·기본값·범위·길이·cardinality·enum을 등록한다. `source_policy`, `selection_source`, 실제 목록 resolver/scope, entity 종류/허용 문맥, `execution_key`, 위험도·권한·확인 정책·응답 공개 범위·고정 handler도 등록한다. 재생목록/곡/채널은 실제 목록, 새 이름/검색어는 원문 추출로 명시한다.
2. C01~C47과 I01~I08 및 모든 공개 옵션을 실제 slash 정의에서 수집하고 등록부와 양방향 비교한다. 슬래시 정의와 자연어 정의를 수작업으로 이중 관리하지 않는다. 내부 `PLAYLIST_RESTORE`/`SETTINGS_UPDATE` 등을 새 공개 명령으로 노출하지 않는다.
3. 기존 C-ID는 호환 식별자로 유지하고 명세 예시의 `playlist.rename` 같은 의미 ID와 일대일 또는 명시적 별칭 관계로 연결한다. 모델/로그에서 ID를 바꿨다고 옛 기록을 소급 수정하지 않는다.
4. `application`에 공통 CommandService 경계를 만들고 기존 executor/watch/transfer/undo/generation·재생 서비스를 연결한다. `현재곡` 전용 표시, 계속의 입장/재개, 검색 후 선택, 만료곡 단건 재승인 등 기존 흐름을 보존한다.
5. Discord 어댑터는 입력을 내부 객체로 바꾸고 결과 view를 표시한다. 파서가 임의 함수를 import/eval하거나 `/명령 문자열`을 다시 파싱해 실행하지 않는다. 모델에 등록한 handler의 실제 실행은 코드의 고정 매핑만 허용한다.
6. 구조화 입력은 같은 service/validation 경로를 직접 사용한다. 올바르지 않은 slash 입력을 모델로 고쳐 다른 명령으로 실행하지 않는다. 기존 정확 별칭/구조화 제어의 모델0회 분류를 명시하고 자유 문장을 임의 정규식으로 구조화 명령에 편입하지 않는다.
7. 등록부에서 명령별 JSON Schema·Jev 질문용 설명·후속 질문/미리보기 텍스트를 생성한다. 필드와 권한 스키마의 drift를 fixture에서 검출한다. 정식 공개 명령 추가가 있으면 manifest/독립 평가 분모를 함께 갱신한다.

## 산출물

typed registry·C-ID 호환표·실행/표시 포트·schema 생성기·공개 명령/옵션 manifest·기존/신규 경로 동등성 fixture. 최종 모듈 위치는01단계의 의존성 경계를 따른다.

## 검증·종료 조건

- R120-04: 모든 공개 명령·옵션·8개 상호작용의 대응 누락0. 등록부와 slash 옵션/기본값/권한의 차이0. C39는 후보 제외/재귀0.
- R120-05: 같은 명령과 인수를 입력한 slash/기존 자연어/새 초안이 동일 service 효과와 공개 범위를 가진다. 쓰기·일괄·동명·검색 선택·주시 채널 변경의 실제 실행 경계도 검증한다.
- 모델 호출 없이 LXC의 격리DB·기록형 서비스로 먼저 검증한다. 자연어 전체 정확도는11단계이며 이 단계 통과로 대체하지 않는다.
- 기존 서비스 기능이 빠지면 등록부에 이름만 있다는 이유로 완료하지 않는다. 회귀를 통과할 때까지 신규 파서 활성화는 보류한다.
