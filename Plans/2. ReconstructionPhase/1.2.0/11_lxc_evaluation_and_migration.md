## 목적과 기준선

명령 이름만 고르는 정확도와 실제 명령·전체 인수·검증 결과가 맞는 정확도를 구분한다. 같은 소스·설정·등록부·모델 후보를 소스 실행과 설치 wheel에서 검증하고, 새 parser 계약과 기존 서비스 데이터의 복귀 가능성을 함께 확인한다.

계획 당시 활성 봇은 `patch117b`, gateway는 `patch116g`였다. p12d에 gateway를 `recon120p12dgw`로 전환했고 봇은 그대로다. `patch118a`는 미적용 소스/wheel 후보였다. 현재 실행 단위·원장과 제한 실호출 결과는 [실행 기록](../../../evidence/public/reconstruction-120-progress.md)에 남겼다. 실제 봇 전환 전 설치 wheel·서비스 설정·API 계약·업무 DB 스키마·원장 잔여량을 다시 기록한다.

[1.1.8 개발 증거](../../../evidence/public/patch-118-development-20260928.md)의 45/46은 개발 예문 의도 ID 성적이다. 369개 회귀, 과거 독립 평가 실패, 실제 Discord 미인수도 각각 별도 이력으로 유지하며 신규 독립 성적으로 전환하지 않는다.

## R120-27 — 소스·wheel·전수 회귀

2026-09-28 p11 개발 체크포인트에서 같은 공개 소스 manifest와 신규 bot/gateway wheel을 DiscordBotLXC 격리 경로에 빌드했다. 소스 우선 476/476, 신규 설치 wheel을 우선 import한 경로 476/476, 전체 Ruff·mypy64파일이 통과했다. [실행 기록](../../../evidence/public/reconstruction-120-progress.md)의 SHA·명령을 참조한다. 이 결과는 R120-27의 기존 테스트 회귀 근거이며 공개 옵션·상호작용 전수 대응이나 아래 R120-28~30 게이트를 닫지 않는다.

1. 변경 전후 manifest·wheel SHA·의존성·설정 지문·registry/normalizer/prompt/schema 버전을 고정한다. 비밀값은 지문 입력·보고서에서 제외한다.
2. 현재 등록된 C01~C47과 I01~I08의 명령·옵션·선택/확인·화면 대응표를 재검사한다. C39는 자연어 진입점이며 다시 자기 자신을 모델 후보로 실행하지 않는다.
3. 동일 후보의 source-first와 새 격리 설치 wheel에서 lint·타입·단위/mock·통합·안전 회귀를 실행한다. 활성 wheel에 다른 소스 테스트를 연결한 collection 실패를 PASS로 세지 않는다.
4. 초기/재해석 Jev, rewrite/full_parse, 정규화/source map, 원문 인수 근거, 권한·주시 세대·멱등성·확인/취소를 함께 검증한다. R120-08/09/12의 목록 기반 참조 선택은 문자열 구간 추출과 별도 시험표로 추적한다.
5. 기록형 대역으로 각 패스 3회·Jev 합계 6회·모드별 1회·전체 8회와 9번째 거부, 숨은 재시도 0회, deadline·늦은 응답·예약 경합을 검증한다.
6. trace 부모·자식 삭제, 정확히 7일 만료, usage unknown/null, 로그 장애 중 재실행 금지, 비밀값 마스킹·반입/내보내기를 포함한다.

종료 조건은 공개 명령/옵션/상호작용 대응 누락 0, 필수 결정적 회귀 전건 PASS, 소스와 설치 wheel 결과 불일치 0이다. 테스트 수가 이전보다 적다는 이유만으로 성공하지 않으며 삭제·대체한 테스트의 근거를 남긴다.

## R120-28 — 새 한국어 독립 평가

- 개발·튜닝 자료와 겹치지 않는 **최소 221문장**을 새로 작성한다. 최소 141개 명확 요청과 80개 누락·모호·미지원·부정·복합·공격/오류 사례로 시작하며 구성은 첫 실행 전에 잠근다.
- C01~C47 진입/명령 전수와 I01~I08 상호작용을 포함한다. 모든 공개 옵션·모드 조합의 결정적 회귀표는 221문장과 별도로 관리한다. 부족하면 평가 문장을 늘린다.
- 정답은 명령 ID, 모든 필수/선택 인수, 허용 기본값, 객체 범위, 예상 질문·거절·확인·최종 서비스 계획으로 작성한다. 잘못된 옵션을 맞은 명령 ID로 가리지 않는다.
- 여러 단어·인용·동명/중복 entry·조사처럼 보이는 제목·false·0·문자열 none·NFC·URL·멘션·다른 서버 ID·prompt injection과 rewrite 의미 변질을 포함한다.
- 플레이리스트·곡·채널처럼 열거 가능한 대상은 권한/조회 범위의 실제 목록을 기준으로 평가한다. 사용자 문장과 어휘가 겹치지 않아도 범위 안의 유효한 대상이 전달 목록에서 빠지지 않아야 한다.
- 목록의 완전성·snapshot revision·선택 ID의 해당 snapshot 소속과, 새 이름/검색어의 원문 구간 정답 포함률을 따로 채점한다. 모델이 목록 ID를 선택했다는 사실을 원문 의미 정답이나 최신 객체 검증 통과로 대신하지 않는다.
- 동명 객체·같은 곡의 중복 entry·선택 뒤 삭제/권한 변경·오래된 revision을 포함한다. 범위 밖 대상 혼입과 선택한 snapshot 밖 ID는 모두 거부한다.
- 지원 크기를 넘는 목록은 명시된 안내/범위 축소 결과를 기대한다. 조용한 top-K·어휘 필터·잘림이나 모든 페이지를 추가 호출해 상한을 우회하는 처리는 실패로 판정한다.
- 데이터 해시·정답 작성자/검수·후보 버전·채점 규칙·분모·실행 시각을 고정한다. 평가 결과를 보고 조정했다면 그 세트는 개발 회귀로 전환하고 새 독립 세트를 잠근다.
- **초기 제안 게이트:** 명확 요청의 명령+전체 인수 완전 일치율 ≥95%·명령군별 ≥90%, 시험 표본의 잘못된 실행 0건, 권한/다른 서버/원문 위조·금지 복합 작업의 차단 전건 PASS. 이는 아직 측정한 성적이 아니다.
- 미지원/누락 사례는 질문·거절 정답률과 과잉 거절률로 따로 보고한다. 안전한 거절도 명확 요청의 기능 성공으로 계산하지 않는다.
- 전체 평균 외에 명령군·경로·쓰기/읽기·관리자별 분모와 오답을 공개한다. 표본이 적은 그룹은 추가 검증 없이는 전체 지원으로 확대하지 않는다.

실행 없는 synthetic shadow에서 `executed_command=null`을 유지한다. 실제 서비스 호출을 차단한 대역의 의도/인수 성적과 격리 DB에서 실행한 결정적 회귀의 부작용 성적을 분리한다. 운영 메시지를 몰래 두 모델 경로에 재전송하지 않는다.

## R120-29 — 경로별 호출·지연·비용

p12d의 합성2건은 새 v2 gateway에서 Jev의 실제 전송/응답과 공유 예약 640→642를 확인했다. 모호한 문장은 `__NONE__`, 명확한 재생목록 조회는 `C01`로 선택됐다. p12e에는 합성 Jev→GPT 3경로를 추가해 reasoning-only incomplete와 수정 후 rewrite/full_parse 완료를 확인했다. 공유 Jev 예약은645, GPT 예약2005/실제521 micro USD이며 사용자 상한은1,000,000 micro USD다. 이는 아래 경로별 지연/독립 품질·원문 인수/복귀 평가를 충족하지 않는다.

| 측정 단위 | 기록할 값과 초기 제안 기준 |
| --- | --- |
| 최초 Jev 완료 | 목록 완전성/소속·원문 구간 정답 포함률을 분리하고 완전 해석률·호출/지연 p50/p95 기록; p95 ≤10초 제안 |
| rewrite → 재해석 | rewrite 전체/유효 변경/재해석 진입의 분모별 복구율; 경로 p95 ≤25초 제안 |
| full_parse 및 장애 직행 | 사유별 진입/복구·거절·timeout; 경로 p95 ≤35초 제안 |
| 요청 전체 | 최초 수신 기준 35초 상한, Jev 시도 5초·rewrite 5초·full_parse 10초 시작값; 남은 시간 내에서만 예약 |
| 원격 사용량 | Jev·LLM 작업별 예약/실제 전송·실패·사용량 미확인, 실제 token·금액·완전성 |

35초는 사용자 답변/확인 대기 시간을 제외한 추론 deadline의 시작 제안이며, 개별 timeout의 합만큼 자동 연장하지 않는다. 지연 목표·시험 분모·동시성·예산 상한은 첫 평가 전에 고정하고 실패 뒤 숫자를 바꿔 PASS를 만들지 않는다.

동일 잠금 세트로 새 전체 경로와 별도 `Jev → full_parse` 비교를 허용하되 서로 다른 실험으로 명시한다. 비운영 synthetic 입력·실행 차단·별도 지출 한도를 사용하고 요청을 중복 실행하지 않는다. 추가 실호출은 공통 원장에 모두 차감하며 기존 epoch/소비량을 초기화하지 않는다.

가격표와 사용량 근거가 있을 때만 실제 비용을 계산한다. 미제공 usage/내부 forward/가격은 null 또는 unknown으로 남기며 known 부분 합계와 누락 범위를 같이 표시한다. 키가 있다는 사실은 무제한 지출 허용이 아니다.

## R120-30 — 이관과 복귀 예행

1. 현존 스키마를 먼저 조사한다. 설계서의 trace v1 예시가 실제 DB에 있다고 가정하지 않는다. 업무 DB·보안 감사/사용량 원장과 7일 parser trace의 책임·수명을 분리한다.
2. synthetic 또는 비식별 격리 사본으로 신규 parser-api-v2/trace-v2 전환을 검증한다. 구 API1.2의 요청당 3회 계약은 유지하며 새 8회 계약을 구 endpoint에 조용히 적용하지 않는다.
3. v1이 존재하면 기존 Jev는 initial, fallback은 full_parse로 매핑한다. 없는 정규화/rewrite·usage는 null/not_recorded, 원래 request_id·created_at·expires_at·실행 결과는 보존한다.
4. 만료 원문은 이관 전에 제거한다. 사본·export·임시 파일도 원래 만료를 넘겨 보존하지 않는다. 업무 DB는 trace 삭제와 함께 지우지 않는다.
5. 새 schema를 구 바이너리가 읽는 복귀 경로를 차단한다. 호환 reader 또는 분리된 trace 파일을 사용해 기존 bot/gateway·설정 묶음으로 되돌리고, 새 원장 소비/예약은 보존한다.
6. 중단·부분 이관·재시작·중복 메시지·진행 중 확인/60초 continuation·사용량 미확인 요청을 시험한다. 만료되거나 구 계획에 묶인 요청을 재해석/재실행하지 않는다.

사용자가 지정한 **1.1.7 백업 검증 SKIPPED**는 유지한다. 이 단계는 격리 이관·복귀 검증이며 외부 저장소 백업 실험을 새 선행조건으로 추가하지 않는다. 만료 원문을 운영 로그·사본에 남기지 않는 정책 검사는 별도로 수행한다.

## 산출물과 종료 게이트

- 소스/wheel 회귀표, 명령·옵션·상호작용 전수표, 잠금 평가 manifest와 상세 판정, 경로별 지연/호출/비용 보고서.
- 실제 실행한 LXC 절차, 새·구 API 호환표, 격리 이관/복귀 결과, 원장 전후값과 비밀값 없는 설정 지문.

- 평가 통과는 실제 Discord 조작·청취·운영 인수 또는 정식 출시 PASS를 뜻하지 않는다.
