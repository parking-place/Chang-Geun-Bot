# 03 — 원문 보존·보수적 정규화·source map

- 상태: **IN_PROGRESS — 정규화/source map 개발시험 완료, 실제 자연어 경로 연결 대기**
- 선행: [01 계약](01_baseline_and_contracts.md), [02 등록부](02_registry_and_command_service.md).
- 명세: 2~3절·5.3~5.4·12.5. 시험: R120-06/07.

## 작업

1. 허용 진입점에서 원문을 변경 없이 보존한다. 봇/웹훅/DM/미주시 채널·빈 접두사 등 기존 필터를 먼저 적용한다. 호출 조건이 없는 일반 채팅은 모델 입력과 원문 명령 로그를 만들지 않는다.
2. `original_text`, `normalized_text`, `rewritten_text`를 다른 타입/필드로 유지한다. 로그용 마스킹본을 파서 입력이나 근거 검사에 되돌려 쓰지 않는다. 요청 길이·첨부 metadata 크기는 별도 입력 계약으로 제한한다.
3. 따옴표, URL·멘션, 접근 가능한 기존 이름의 정확 일치 구간을 먼저 보호한다. 닫히지 않은 인용은 나머지를 보수적으로 보호한다. 값인지 감탄인지 불명확하면 변경하지 않는다.
4. 보호 구간 밖 선후행 공백·연속 공백/탭만 정리하고 NFC는 해석 뷰에 적용한다. 호출 위치로 확인된 봇 멘션/접두사만 제거한다. 대상 채널/사용자 멘션, URL 경로, 일반 텍스트 `/재생`을 전역 삭제하지 않는다.
5. 전역 NFKC·소문자화·구두점 제거·조사 삭제·오탈자 교정·별칭 치환을 금지한다. 웃음 축약/ASR 규칙은 기본 비활성으로 남기고 추후 독립 검증 없이는 켜지 않는다.
6. Python Unicode code point 기준 `[start,end)` source map을 만든다. copy/collapsed whitespace/NFC 다대일/호출부 제거를 표현하고, 매핑된 값은 원문에서 `original[start:end] == raw_span`을 다시 확인한다.
7. 새 이름·검색어는 원문에서 독립 후보를 만들도록 연결한다. 정규화 과정에서 값 경계가 불확실하면 원문 후보/확인을 사용하며 정규화 문자열을 저장값으로 대체하지 않는다.
8. 빈 정규화 결과는 모델0회, 내부 정규화 오류는 명시 오류 안내로 종료한다. 오류를 숨기고 원문 경로로 자동 fallback하지 않는다. `code.normalize`에는 버전·규칙·변경 여부·시간·보호구간 수를 기록하고 model_calls는 만들지 않는다.

## 산출물

InputNormalizer·provenance/source-map 타입·보호구간 탐색기·원문 근거 검증기·한국어/Unicode fixture·이벤트 포트. 실제 원문을 포함한 임시 상태/사본은10단계의 부모 만료를 따른다.

## 검증·종료 조건

- R120-06: `너에게`, `쉼,표`, `RED`, 실제 이름 `none`, `ㅋㅋㅋㅋ`, 새 이름 `"퇴근  후"`, 닫히지 않은 따옴표가 손상되지 않는다. URL query와 대상 멘션을 보존한다.
- R120-07: 조합형 한글·이모지·반복된 동일 문자열·다대일 NFC·접두사 앞 공백에서 인덱스가 맞고 원문 근거 일치가 재현된다. 실패한 매핑의 실행값 채택0.
- 모든 fixture는 DiscordBotLXC에서 모델 없이 검증한다. 단위시험에 더해 무작위 Unicode 변형/경계 사례로 범위 밖 인덱스와 비연속 구간 합성을 검출한다.
- 보호구간 처리 성공은 rewrite 의미 보존 증명과 다르다. 원문 근거/인수 역할 검증은08/09단계에서도 유지한다.
