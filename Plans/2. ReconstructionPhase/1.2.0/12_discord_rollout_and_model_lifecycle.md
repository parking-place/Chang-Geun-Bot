## 출발 상태와 완료 경계

계획 출발 기록은 활성 bot `patch117b`/gateway `patch116g`, 소스·wheel 후보 `patch118a` 미적용이다. 이 문서를 작성하면서 실제 프로세스·설정·원장·모델 가용성을 새로 확인하지 않았다. 적용 직전 현재 상태와 Git SHA·설치 wheel·설정 지문을 다시 잠근다.

이 단계의 개발 후보 배포, 사용자 조작 인수, 버전 전체 완료, 정식 VERSION/태그는 각각 다른 판정이다. 계획 작성이나 키 파일 준비만으로 외부 API를 호출하거나 서비스를 교체하지 않는다. 구현 요청 이후에는 승인된 실행 범위에서 단계별 증거를 남긴다.

## R120-31 — 단계 적용과 실제 Discord 인수

1. 11단계와 동일한 후보 artifact를 준비하고 실행 설정·권한·TLS·DB/schema·보류 요청·원장 잔여량을 재확인한다. 정상 동작 중인 기존 서비스와 데이터의 복귀 참조를 남긴다.
2. 구 API1.2와 새 parser-api-v2의 endpoint·인증·budget scope·health/readiness를 구분한다. 신규 경로 비활성 기본값에서 slash/기존 버튼과 기존 경로의 smoke를 확인한다.
3. 허용된 테스트 서버·주시 채널·요청자 집합에만 새 경로를 적용한다. 일반 채팅/미주시 채널·타 봇 메시지는 외부 모델로 보내거나 명령 원문 로그로 수집하지 않는다.
4. 실행 없는 synthetic shadow의 성적을 확인한 뒤 실제 요청 처리를 한 경로로 전환한다. 운영 메시지를 비교 명목으로 자동 이중 전송하지 않으며 전환 순간에도 메시지 멱등성 키를 보존한다.
5. 읽기와 미리보기부터 확인하고 쓰기를 확대한다. 위험 작업과 LLM이 관여한 쓰기는 최초 정책상 실제 사용자 확인을 요구한다. 실제 인수 없이 확인을 생략하는 범위를 넓히지 않는다.
6. 기존 slash·버튼과 자연어를 같은 대상·옵션·권한에서 비교한다. 공개 명령 C01~C47와 I01~I08의 적용 가능 항목마다 결과와 한계를 남긴다.

| 실제 시험 묶음 | 확인할 결과 |
| --- | --- |
| 일반 읽기·페이지·개인 결과 | 올바른 화면/옵션·페이지/새로고침, 요청자 외 개인 결과 비공개 |
| 곡·목록·YouTube 검색/재생 | 대상·소스·검색 선택·대기열·일시정지/계속/정지가 기존 서비스와 일치 |
| 실제 목록에서 참조 선택 | 플레이리스트·곡·채널의 범위 안 목록에서 선택, 어휘 불일치 유효 대상 누락 0, snapshot 소속/최신 상태 재검증 |
| 목록 생성·이름 변경·추가/삭제 | 여러 단어·인용/공백·동명 대상·중복 entry를 정확히 구분, 확인 전 부작용 0 |
| 주시·관리자 명령 | 최신 역할/허용 채널 검사, 복구 진입 범위, 비공개 결과와 변경 이력 |
| 인수 질문·선택·확인·취소 | 60초 단회 typed continuation과 300초 확인을 구분, 다른 사용자·채널/서버 답변 거부 |
| rewrite/full_parse | 경로 표시와 trace 대응, 원문 근거·쓰기 확인 유지, 실패 때 서비스 미실행 |
| 경합·종료 | 중복 이벤트/버튼·취소·권한 철회·주시 세대 변경·deadline 뒤 늦은 답변의 부작용 최대 1회 |
| 비활성·장애 | disabled·키 없음·LLM 장애에서 숨은 대체 호출 없음, 사용자가 질문/실패 이유를 알 수 있음 |

음성 재생은 사람의 실제 청취와 조작 결과를 별도로 기록한다. 자동 PCM·모델 정답·서비스 로그가 청취 성공을 대신하지 않는다. 운영 데이터를 파괴하는 테스트 대신 제한된 시험 대상과 되돌릴 수 있는 자료를 사용한다.

실제 경로가 자연스럽게 발생하지 않으면 사전 고정한 시험 입력으로 확인한다. 실제 Discord에 mock 공급자를 켜거나 모델 결과를 조작해 인수를 만들지 않는다. 아직 관측하지 못한 경로는 NOT_RUN으로 남긴다.

목록 기반 참조는 동명 대상·중복 entry·조회 뒤 삭제/권한 철회·revision 변경을 실제 제한 시험 대상으로 확인한다. 지원 크기 초과 시 명시적 안내나 범위 축소를 제시해야 하며, 조용한 top-K/잘림·모든 페이지의 추가 모델 호출로 대체하지 않는다. 새 이름·검색어의 원문 추출 성적과 목록 전달 완전성은 서로 다른 인수 기록으로 남긴다.

## R120-32 — 모델 프로필 수명과 비활성 경로

p12 개발 체크포인트에서 gateway CLI에 기본 비활성 `--parser-v2`와 필수 `--llm-fallback disabled|gpt-5-nano`를 추가했다. v2는 Jev API와 영속 tombstone이 있을 때만 생성하며, 기존 API1.2와 한 dispatch semaphore를 공유한다. `disabled` 경로는 OpenAI 키 없이 시작할 수 있고 GPT 프로필은 키가 없으면 시작 전 오류로 멈춘다. 인증된 health의 `parser_v2_ready`와 v2 usage를 LXC 대역에서 확인했다. 이 코드는 **활성 서비스에서 사용하지 않았고** bot의 새 자연어 진입점도 아직 연결되지 않았다. [실행 증거](../../../evidence/public/reconstruction-120-progress.md)를 참조한다.

| 상황 | 전환 정책과 필수 근거 |
| --- | --- |
| 초기 nano 활성화 | rewrite/full_parse 각각의 실제 API·스키마·한국어·거절/timeout·usage 계약을 제한 예산에서 검증 |
| `LLM_FALLBACK=disabled` | 키 없이 시작 가능, LLM 객체/네트워크 호출 없음; Jev 성공은 유지하고 미해결은 질문/종료 |
| 모델·공급자 변경 | 두 작업 모두 공통 계약·회귀·새 잠금 평가·지연/비용 비교 후 명시적 프로필 전환 |
| 모델 접근 불가·종료 공지 | 영향 프로필/시한을 기록하고 검증된 대안 또는 disabled를 선택; 임의 모델명으로 자동 대체 금지 |
| Gemini/Luna 등 미구현 프로필 | 명시적인 설정 오류; nano로 조용히 대체하거나 부분 지원을 완료로 표시하지 않음 |
| 잘못된/레거시 설정 | 시작 전 오류와 수정 항목 표시, 기본 모델/timeout 추정 금지 |
| 모델 교체 중 요청 | 시작 당시 profile/prompt/schema/예산 고정, 늦은 응답으로 새 요청 생성·중복 실행 금지 |
| 캐시·로그·사용량 | 프로필·모델·prompt/schema 버전을 구분, 미제공 token은 null, 변경 전 소비량 보존 |

모델 수명 점검 담당과 확인 주기를 runbook에 정한다. 초기 제안은 월 1회 및 변경 공지 수신 시 공식 가용성/지원 종료 정보를 확인하는 것이다. 이 문서는 자동 알림·정기 작업을 생성하지 않는다.

공급자 교체 때 핵심 파서·검증기·로그 스키마를 다시 쓰지 않는지 계약 테스트로 확인한다. 실제 외부 key는 gateway 계정의 제한 저장소에서만 읽고 bot·Discord 메시지·공개 로그·추적 artifact에 전달하지 않는다.

## 중단·복귀 조건

잘못된 실행 1건, 권한/개인정보 경계 위반, 중복 부작용, 8회/하위 예산 초과, 만료 원문 노출을 발견하면 신규 경로를 중단한다. 지연/오류율/비용의 11단계 잠금 기준 초과도 확대를 멈추고 원인·분모를 기록한다.

먼저 신규 진입을 막고 진행 중 요청을 완료 또는 취소한다. 이미 전송된 호출의 usage unknown과 실제 서비스 결과 불명은 남기며 자동 재실행하지 않는다. 필요하면 `disabled` 또는 검증된 구 bot/gateway 묶음으로 복귀하고 구 API의 3회 계약을 다시 확인한다.

복귀는 업무 DB 변경·사용량 원장·예약·멱등성 기록을 과거 사본으로 덮어 예산이나 실행을 되돌리는 절차가 아니다. 11단계에서 검증한 호환 경로로 복귀하며 종료된 continuation/확인 계획을 부활시키지 않는다. trace 사본도 원래 7일 만료를 유지한다.

## R120-33 — 기존 미완료와 최종 증거

- [1.1 계열 상태](../../1.PatchPhase/STATUS.md)의 과거 FAIL·NOT_RUN과 실제 전건 인수 부족을 그대로 연결한다. 1.1.8의 typed continuation·상호작용/옵션 누락은 새 후보의 전수표로 해소 여부를 기록한다.
- 1.1.6 독립 품질 FAIL, 1.1.7 첫 PCM 94/100 FAIL·후속 100회/8시간·운영 수명 미인수는 자연어 품질로 닫지 않는다. 새 기능 인수와 기존 미디어/운영 전체 인수를 분리한다.
- 사용자 지정 **백업 검증 SKIPPED**를 보존한다. 서버 외부 백업 실시험을 새 출시 선행조건으로 되살리지 않으며, 이관 사본/trace 원문 만료 검사는 별도 책임으로 남긴다.
- 공개 증거에는 Git/manifest/wheel 식별자·설정 버전·시험 일시·경로별 분모·API 실제 소비·실제 사용자 결과·복귀 결과를 남긴다. 키·실제 원문·내부 접속 정보는 공개하지 않는다.
- 명세 §13.2 체크리스트와 R120 전수 대응에서 누락 0, 같은 후보의 필수 자동/실호출/실제 Discord 게이트 충족 시에만 1.2.0 DONE을 검토한다. 미완료는 별도 상태와 이유를 유지한다.

## 산출물과 종료 조건

후보 적용 기록·실제 Discord 전수 인수표·모델 전환/비활성 runbook·복귀 증거·기존 미완료 연결표를 만든다. 명세의 예시 모듈/명령을 실제 실행법으로 복사하지 않고 구현 후 LXC에서 실행한 절차만 runbook에 적는다.

R120-31~33의 증거가 마련되기 전에는 PLANNED/IN_PROGRESS를 유지한다. 정식 VERSION/태그·GitHub 출시 표시는 필수 게이트와 실제 요청 범위를 별도로 확인한 뒤 처리하며 이 계획 문서만으로 변경하지 않는다.
