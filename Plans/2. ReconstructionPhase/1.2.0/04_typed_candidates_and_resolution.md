# 04 — 실제 목록 전달·원문 값 추출·객체 해소

- 상태: **IN_PROGRESS — 목록 스냅샷·원문값·p12f 첨부 실제목록/재검증 개발시험 완료, 전체 collection/실제 Discord 인수 대기**
- 선행: [02 등록부](02_registry_and_command_service.md), [03 원문 근거](03_normalizer_and_provenance.md).
- 명세: 5절·6.4~6.6·8.3·9절 + **사용자 후속 지시: 명확한 목록이 있거나 구성 가능하면 후보 생성 대신 목록 전달**. 시험: R120-08/09.

## 입력 종류에 따른 분리

| 인수 | 기본 방식 | Jev에 전달하는 자료 |
| --- | --- | --- |
| 기존 재생목록 | `collection` | 현재 서버·호출자·명령 권한 범위의 실제 재생목록 전체 |
| 곡·목록 안의 곡·대기열 항목 | `collection` | 실제 카탈로그/선택한 목록/대기열의 항목과 구분 정보 |
| 채널 | `collection` | 명령에 맞는 실제 텍스트/음성 채널, 카테고리 등 최소 구분 정보 |
| 현재 요청 첨부파일 | `collection` | 접수된 메시지의 파일 ID·이름·크기만 포함한 목록; URL은 보내지 않음 |
| 고정 enum·boolean | `registry_options` | 레지스트리에 확정된 선택지, 언급 없음 포함 |
| 새 목록명·새 이름·검색어 | `source_span` | 원문 문자열 구간·조사 경계·인용 값 |
| 숫자·URL·멘션 | `deterministic_value` | 코드가 추출한 값과 원문 근거; 멘션 대상은 실제 목록에서도 검증 |

`collection`은 문장의 단어·유사도·임베딩으로 추측해 만든 객체 후보가 아니다. **실제 저장소/API로 만들 수 있는 접근 가능 목록을 먼저 조회하고 전달**한다. 명령 선택용 등록부도 실제 지원 명령 목록이다. 공통 wire의 선택ID/`candidate_set_id` 표현을 유지하더라도 `source_kind=collection`과 목록 스냅샷을 명시해 원문 구간 후보와 혼동하지 않는다.

## 작업

1. 레지스트리 인수에 `selection_source`, `collection_resolver`, scope/filter 정책을 선언한다. 등록부가 실제 목록을 제공할 수 있으면 문장 구간 기반 entity 추측을 기본 경로에서 제거한다. 재생목록/카탈로그/목록entry/queue item/채널별 resolver를 만든다.
2. resolver는 권한·현재 서버·명령이 요구하는 종류, 사용자가 명시한 목록/카테고리 등 **확정된 범위만** 적용한다. 예를 들어 조회 가능한 채널과 주시 설정 가능한 채널, 재생 가능한 음성채널은 정책에 맞게 구분한다. 이름 유사도 top-k로 실제 목록을 몰래 대체하지 않는다.
3. 모델에는 불투명 selection ID·실제 표시명·필요한 별칭/종류/위치/중복 구분 정보만 전달하고 DB/Discord 원본 ID 매핑은 코드에 둔다. 목록 이름 속 지시문은 데이터다. `collection_key`, `snapshot_id`, scope/권한 fingerprint, revision, root/pass/argument, stable order, 원래/전달 항목 수, complete 여부를 결합한다.
4. 목록이 허용 크기 내라면 해당 범위의 **전 항목**을 전달한다. 실제 목록에는 원문 span의80후보 제한을 적용하지 않는다. Choice 예약값을 포함한 공급자 상한과 질문/토큰/byte 예산을 먼저 확인한다. 너무 크면 사용자에게 범위를 좁히거나 UI에서 목록을 선택하게 한다. 명시 범위를 새로 얻으면 그 범위의 완전한 목록을 다시 구성한다.
5. DB/API 페이지는 코드가 허용 자원 한도 안에서 일관된 전체 목록으로 수집할 수 있다. 불완전 fetch·페이지 변경·권한 미확인은 complete로 표시하지 않는다. 여러 페이지를 Jev에 차례로 보내는 숨은 추가 호출, 임의 첫80개/상위k개, full_parse로 목록 제한을 우회하는 처리는 금지한다. 조회 자체가 실패하면 목록이 비었다고 답하지 않는다.
6. 목록 선택 뒤 조회 의존성을 처리한다. ‘운동 목록에서 RED 빼줘’는 재생목록 선택 후 해당 목록의 실제 entry 목록을 전달한다. 같은 곡이 여러 번 있으면 entry/queue item ID와 위치로 구분한다. 동명·중복은 질문하고 첫 항목을 자동 선택하지 않는다.
7. 목록이 아닌 새 값에만 원문 구간 추출을 적용한다. text는 인용·연속 구간·조사 경계, 숫자는 수사/단위, URL/멘션은 결정적 파서로 읽는다. 일반 span8어절/80개는 이 경로의 시작값이며 긴 인용은 별도 보존한다. 원문 위치/derivation과 `source_policy`를 검증하고 false/0/null/none을 구분한다.
8. `__MISSING__`는 실제 미언급, `__NO_MATCH__`는 전달된 완전 목록에서 대상을 못 찾음 또는 원문 값 미포함, `__AMBIGUOUS__`는 복수 항목이다. 모델의 NO_MATCH만으로 실제 객체 부재를 단정하지 않고 원문·실제 목록을 대조한다. 목록 불완전/조회 실패/너무 큼은 별도 코드로 둔다. 실제 목록에서 대상이 없으면 모델이 ID를 생성하지 않는다.
9. 복수 선택은 전달 목록 항목의 포함·제외를 Noul로 판정한다. 요소 일부만 확실하거나 범위를 벗어나면 부분 실행하지 않는다. ‘현재곡/그 목록’ 문맥은 같은 사용자·서버·유효TTL/세대의 명시 상태와 실제 목록 membership을 모두 만족해야 한다.
10. after_rewrite는 원문과 확정 scope에 맞는 실제 목록을 사용하고 snapshot 소속을 검증한다. 최초 잘못 선택한 명령의 scope를 고정하지 않으며 명령을 다시 선택하면 해당 resolver로 목록을 재구성한다. 새로 조회한 목록은 새 revision/ID 매핑으로 결합하고 이전 패스 ID를 재사용하지 않는다. full_parse의 원문 query는 코드의 목록 재조회/범위 질문으로 연결할 뿐 기존 목록 항목을 모델이 발명하는 수단이 아니다. 실행 직전 최신 객체·권한·세대를 재확인하고 달라진 대상은 조용히 치환하지 않는다.
11. 외부 YouTube 검색은 사용자가 실제 검색을 요청한 경우 코드가 공식 검색으로 만든 결과 목록에서 선택하게 한다. 전세계 모든 곡의 완전 목록이라고 표시하지 않는다. URL 접근은 기존 네트워크 가드, 첨부 import는 기존 제한 검증을 따른다.

p12f 후보는 현재 메시지의 첨부파일 목록을 추가했다. 단일 파일의 “이 파일” 표현을 허용하고 복수 파일은 명시된 이름이나 신뢰된 선택이 필요하다. 실행 직전 같은 메시지의 첨부 ID와 목록 revision을 다시 검사한다. 빈 선택형 첨부 목록은 `null`로 고정해 링크 가져오기를 막지 않는다. 이 동작은 LXC 격리시험 결과이며 실제 Discord 첨부 조작 인수는 남았다. [실행 기록](../../../evidence/public/reconstruction-120-progress.md)을 참조한다.

## 산출물

CollectionResolver/CollectionSnapshot·source별 ValueExtractor·예약/목록오류 enum·목록 완전성/범위 manifest·원문값 포함률 보고·크기 초과/모호함 fixture. 실제 목록 커버리지와 문자열 추출 커버리지는 별도 지표로 남긴다.

## 검증·종료 조건

- R120-08: 실제 재생목록·곡목록·채널목록이 scope 내 전 항목으로 전달된다. 문장과 이름의 어휘가 겹치지 않아도 항목이 빠지지 않는다. 새 값의 다어절/조사/0/false/none/수사/URL 추출은 별도로 검증한다.
- R120-09: 빈 목록/불완전 조회/크기 초과를 구분하고 경계 항목·예약값 포함 상한을 검사한다. 동명 목록·중복곡·타 서버·권한 회수·수정된 revision·오래된 snapshot ID의 잘못된 객체/부분 실행0. overflow 시 임의 절단·추가 페이지 모델 호출0.
- LXC의 격리DB/고정 카탈로그로 검증하고 모델 성적과 생성기 성적을 나눠 기록한다. 11단계 독립 평가 전에 생성기 버전을 잠근다.
