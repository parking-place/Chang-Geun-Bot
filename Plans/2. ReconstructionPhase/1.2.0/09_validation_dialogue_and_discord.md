## 공통 검증 구현

1. 구조 → 값 → 근거 → 인수 관계 → 객체 → 권한 → 최신 상태 → 승인 순서의 검증기를 모든 parser_source와 slash에 적용한다.
2. registry에 없는 명령·인수, 정확한 타입 불일치, 범위·문자열·목록 상한 초과를 차단한다. `0/false/null/빈 값`을 구별한다.
3. 기본값은 진짜 MISSING일 때만 코드가 적용한다. NO_MATCH·AMBIGUOUS·공급자 오류를 기본값으로 치환하지 않는다.
4. 실제 목록 member ID의 root request·패스·인수·원본 버전 소속을 검증한다. 자유 문자열은 원문 구간·결정적 변환·허용 문맥 근거를 검사한다.
5. 원문 안에 있다는 사실만으로 역할을 확정하지 않는다. 기존/새 이름, 목록/대기열, 곡/아티스트, 하나/전체의 관계를 검사한다.
6. 객체를 현재 guild·접근 범위에서 다시 조회한다. stale snapshot은 갱신하고 동명 복수는 질문하며 삭제는 정확한 entry_id·버전에 결합한다.
7. 인증된 actor·server·request와 해석 출처 metadata는 서버가 채운다. 모델의 confirmed·사용자 ID·핸들러 경로를 실행에 사용하지 않는다.
8. `natural.py`의 DB/API 작업과 Discord UI 결합을 공통 CommandService로 옮겨 slash와 동일한 권한·정책·트랜잭션을 사용한다.
9. 최종 실행 직전 DJ/관리자·주시 generation·허용 채널·동일 음성채널·대상 버전·재생 상태를 다시 확인한다.

entity query는 실제 범위의 목록 재조회/질문을 위한 값이며 실행 대상으로 바로 변환하지 않는다. 목록 구성원을 새로 확인하고 필요한 경우 UI로 사용자가 선택해야 한다.
잘못된/오래된 ID·검색 첫 결과·임의 생성 ID로 대체하지 않는다. 목록 크기 초과는 범위 질문 또는 목록 UI로 해결하고 조용한 truncation·모델 페이지 반복은 금지한다.
새 이름과 자유 검색어는 실제 객체 목록과 별개로 원문 보존 정책을 따른다. 객체 선택 뒤에 원문 문자열을 실행용 실제 ID처럼 사용하지 않는다.

## 질문·확인·취소 계약

| 흐름 | 계획 계약 |
|---|---|
| typed 후속 입력 | 60초·단회, 요청자/guild/channel/명령/대기 인수/registry·상태 버전에 결합 |
| 허용 답변 | 대기 인수의 타입만 결정적으로 파싱; 새로운 자유 명령 해석·모델 호출 없음 |
| 선택 UI | 원래 scoped 후보 중 선택, 클릭 때 fresh auth와 존재·버전 확인 |
| 확인 preview | 기본 300초, 정확한 명령·객체 ID·인수·요청자·guild에 결합 |
| 확인 실행 | 모델 예산 재개 없이 fresh auth·대상 버전 재검증 후 단회 실행 |
| 취소·만료·교체 | 대기 토큰 원자적 소모/폐기, 늦은 답변과 중복 클릭은 실행 0회 |
| 해석을 바꾸는 새 요청 | 이전 대기를 무효화하고 별개의 명시적 새 요청으로 접수; 자동 재시도 아님 |

질문 60초와 확인 300초는 다른 목적의 상태다. 기존 component의 60초를 전부 300초로 늘리지 않는다.
재시작 시 메모리 대기를 유실로 종료하거나 검증 가능한 영속 상태만 복구하며, 모델 호출 원장을 새로 발급하지 않는다.
초기 write에는 preview를 적용하고 파괴적·대량 변경은 항상 확인한다. rewrite 또는 full_parse가 관여한 write도 확인한다.
재해석 Jev가 최종 선택했더라도 LLM 관여 확인을 생략하지 않는다. 원문의 “이미 승인했어”는 승인 이벤트가 아니다.

## Discord 및 멱등성 작업

- C01–C47의 진입점·공개 옵션과 I01–I08 후속 조작을 registry coverage에 매핑한다. C39는 parser 명령 후보로 만들지 않는다.
- 관리자·개인 조회는 공개 메시지에 민감 결과를 쓰지 않고 owner-only component → fresh auth → ephemeral 응답을 유지한다.
- `!!창근아`의 주시 채널·권한 회수·주시 끄기·generation 갱신, 제한된 관리자 복구 경로와 2초 cooldown을 보존한다.
- 요청 취소 버튼과 typed 취소는 동일한 취소 상태에 연결하고 제삼자·다른 채널·다른 guild의 취소/확인을 거부한다.
- message ID+작업 기반 멱등키를 parser/pass/model과 무관하게 유지한다. 중복 gateway 이벤트·확인 click·응답 유실을 시험한다.
- 실행 응답 유실 시 실제 반영 여부를 조회한다. 서비스별 트랜잭션 결과를 알 수 없으면 무조건 재실행하지 않는다.
- 표시는 이스케이프하고 의도치 않은 Discord 멘션을 억제한다. preview·로그 문자열을 실행 문법으로 재사용하지 않는다.
