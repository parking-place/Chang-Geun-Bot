## 사용자 명령과 권한 계약

아래 추가 명령/버튼은 **구현 예정**이다. 기존 `/주시`6명령의 권한과 신규 조회 권한을 혼동하지 않는다.

| 진입점 | 예정 동작 | 권한 |
| --- | --- | --- |
| `/주시 이력` | 현재 서버 변경 시각·행동·결과를 개인 응답 페이지로 조회 | 서버 소유자 또는 최신 Manage Guild; DJ 단독 불가 |
| `/운영 사용량` | 현재 서버의 처리/실패 분류·관측 기간·기준 시각 표시 | 서버 소유자 또는 최신 Manage Guild; 요청자 전용 |
| 진행 응답의 `요청 취소` | 해당 사용자의 아직 끝나지 않은 요청을 무효화 | 원래 요청자·서버·채널·request ID 일치 |

관리 조회는 등록된 서버의 접근 가능한 일반 텍스트 채널에서 가능하도록 별도 조회 경계를 설계한다. 일반 음악 명령 정책은 확장하지 않는다.
페이지 전환 때도 최신 관리자 권한을 확인한다. 관리자라도 다른 사용자의 요청을 일반 취소 버튼으로 취소할 수 없다.
요청자 권한이 사라진 뒤에도 본인 진행 요청의 취소는 허용할 수 있으나, 취소를 이용한 재실행/권한 부여는 불가능해야 한다.
이미 커밋된 결과는 취소 성공이라고 표시하지 않는다. 편집 되돌리기가 지원되는 경우 기존 경로를 안내한다.
슬래시의 진행/관리 응답은 개인 응답을 사용한다. 일반 prefix 메시지의 응답에는 ephemeral을 보장할 수 없으므로 공개 가능한 최소 처리 상태와 취소 버튼만 표시한다.
공개된 버튼이어도 호출자는 원래 요청자로 검증한다. 취소 처리 결과는 버튼 interaction의 개인 응답으로 전달하고 원문/관리 집계를 공개 메시지에 붙이지 않는다.

## 집계·데이터·취소 계약

- 감사90일의 기존 보존 규칙을 유지하고 페이지는 최대10행으로 제한한다. 원문 대화/판단 payload를 추가 저장하지 않는다.
- 사용량은 현재 서버 집계와 중계 전체 고정 예산을 분리한다. 관측 기간 밖·분류 불명·미제공 값은unknown으로 표시한다.
- 남은 개발 dispatch는 해당 서버 전용 예산임을 입증하는 경우만 표시한다. 여러 서버가 공유하거나 귀속 불명이면 화면에서 제외한다.
- 과거 계정 전체 누계·가격·실제 통화 비용·hosted forward는 추정 실측으로 만들지 않는다. 필요 자료는 운영자 제한 증거로 관리한다.
- 봇은 별도 중계 DB/hosted 키를 직접 읽지 않는다. 필요한 집계만 반환하는 인증된 내부 조회 API와 최소 필드를 설계한다.
- 집계 조회는 provider dispatch0이며 읽기 전용이다. 기존 API1.2 판단 스키마와 분리하고 TLS·binding·응답 상한·오류 처리를 검증한다.
- 취소는 영속 요청 상태와 실행 커밋 순서를 대조한다. 메모리 task 취소만으로 완료 처리하지 않고 늦은 응답/자식/확인을 차단한다.
- 봇의 취소가 hosted 계산 중단을 보장하지 않는다. 예약 호출 환불·재전송·새 ID 자동 발급·재시작 예산 초기화는0이다.
- 삭제/끄기/권한 상실은 해당 출처만 무효화하고 현재 스트림·다른 출처 큐·감사·tombstone을 보존한다.

## 완료·중단·rollback

P115-01~07과 W-01~20의 모든 필수 하위 조건을 추적한다. 대표 시험 통과만으로 전체 W를 완료 처리하지 않는다.
W-20에 포함된 최종 장시간/상속 조건이1.1.7까지 남으면 R-03과 해당 단계도 미완료로 유지한다. 다른 단계의 부분 인수만 개별 기록한다.
무단 정보 노출·취소 뒤 실행·다른 출처 큐 손실·예산 초기화가 있으면 적용을 중단한다. 취소 이후 도착 결과는 재사용하지 않는다.
이전 바이너리/이전 DB 묶음으로 복귀하고 최신 원장·감사·tombstone은 보존한다. 과거 원장 복원으로 소모 예산을 되돌리지 않는다.
새 집계 endpoint를 되돌릴 때 봇의 호출도 함께 호환되게 복귀한다. 조회 실패 때문에 자연어를 다른 제공자로 전환하지 않는다.
이번 개발 인수는 정식 출시 승격과 분리한다. 이전 독립 품질·실제100회·8시간·운영 복구의 미완료 조건을 유지한다.
