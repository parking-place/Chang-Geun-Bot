# 1.1.4 — 재생 실패 안내와 최근 완료곡

- 상태: **PLANNED — 문서만 작성, 구현·LXC 시험·개발 인수 미실행**
- 포함 항목: **R-02, F-04, F-09**. [전체 항목 배정](../ITEM_COVERAGE.md)을 따른다.
- 목표: 실패한 구간을 설명할 수 있게 하고, 사용자가 다음 행동과 최근 완료곡을 쉽게 찾도록 한다.
- 실행·상태·증거 기준: [공통 규칙](../EXECUTION_RULES.md), [STATUS](../STATUS.md), [시험 추적](../TEST_MATRIX.md).

## 사용자 명령과 화면 계약

아래 신규 명령/응답은 **구현 예정**이다. 현재 등록된 명령이라고 안내하지 않는다.

| 진입점 | 예정 동작 | 권한/출처 |
| --- | --- | --- |
| 기존 요청의 실패 응답 | 지원 조건·권한·혼잡·기한·미디어 준비 실패별 다음 한 단계 | 원래 요청자에게 기존 응답 경로로 전달 |
| `/현재곡` | 준비/정지 상태와 안전하게 분류한 최근 관련 실패 안내 | 기존 조회 권한, 다른 사용자의 비공개 요청 내용 미표시 |
| `/최근곡` | 현재 서버 최근 완료곡을 페이지로 조회 | 기존 일반 음악 조회의 서버/텍스트 채널 정책 |
| 최근곡의 `재생 요청` | 선택한 등록 곡에 대한 새 명시 요청 | 최신 DJ·동일 음성·채널·음원 지원 조건 |

조회는 최근30일 이내 최대100건, 페이지 최대10항목을 초기 계약으로 삼는다. 이는 조회 범위이며 기존 이력을 삭제하는 보존 정책이 아니다.
별도 변경이 필요한 보존 정책은 기존 목록 생성의 최대365일 최근 제외와 함께 검토한다. 이 버전에서 원본 기록을 임의 삭제하지 않는다.
같은 곡의 여러 완료 기록은 시각으로 구별한다. 조회만으로 자동 재생하거나 옛 재생 승인을 재사용하지 않는다.
최근곡 UI는 구조화 요청이며 Jev0회다. 일반 멤버의 조회 가능 범위와 DJ 재생 권한을 분리한다.
저장 목록에 넣고 싶은 사용자는 선택 곡의 안전한 식별 정보를 확인한 뒤 기존 `/곡 추가` 또는 일반 멤버용 `/곡제안`으로 이어갈 수 있게 안내한다. 기존 편집/제안 권한과 중복·대상 버전 검사를 유지하며 조회만으로 목록을 변경하지 않는다.

## 실패·데이터·안전 계약

- 메타데이터/지원 조건, resolver, 네트워크, FFmpeg 시작, 첫 PCM, Discord 음성 시작의 실패 구간을 분리한다.
- 길이·비공개/삭제·라이브 등 지원 제외와 일시적 준비 실패를 구별한다. 판별하지 못한 원인은 `unknown`으로 남긴다.
- 오류에는 코드·구간·경과시간·안전한 후보/실행 식별만 기록한다. 원문 응답·stderr 전체·signed URL·키를 저장하지 않는다.
- 승인 만료·명령 취소·권한 거절은 미디어 고장 횟수에 합산하지 않는다. 첫 PCM은 실제 청취 완료와 구별한다.
- “다른 곡 선택”, “음성 권한 확인”, “슬래시 명령 사용”처럼 해당 상태에서 유효한 행동만 안내한다.
- 아직 전송되지 않은 자연어 요청만 중단할 수 있는 상황과 이미 전송된 호출을 구별한다. 자동 재전송·예약 환불을 추가하지 않는다.
- 최근곡 선택은 track ID·조회 snapshot에 결합하고 삭제/미지원 변경을 재검사한다. 실패·중단·넘기기를 완료곡으로 새 기록하지 않는다.
- 이력 조회는 청취자·개인 취향·대화 추적을 추가하지 않는다. 새 분류/색인이 필요하면 additive migration을 사용한다.

## 완료·중단·rollback

P114-01~07의 결과를 고정 후보와 연결한다. P114-02가95%에 못 미치면 원인 설명이 개선돼도 재생 안정성 인수를 PASS로 올리지 않는다.
분류 불가능한 일부 실패는unknown으로 공개하고 무조건 단일 원인을 부여하지 않는다. 성공 지연만으로 전체 개선을 주장하지 않는다.
권한 우회·잘못된 재요청·비밀 노출·이력 손실이 확인되면 적용을 중단하고 이전 검증된 후보로 복귀한다.
이전 바이너리/호환 DB 묶음을 사용하며 신규 분류/이력 증거와 최신 DB를 별도 보존한다. gateway 원장·예산은 초기화하지 않는다.
이 버전의 첫 PCM100회와 일부 사용자 청취는 최종 실제 음성100회·8시간·품질·복구 게이트를 대체하지 않는다.
