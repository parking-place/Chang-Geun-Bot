## 현재와 바뀔 점

현재 `/주시`6명령과 단일 후보의 동적 출처 검증은 구현되어 있다. R-01은 다후보의2단계 직전 검사에 정적 `self.policy`가 사용되는 코드상 의심점이며, 실제 재현 결과는 없다. 재현·원인 확인 후 필요한 범위만 수정한다.

현재 개발 probe는 전체/단계 왕복 시간을 측정하고, 자연어 예외는 대체로 공통 안내로 처리한다. 이 버전은 처리 구간별 계측과 안전한 오류 분류를 추가하며 `/도움말`을 현재 역할·채널·DB 주시 상태에 맞춘다. 새 명령 이름이나 구현된 상태 조회 기능을 가정하지 않는다.

## 선행 조건과 증거 준비

1. 1.0.3 현재 소스·설치 wheel·설정 binding·DB/중계 원장 위치를 읽기 전용으로 확인하고 변경 전 복귀 묶음을 남긴다.
2. 기존328/41 PASS와 사용자 부분 인수를 참고하되 새 분기의 통과 증거로 재사용하지 않는다.
3. 정적 허용 채널과 신규 동적 주시 채널, 동일 역할·음성·목록을 가진 격리 fixture를 준비한다.
4. 독립 한국어 평가의 분류·정답 규칙·데이터 분리·접근/동결 절차를 이 버전부터 설계한다. 개발 회귀 자료와 held-out은 분리한다.
5. 독립200문장의 최종 평가 책임은1.1.6에 있다. 그 점수를1.1.0의 과거 SHA 성적으로 소급하지 않는다.

## 사용자·API 계약

- 정상 prefix 요청은 입증된 출처/주시 세대를 적용한다. 슬래시·멘션의 정적 허용 범위와 DJ·같은 음성채널·확인 정책은 유지한다.
- `/도움말`은 Jev0회·설정 변경0이다. 미허용 채널에서는 요청자에게 보편적 사용법만 안내하고 다른 채널 이름·목록·관리 정보를 노출하지 않는 경계를 설계한다.
- 도움말을 열거나 버튼을 누를 때 최신 역할/권한을 확인한다. Manage Guild가 없는 사용자에게 관리자 진단을 노출하지 않는다.
- Jev API Only·API1.2·최대3dispatch·전체12초/단계4초·활성1/대기4·retry0를 유지한다. 원장 예약/불명 호출은 환불하지 않는다.
- 운영 지표는 구간 소요 시간과 비밀 없는 오류·집계로 제한한다. 원문·제목·실제 Discord ID·키·signed URL을 새로 저장하지 않는다.
- 신규 호출과 같은 요청 재사용을 구분한다. 미제공 token/forward/revision/가격은 unknown 또는 unavailable로 남긴다.

## 측정과 채택 판단

권한 수정 여부는 재현 증거로 결정한다. 재현되지 않으면 조사 범위·관측 한계를 기록하며 “버그 수정 PASS”라고 쓰지 않는다. 계측 오버헤드는 같은 fixture/자료 크기에서 비교하고 큰 지연·불안정성이 생기면 관측 범위를 줄여 다시 검증한다.

지연 비교에는 health·DB·대기·provider·전체 시간을 분리하고 성공 p50/p95와 실패/timeout 수·시간을 함께 기록한다. 이후 최적화의 기준값이며 이 버전에서 응답 속도 개선을 보장하지 않는다. 유료 비교 전 최대 호출 수와 현재 남은 영속 예산을 대조한다.

## 완료·중단·복귀 조건

- 개발 완료: 범위4항목의 조사/구현 산출물, P110 전건의 필요한 자동·실제 증거, exact candidate 식별, 알려진 한계·복귀 결과를 남긴다.
- 정식 출시: 해당 후보 자체의 필수 회귀·품질·성능·운영 게이트가 모두 충족되어야 한다. 후속1.1.6/1.1.7 결과만으로 과거 후보를 출시 PASS로 바꾸지 않는다.
- 중단: 권한/출처 우회, 정보 노출, 호출 누계 불일치, 원장 초기화, 기한 후 실행, 재현·측정 자료 불충분이면 영향 기능 인수를 중단한다.
- 복귀: 새 후보 접수를 멈추고 이전 바이너리/설정과 그에 맞는 DB 묶음을 사용한다. 중계 원장·tombstone·남은 예산은 보존하고 자동 재생하지 않는다.
- 실패는 FAIL, 미실행은 PLANNED/진행 중으로 남긴다. 제품 VERSION·출시 태그는 계획 작성이나 부분 통과로 변경하지 않는다.
