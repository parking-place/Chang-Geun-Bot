# 1.1.6 — Jev 판단 효율과 독립 한국어 품질

- 상태: **IN_PROGRESS — 개발 비교·첫 잠금200문장 평가 완료, 독립 품질 인수 FAIL**
- 범위: **J-07, J-09, R-04**. 원안은 [Jev 최적화](../02_JEV_OPTIMIZATION.md)와 [안정화](../03_STABILITY_AND_ACCEPTANCE.md)다.
- 목적: 프롬프트와 판단 임계값의 개선 효과를 비교하고, 고정 후보의 한국어 의도·대상·확인 판단을 독립 자료로 검증한다.
- 공통 기준: [실행 규칙](../EXECUTION_RULES.md), [항목 배정](../ITEM_COVERAGE.md), [상태](../STATUS.md), [시험표](../TEST_MATRIX.md).

## 현재와 달라지는 점

현재 프롬프트는 단계별로 공통 지시를 보내며 개발 프로필은 confidence 0.80 / margin 0.10을 사용한다. 과거 후보의 개발 37문장 통과는 독립 한국어 품질이나 새 후보의 성적이 아니다.

이 버전은 지시문 축약과 임계값 조정을 각각 비교한다. 변경을 채택하지 않는 결론도 허용한다. 효과가 없거나 안전·정확도가 나빠지면 기준 설정을 유지하고 그 결정과 측정 결과를 남긴다.

| 항목 | 구현·검증 범위 | 제외 또는 유지할 경계 |
| --- | --- | --- |
| J-07 | 반복 설명 축약, 단계별 표현의 비교, payload 크기·실측 usage·정확도 기록 | 미확인 prompt cache/batching 인자를 추가하지 않음 |
| J-09 | 개발 자료에서 confidence/margin을 하나씩 비교하고 채택 기준으로 선택 | 단계별 임계값 신설·확인 생략·confidence의 성공확률 표시는 제외 |
| R-04 | 독립 held-out 최소 200문장, 잠금 manifest·채점기·안전 회귀·고정 후보 평가 | 개발 37문장·mock·과거 결과 합산 금지 |

## 선행 조건과 진행 순서

1. [1.1.0](../1.1.0/README.md)의 평가 자료 분리·계측 기반과 권한 경로 점검을 먼저 확보한다. 독립 자료는 개발 중 프롬프트 선택에 사용하지 않는다.
2. [1.1.1](../1.1.1/README.md)~[1.1.5](../1.1.5/README.md)의 영향받는 연결·후보·UX·주시 경로가 개발 후보에서 검증되어야 최종 평가 대상을 잠근다. 주시의 핵심 권한·출처·취소·재시작 회귀를 선행 조건으로 삼으며, R-03 전체 완료나1.1.7에서 닫을 W-20 장시간/상속 게이트를 미리 요구하지 않는다.
3. 설계·fixture·채점기 준비는 선행 정식 출시를 기다리지 않고 진행할 수 있다. 실제 비교는 동일 조건의 기준 후보와 변경 후보가 준비된 뒤 수행한다.
4. 이 버전의 개발 인수 이후 [1.1.7](../1.1.7/README.md)에서 성능·음성·복구를 종합 검증한다. 이전 버전의 미통과 출시 게이트는 계속 남으며 제품 VERSION·태그를 먼저 올리지 않는다.

## 계약과 자료

Jev API Only, API 1.2, 요청당 최대 3단계/3 dispatch, 전체 12초·단계 `min(4초, 잔여시간)`과 3단계 진입 잔여 1초를 유지한다. 모델은 등록된 후보만 선택하며 권한·주시 세대·대상 버전·필수 확인·실행 승인은 봇이 다시 검사한다.

- prompt 비교 중에는 기존 confidence/margin을 고정한다. 이후 선택한 prompt를 고정하고 임계값을 비교한다. 변경을 동시에 섞어 효과 원인을 흐리지 않는다.
- 부정문, 저장 목록/대기열 구별, 비신뢰 제목, 복합 요청 미지원, clarify 조건과 위험 동작 확인 규칙을 축약으로 제거하지 않는다.
- 각 실험 전에 표본 수, 비교 횟수, 최소 유효 개선 폭·측정 편차 처리, 정확도 허용 기준과 채택 순서를 확정한다. 위험 계획·무단 실행 0, 자동 의도·대상 정확도 악화 없음이 필수이며 비용/지연 하나만 좋아진 결과를 자동 채택하지 않는다.
- held-out은 최소 200문장으로 명확한 지원 명령 120개·모호/비명령/부정 60개·우회/교란 20개를 구성한다. 신규 곡/목록명, 띄어쓰기·오타·존댓말·반말·수사·따옴표·짧은 제목을 포함한다.
- 문장·정답·허용 확인/거절·초기 snapshot/seed와 source/candidate/profile/config/prompt/threshold hash를 평가 전에 잠근다. 같은 문장·근접 변형의 개발 세트 중복을 점검한다.
- 결과를 본 held-out으로 프롬프트를 수정하면 그 자료는 개발/회귀용으로 전환한다. 새 최종 평가는 독립 자료를 다시 잠그며 최초 실패와 소비 예산을 보존한다.
- 의도·대상·확인 필요·최종 ActionPlan, 0/1/2/조건부 3단계, 불필요한 확인·오거절·위험 계획·실제 효과를 따로 채점한다. 불필요한 확인은 자동 해석 성공으로 세지 않는다.
- API가 반환한 token만 실측으로 기록하고 누락은 unknown으로 둔다. payload 바이트를 token으로 환산하지 않는다. hosted forward와 미공개 revision은 null/unavailable이다.

### 예산과 실행 위치

제품 실행은 DiscordBotLXC에서만 한다. 비교·품질·성능·soak의 유료 호출을 같은 고정 epoch의 영속 누계와 남은 한도에 합산한다. 현재 최대 3000 dispatch 안에서 이미 예약된 준비·실패·불명 호출도 차감한다.

개발 N문장 기준/후보 비교 한 번의 상한은 `2 × N × 3 + 준비 호출`이고 최종 200문장 한 번은 최대 600 dispatch다. 비교 횟수와 1.1.7의 성능/혼합 부하까지 예약 상한을 먼저 계산한다. 부족하면 해당 실험을 시작하지 않고 차단 사유·필요 예산을 기록한다. 새 run 반복·원장 삭제·재시작·실험 식별자 변경으로 한도를 초기화하지 않는다.

설정 후보에는 별도 식별자/hash를 부여하되 현재 원장을 덮어쓰지 않는다. 후보별 binding과 공통 누계가 함께 보존되는 전환 절차를 먼저 검증한다. 이 문서만으로 현재 profile·epoch·한도를 바꾸지 않는다.

## 완료·중단·복귀 조건

개발 인수에는 다섯 단계 증거, P116 전건 결과, 자동 해석 ≥95%와 안전 위반 0, 비용/효과를 근거로 한 채택 또는 기준 유지 결정이 필요하다. 개선 후보를 채택하지 않아도 고정 기준 후보의 독립 품질 게이트 자체는 통과해야 한다.

자료 누출·위험 실행·예산 부족·설정 binding 불일치·정확도 기준 미달이면 해당 평가/적용을 중단한다. 실패 결과를 삭제하거나 정답을 수정해 같은 평가를 PASS로 바꾸지 않는다. 판단 설정만 되돌릴 때도 고정 후보와 연결 재사용 상태를 함께 확인하고 예산·tombstone은 보존한다.

이 버전 결과는 실제 평가한 SHA/설정에만 유효하다. 1.1.7에서 판단 영향 변경이 발생하면 영향을 재평가한다. 정식 출시는 기존 미완료 인수와 1.1.7의 성능·음성·복구 게이트까지 충족한 대상만 검토한다.
