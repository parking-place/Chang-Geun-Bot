# 1.1.6 개발 비교 사전 고정 — 2026-09-28

이 문서는 1.1.6 실제 비교 실행 **전** 고정한 판정 규칙이다. 같은 DiscordBotLXC·Jev API1.2·고정 epoch `single-lxc-20260928`의 현재 예산을 사용한다. 1.1.5까지의 이전 개발 37문장 결과는 배경이며 새 후보의 결과로 옮기지 않는다.

## 순서·분모

1. 코드/설치 wheel·gateway instruction SHA를 고정하고 `tests/nlp_eval/development.json` 37문장(명확25)을 같은 fixture/역할/설정으로 기준 prompt `korean-candidates-dev-v5`, 압축 prompt `korean-candidates-compact-v1` 순서로 각 1회 평가한다. confidence0.80/margin0.10을 유지한다. 실패도 전부 포함한다.
2. 압축을 채택하려면 위험 계획0, 명확25/25, 전체37/37을 유지하면서 instruction UTF-8 바이트가 최소15% 줄고, Jev가 실제 반환한 입력 token의 합계가 기준보다 최소5% 줄어야 한다. token이 빠지거나 조건 미달이면 안전해도 **기준 유지**다. 지연만으로 채택하지 않는다. 재실행으로 실패를 지우지 않는다.
3. 선택된 prompt를 고정한 뒤 기준 0.80/0.10과 대안 0.75/0.10을 개발37문장으로 비교한다. 대안 채택에는 위험 계획0, 전체37/37, 명확25/25, 불필요한 확인 감소 최소2건이 필요하다. 변화가 없거나 악화/측정 불가면 **기준 유지**다. confidence를 성공확률로 해석하지 않는다.
4. 독립 200문장 자료는 개발 비교를 마친 뒤 코드/설정 수정 없이 별도 생성·잠근다. 명확120, 모호/비명령/부정60, 우회/교란20과 정답·fixture·SHA를 실행 전 확정한다. 개발 문장과 중복/근접 변형을 제외한다. 이 자료를 보고 코드를 바꾸면 그 자료를 개발용으로 전환하고 새 독립 자료를 만들어야 한다.

## 안전·비용 경계

- 개발 비교 3회 상한은 `3 × 37 × 3 = 333` dispatch다. 독립200문장 1회 상한600, 1.1.7의 3경로 성능 한 조건 준비 포함 상한945다. 시작 전 원장 사용량과 이 합계1878을 확인한다. 여기에 실제 음성/장시간 자연어 부하를 쓰려면 그 최대 호출도 별도 더한다. 부족하면 추가 평가를 막는다.
- 비교 중 이전 profile/config 파일, run ID, 영속 원장/tombstone을 바꾸거나 삭제하지 않는다. 새 prompt는 코드에 고정하고 요청의 `prompt_version`으로 선택하되 현재 운영 bot 설정은 개발 비교에서 그대로 둔다.
- 요청별 단계·성공/거절/오류/timeout·대상 정확도와 안전 위반을 비교한다. 실제 입력 token이 없으면 unknown이다. provider 내부 forward·가격은 unavailable이다.
- 독립 평가에서 명확 자동 의도·대상 정답은 최소114/120(95%)이고, 위험/무단 계획0이어야 한다. 자동 명확화나 실패는 명확 정답으로 세지 않는다. 개발 비교 결과와 독립 결과를 합치지 않는다.
