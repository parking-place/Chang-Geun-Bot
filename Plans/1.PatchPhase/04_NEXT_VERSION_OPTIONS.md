# 1.1 계열 편성 근거와 순서

2026-09-28 사용자가 전체 제안을 포함하도록 요청하여 선택형 A/B/C 대신 **1.1.0~1.1.7의8개 버전**에 전부 배정했다. 현재 8개 버전 모두 개발 작업 중이며 전체 인수/출시는 미완료다. 버전별 실행 결과는 [현황](STATUS.md)과 [시험표](TEST_MATRIX.md), 전체 ID는 [배정표](ITEM_COVERAGE.md)에 있다. 아래는 편성 당시의 묶음 근거다.

## 먼저 준비할 일

개발/독립 데이터 분리는1.1.0부터, 후보 재현율 검사는1.1.2부터 준비한다. prompt/threshold는 개발 세트로만 조정하고1.1.6의 잠긴 독립 세트로 최종 판단한다. 독립 세트를 보고 조정했다면 새 미사용 세트가 필요하다.

매 데이터 변경 전 백업과 이전 바이너리/DB 묶음, 매 배포 전 인증서·키/접근·예산을 확인한다. 인증서 만료나 실제 미디어 장애가 보이면 해당 문제를 다음 큰 버전까지 방치하지 않는다. R-03 주시 회귀는 관련 변경마다 수행하고1.1.5에서 전체 W 실제 시나리오를 추적한다. W-20의 장시간/상속 게이트가 남으면1.1.7에서 닫을 때까지 R-03 전체는 미완료로 유지한다.

초기 버전은 개발 후보로 검증/사용할 수 있으나 정식 VERSION/태그/DONE은 기존 미완료 조건을 포함한 해당 후보의 증거가 필요하다. 최종1.1.7 PASS가 이전 SHA의 시험을 대신하지 않는다. 자세한 경계는 [공통 계약](EXECUTION_RULES.md)에 있다.

## 순서/범위를 바꿀 때

하나의 개선이 예상보다 크면 ID를 잃지 않고 하위 작업과 책임 버전을 기록한다. 신규 API 기능·가격·서비스 설정은 확인한 사실과 unknown을 구분한다. 성능 목표를 만족하려고 권한·예산·기한을 완화하지 않는다.

각 최적화는 구현 후보와 비교·채택 조건까지 수행한다. 효과가 없으면 그 근거로 기준을 유지할 수 있지만 항목을 조용히 빼거나 성공으로 표시하지 않는다. 기능 제외나 새로운 큰 확장은 별도 범위 변경이다. 시간 이동·개인 추천·다중 서버/음성방 등 당시 보류 예시는 기존26개 제안에 포함되지 않는다.
