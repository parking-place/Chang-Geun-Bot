# 1.1.8 — 모든 명령의 `!!창근아` 자연어 입력

- 상태: **IN_PROGRESS — 소스 구현·일부 LXC 개발 시험, 후보 적용·독립 인수 전**
- 요청: 기존 모든 사용자 명령을 `!!창근아` 뒤의 한국어 문장으로 요청할 수 있도록 최적화한다.
- 범위: **F-10, F-11, F-12, J-10, J-11, R-09**. 기존 26개 제안에 추가한 후속 6개 항목이다.
- 소스 기준: `329218f86ae0490aad218b95c353d8ece345fb0e`. 기록상 개발 봇은 `patch117b`, 중계는 `patch116g`이며 이번 계획에서 LXC 상태를 새로 조회하지 않았다.
- 공통 기준: [실행 규칙](../EXECUTION_RULES.md), [환경](../../0.DevPhase/ENVIRONMENT.md), [Jev 계약](../../0.DevPhase/INFERENCE_PROFILES.md), [새 입력 경계 결정](../../../docs/decisions/0009-all-command-natural-language-plan.md).

현재 작업은 공통 명령 등록부, 의도 선택, 주요 명령의 기존 실행기 연결, 관리자 전용 결과 열기와 접두어 버튼의 주시 세대 검사까지 소스에 반영했다. [개발 증거](../../../evidence/public/patch-118-development-20260928.md)의 예문 의도 선택은45/46이지만 대상·옵션·후속 답변의 전수 결과가 아니다. 새221문장 독립 평가와 실제 Discord 인수가 없어 모든 단계는 진행 중 또는 계획 상태다. 활성 봇은 여전히 이전 후보이며 정식 버전/태그는 바꾸지 않았다.

## 목표와 현재 차이

출발 기준에서 슬래시 말단 명령은 **47개**, 도메인 `Action`은 **41개**다. 기존 활성 봇의 자연어 후보 생성은 그중 **18개 Action의 일부 문형·옵션**만 다룬다. `현재곡`을 대기열 조회로 처리하거나 `/계속`의 입장/재개 흐름을 온전히 연결하지 못하는 차이도 있다. 새 소스 후보는 이 차이를 줄이는 중이며, 단순히 프롬프트에 명령 이름을 더하는 것으로 전체 지원을 판정하지 않는다.

[1.1.6 평가](../../../evidence/public/patch-116-development-20260928.md)의 실패 20건 중 15건은 Jev 호출 전 후보 생성 실패였다. 이 버전은 **명령 등록부 → 한국어 의도·인자 후보 → 권한과 상태 검증 → 기존 서비스 실행 → 맞는 응답 화면**을 끝까지 연결한다. 일반 사용자는 명령 이름이나 내부 ID를 외우지 않고 요청하고, 필수 정보가 빠졌을 때는 필요한 항목만 질문받는다.

## “모든 명령”의 의미

1. [COMMAND_COVERAGE](COMMAND_COVERAGE.md)의 **C01~C47 모든 행과 공개 옵션·모드**를 자연어로 시작할 수 있어야 한다. 빈 목록 생성과 조건 목록 생성, 카탈로그 검색과 YouTube 검색, 곡/목록/검색어 재생을 구분한다.
2. I01~I08의 페이지·선택·재요청·확인·취소 흐름도 연결한다. 위험한 변경에는 기존 확인을 거치고, 관리자 상세는 비공개 결과 버튼을 통해 연다. 모든 작업을 자연어로 시작한다는 목표는 필요한 확인/선택 UI를 없앤다는 뜻이 아니다.
3. `/부탁`은 동일한 자연어 진입점이다. 자연어가 다시 `/부탁`을 실행하는 재귀 구조는 만들지 않는다. 슬래시·버튼은 계속 제공한다.
4. 기존 권한·허용 채널·지원 소스·옵션 범위 내의 명령이 대상이다. 내부 `PLAYLIST_RESTORE`, `SETTINGS_UPDATE`를 새 공개 기능으로 노출하거나 서버 역할 변경·임의 운영 명령을 추가하지 않는다. 내부 `QUEUE_ENQUEUE`는 기존 재생 조합의 일부로 유지한다.
5. 한 요청의 사용자 의도는 한 가지다. “등록해서 재생”처럼 기존 `/재생`이 제공하는 내부 흐름은 허용하지만 “목록 삭제하고 다음 곡 재생” 같은 별개 작업의 연속 실행은 선택을 되묻는다. 일반 대화 기억·무제한 대화형 에이전트는 범위에 포함하지 않는다.

## 사용자 경험의 기준

- `!!창근아 운동용 목록에 이 곡 추가해줘` → 목록과 현재곡을 특정해 기존 추가 실행기로 전달한다.
- `!!창근아 운동용 말고 휴식용 목록 틀어줘` → 제외된 대상을 재생하지 않는다.
- `!!창근아 유튜브에서 봄 노래 찾아서 틀어줘` → 검색 결과를 제시하고 사용자 선택 뒤 재생한다. 첫 검색 결과를 자동 선택하지 않는다.
- `!!창근아 이 파일을 새 목록으로 가져와줘` + JSON 첨부 → 이름만 질문하고 제한된 가져오기 미리보기/확인으로 연결한다.
- `!!창근아 #일반에서도 내 말을 들어줘` → 관리자 여부·대상 채널을 확인한 뒤 주시 추가를 제안한다. 음악용 목록 편집으로 해석하지 않는다.
- `!!창근아 사용량 보여줘` → 관리자에게 내용 없는 결과 열기 버튼을 제공하고, 본인 클릭 시 다시 권한을 검사해 비공개로 표시한다.
- `!!창근아 내 요청 취소해` → 진행 중 요청을 취소한다. 현재 재생 중인 곡을 정지하는 요청과 구별한다.

모든 예시는 **1.1.8 목표**이며 현재 후보에서 모두 동작한다는 안내가 아니다.

## 선행·완료 경계

1.1.6의 명확103/120·교란3건 실패 자료는 개발 회귀로만 사용한다. 새로운 명령군이 생기는 1.1.8에서는 별도 독립 자료를 다시 잠근다. 새 성적을 과거 후보의 PASS로 소급하지 않는다.

1.1.7의 `patch117a` 첫 PCM94/100, 실제 음성100회·8시간·운영 수명 미완료와 **사용자 지정 백업 검증 SKIPPED**를 보존한다. 자연어가 정확히 재생 계획을 만들었다는 결과로 미디어나 청취 게이트를 닫지 않는다. 1.1.8 소스 개발 시험에서는 실제 Jev 호출로 공유 예산을 사용했다. 새 봇 후보의 DB 이관·Discord 적용·VERSION/태그 변경은 하지 않았다. 제품 검증은 DiscordBotLXC에서만 한다.
