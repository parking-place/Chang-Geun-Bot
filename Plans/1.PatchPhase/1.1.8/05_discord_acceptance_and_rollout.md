# 05 — Discord 인수·적용·복귀

- 상태: **PLANNED**
- 책임: R-09, F-10~12. 시험: P118-07.
- 선행:01~04단계의 고정 후보·권한·개인정보·독립 품질 증거. 계획만으로 현재 서비스나 주시 목록을 바꾸지 않는다.

## 개발 후보 준비

1. 구현 시 현재 Git diff·활성 bot/gateway wheel·profile/config·DB/schema·주시 설정·인증서 수명·고정 epoch 원장/잔여 한도를 재확인한다. 기존 `patch117b`/`patch116g`는 계획 출발점 기록이며 다음 배포 때 현황으로 단정하지 않는다.
2. 순수 명령/파서/응답 변경이면 DB 이관을 만들지 않는다. 명확화/관리 출처의 영속 상태가 필요하면 additive migration과 이전 DB/바이너리 복귀 묶음을 준비하고 기존 SQL/checksum을 고치지 않는다.
3. 새로운 기능은 후보/설정에 명시적으로 결합하고 제한 테스트 서버/채널에서 검증한다. 같은 길드에 여러 봇 세션을 병행해 명령을 중복 실행하지 않는다. 기존 source/wheel/profile을 덮어쓰거나 배포 재시작으로 예산을 초기화하지 않는다.
4. 자연어 entry의 변경이 슬래시/버튼, 승인 소스/YouTube, 주시0채널/꺼짐 재시작의 동작을 바꾸는지 영향 회귀를 수행한다. 관리자 prefix 복구는 별도 source/권한 검증을 마친 뒤 활성화한다.

## 실제 Discord 인수

고정된 시험 자료와 관리자/DJ/일반 멤버, 정상 주시 채널2개·미주시 채널·정적 관리 복구 채널을 사전에 확인한다. 실제 서버의 파괴적 편집 대신 삭제 가능한 전용 목록·곡/큐 fixture를 사용한다. 일반 사용자의 관리 명령·다른 사용자의 버튼을 관리자 계정 하나의 모의 결과로 대신하지 않는다.

| 묶음 | 필수 확인 |
| --- | --- |
| C01~C15 | 빈/조건 목록·이름 변경·복사·내보낸 첨부·링크/JSON 가져오기·곡 편집·카탈로그/YouTube 검색을 구분하고, 각 공개 옵션의 결과/확인 대조 |
| C16~C31 | 저장 목록과 큐 구별·위치 이동/저장 옵션·정지/일시정지/계속·반복3모드·볼륨·현재곡 화면·음성채널 선택/이동 |
| C32~C39 | 일반 멤버 제안→DJ 조회/승인/거절, 완료 최근곡/재요청, 대상 편집 undo, 역할 도움말, slash `/부탁`과 prefix 의미 일치 |

| I01~I08 | 질문·선택·확인·취소·페이지·만료곡 단건·최근곡·검색 선택, 본인/타인/다른 채널/만료·재전송·재시작 |

전수표의 각 행에 실제 시도·역할·옵션·기대/실제 결과·후보 SHA를 기록한다. 자동 mock 전수 통과를 사람의 실제 조작으로 표시하지 않는다. YouTube 자연어 재생은 올바른 영상 선택과 음성 시작·사람의 청취를 각각 확인한다. 외부 미디어 실패가 있으면 의미 판단이 맞아도 end-to-end 실패로 남긴다.

## 실패와 복귀

무단/다른 대상 실행, 필수 확인 누락, 관리자 상세 공개, 취소 후 늦은 실행, 중복 효과, 원장 감소 또는 숨은4번째 dispatch가 나오면 새 경로의 적용/인수를 중단한다. 현재 결과와 원본을 보존하고 검증한 이전 후보/호환 DB·설정으로 복귀한다. 새 DB/감사와 현재까지의 원장/tombstone은 보존하며 오래된 백업으로 호출 누계를 되감지 않는다.

복귀 후 새 기능의 pending 질문·버튼·확인은 만료시키고 과거 요청을 자동 재생성하지 않는다. 자동 음성 입장/재생도 하지 않는다. 구조화 명령·권한·주시 꺼짐·예산을 확인하고 복귀 SHA/DB의 증거를 따로 남긴다.

사용자가1.1.7에서 요청한 백업 검증 SKIPPED를 기록 그대로 유지한다. 이를 복원 PASS로 쓰거나 이번 계획을 백업 검증 재개 지시로 해석하지 않는다. 구현 중 기존 데이터 보호/복귀 묶음의 필요성과 정식 복구 인수 미확인은 구분한다.

## 완료 판정

- **1.1.8 개발 기능 인수:** C01~C47/I01~I08 및 공개 옵션, P118-01~07, 실제 역할/채널/결과 공개·누계 증거를 같은 후보에 연결한다. 남은 과거 게이트를 함께 기록한다.
- **최적화 채택:** 품질/안전이 유지되고04단계의 비교 기준을 만족한 항목만 채택한다. 효과가 없는 설정은 기준 유지로 기록한다.
- **정식 VERSION·태그·DONE:** 1.1.8 기능 인수뿐 아니라 해당 후보의 필수 전체 출시 게이트가 필요하다. 1.1.6 실패,1.1.7 미디어/음성100회·8시간·운영/복구 미확인을 계획이나 다른 SHA의 성적으로 지우지 않는다.

개발 후보 공개 요약에는 실제 구현 명령, 제한/미지원 상황, 해당 SHA, 시험 결과와 예산, 이전 후보 복귀 근거를 적는다. GitHub 업로드나 제품 배포는 별도 실제 실행 사실이 있을 때만 기록한다.
