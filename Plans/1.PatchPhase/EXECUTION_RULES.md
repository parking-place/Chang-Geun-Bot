# 1.1 계열 공통 실행·인수 계약

- 작성일: 2026-09-28
- 상태: **공통 계약 유지; 1.1.0~1.1.7 개발 진행·부분 시험, 전체 인수 전**. [현재 상태](STATUS.md)를 따른다.
- 적용: `1.1.0~1.1.7`의8개 버전·40단계. 기존 [명세1.3](../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md), [Jev 계약](../0.DevPhase/INFERENCE_PROFILES.md), [현재 환경](../0.DevPhase/ENVIRONMENT.md)을 이어받는다.

## 계획 번호와 상태

사용자 요청에 따라1.1.0부터1.1.7까지 계획 번호를 부여한다. 번호는 구현·태그·배포·출시 완료를 뜻하지 않으며, 기능 추가/DB/API 변경의 호환성은 각 후보에서 별도로 판단한다. 제품 VERSION과 패키지 번호는 이번 문서 작업에서 변경하지 않는다.

각 버전의5단계는 `01 설계`, `02 구현`, `03 안전 회귀`, `04 지정 LXC 검증`, `05 개발 인수·복귀`로 관리한다. [STATUS](STATUS.md)의 단계 상태와 실행 결과를 구분한다. 전 버전 일부 작업을 실행했지만 전건 완료 단계는 없다. 개별 PASS·FAIL·SKIPPED·미실행은 [시험 추적](TEST_MATRIX.md)에 남긴다.

- 다음 버전 **개발 착수**는 필요한 앞선 계약·구현·영향 회귀가 확보되면 가능하다. 전체 과거 출시가 완료됐다고 가정하지 않는다.
- **개발 후보 인수**는 해당 기능을 실제 시험한 고정 후보의 부분 인수다. 남은 전체 조건을 함께 기록한다.
- **정식 출시/DONE**에는 해당 고정 후보에 연결된 필수 기능·권한·품질·성능·음성·복원 증거와 기존 미완료 출시 조건이 필요하다. 후속 후보 성적을 이전 SHA의 PASS로 옮기지 않는다.
- 후속 단계에서 전체 인수 도구를 준비하더라도 초기 버전은 그전까지 개발 후보로 둘 수 있다. 1.1.7의 통합 성적이1.1.0~1.1.6의 정식 출시를 자동 완료하지 않는다.

## 공통 선행 준비

최초 착수 때 현재 Git SHA/dirty diff, 봇·중계 wheel/lock/config hash, DB/schema, 원장/tombstone, 고정 epoch의 예약 호출·남은 한도, 이전 DB/바이너리 복귀 묶음을 제한 경로에서 확인한다. 현재 배포 상태는 시행 시 다시 읽고 과거 기록을 현재 실측으로 쓰지 않는다.

| 과제 | 일찍 준비할 것 | 전체 책임 버전 |
| --- | --- | --- |
| R-01 동적 주시 다후보 | 코드상 의심을 mock으로 재현·반례 확인 | 1.1.0 |
| R-02 미디어 실패 | 실패 표본과 원인 코드 연결을1.1.0에서 준비; 사용자 장애가 재현되면 순서와 무관하게 우선 분류 | 1.1.4 |
| R-03 주시 수명 | 권한/취소 변경마다 영향 W 회귀; 전체 실제 시나리오와 사람 조작 준비 | 1.1.5 |

## 변경하지 않는 실행 경계

- 제품 설치/import/lint/타입/빌드·단위/mock/DB/API/Discord/음성은 DiscordBotLXC에서만 수행한다. 로컬은 파일/Git/문서 검사와 stdlib 원격 제어다.
- 실제 제공자는 hosted Jev API 하나다. 봇과 별도 `changgeun-gateway` 계정의 중계, loopback TLS를 유지한다. OpenJevLXC에 새 작업을 수행하지 않는다.
- API1.2의 엄격 요청/응답 binding, 최대3단계/3dispatch, 전체12초·단계 `min(4초, 잔여시간)`,3단계 시작 잔여≥1초를 유지한다.
- worker1·활성dispatch1·대기4, retry0·redirect0·환경 proxy 미사용·TLS 검증을 유지한다. 풀 재사용은 판단 동시성을 늘리는 변경이 아니다.
- 사용자/채널/주시 출처·세대·DJ·음성·대상 버전은 최신 상태로 검증한다. health 캐시나 선택 UI로 권한/확인 검사를 생략하지 않는다.
- 구조화/조회/관리 기능의 기존 Jev0회를 유지하고 신규 조회·자동완성·버튼도 추가 의미 판단이 필요하지 않으면0회로 설계한다. 정상 자연어의 의미 판단을 키워드만으로 실행하는 우회는 추가하지 않는다.
- 개인정보·원문 대화·키·실제 Discord ID·signed media URL을 공개 문서/로그/manifest로 내보내지 않는다. 비밀을 포함하지 않는 집계/오류 코드만 공개한다.

## 유료 시험과 모델 한계

평가 전 현재 영속 원장의 잔여 한도와 **전체 예정 실험의 합계**를 계산한다. 개발 비교·준비 호출·독립 평가·성능·soak를 서로 무료처럼 취급하지 않는다. 실패/불명/취소 후 예약을 환불하지 않고 같은 요청을 재전송하지 않는다.

예를 들어 개발N문장 두 후보 비교의 최대치는 `2×N×3 + 준비 호출`이다. 독립200문장 한 번은 최대600dispatch이며,1/2/3단계 각100요청의 기본 측정은 경로가 그대로 사용되면600dispatch에 준비 호출이 더해진다. 이는 비용 추산식이며 실제 사용량은 원장으로 센다. 단계 경로를 만들 수 없으면 미실행으로 기록하고100건을 임의 복제해 대체하지 않는다.

현재 평가 프로필의 상한은3000이고, 시작 당시 이미 사용한 호출도 차감한다. 새 run/profile/ledger를 반복 생성해 한도를 우회하지 않는다. 예산이 부족하면 해당 시험을 중단하고 잔여 계획을 기록한다. 한도 변경이 필요하면 별도 명시 범위·설정·검증을 거쳐야 하며 계획 문서가 증액 권한은 아니다.

prompt/config를 바꾸는 비교는 새 후보 식별·binding·실험 기록과 원래 누적 예산의 연속성을 함께 설계한다. 실행 중 immutable 프로필 덮어쓰기나 기존 tombstone/원장 초기화는 허용하지 않는다. 현재 배포 도구가 지원하지 않는 비교/held-out/benchmark/soak runner는 먼저 구현·검증하고 실제 명령을 그 뒤 기록한다.

hosted 내부 forward·미공개 revision은 null/unavailable, 미제공 token·비용은 unknown으로 남긴다. 입력 문자 수를 token 실측으로 바꾸지 않는다. 임계값이나 API probability를 보정된 성공확률로 설명하지 않는다.

## 시험과 성과 판정

각 버전의 `P110-*`~`P117-*` 시험을 [새 시험 추적](TEST_MATRIX.md)에 연결하고 기존 [W/C/Y/T/N/B/O](../0.DevPhase/TEST_MATRIX.md) 중 영향 범위를 명시한다. 의미 있는 회귀는 고정 mock과 실제 제공자/Discord 증거를 나누어 실행한다. 사람의 실제 조작·청취는 자동 PCM/API 성공으로 대신하지 않는다.

계측은 성공 p50/p95뿐 아니라 모든 시도의 오류/timeout/거절/취소율과 호출 수를 함께 낸다. 입력/자료 크기·부하·warm/cold·실제 음성 조건·데이터/후보 hash를 고정한다. 정확도 저하나 정상 요청 거절 증가로 호출 수를 줄인 결과는 개선이 아니다.

최적화 항목도 모두 구현/비교 계획에 포함한다. 그러나 측정상 이득이 없거나 안전/정확도가 나빠지면 기존 동작을 유지할 수 있다. 이때 **검토 완료·기준 유지**라는 결론과 근거를 기록하고 “최적화 적용 성공”이라고 표시하지 않는다. 미실행/실패를 이 결론으로 대체할 수 없다. 신규 기능을 제외하려면 대응 ID의 범위 변경을 명시한다.

성능/한국어/미디어/8시간/복구의 정식 목표는 [기존 출시 기준](../0.DevPhase/RELEASE_CRITERIA.md)을 이어받는다. 낮은 표본·과거37문장·첫 PCM93/100 기록은 새 출시 성적이 아니다.

## 배포·이관·복귀

문서 작성만으로 실제 봇이나 서비스 설정을 바꾸지 않는다. 구현 시에는 새 고정 후보와 제한 시험 경로를 사용하고, 실행 중인 소스와 정식 설치 wheel을 구분한다. 소스 동기화가 활성 후보를 교체하지 않도록 한다.

DB 변경은 필요성을 먼저 확인한 뒤 additive migration으로 작성하고 기존 SQL/checksum을 수정하지 않는다. UI 변경만으로 불필요한 DB migration을 만들지 않는다. 알 수 없는 신 schema를 이전 바이너리에 연결하지 않고, 이전 DB/바이너리·설정·조회 시점이 일치하는 묶음으로 복귀한다. 새 DB/감사/실험 결과도 보존한다.

rollback이 이전 중복 기록을 잃어 같은 요청을 다시 실행하거나, 예약 호출을 되돌리거나, 만료 승인을 살려서는 안 된다. 복원/재시작 후 자동 음성 접속·재생은 하지 않는다. 운영 enable·인증서 교체·서버 외부 백업 대상은 각각 구체적 준비/검증 후 적용 범위를 정한다.

증거는 [기존 양식](../0.DevPhase/EVIDENCE_TEMPLATE.md)에 버전·단계·새 시험 ID·실제 SHA/wheel/config·원장 전후를 연결한다. 원본은 제한 LXC에, 비밀 제거 요약만 `evidence/public/`에 둔다. PR/커밋/제품 VERSION/태그/출시 완료는 별도 실제 작업과 결과가 있을 때만 기록한다.
