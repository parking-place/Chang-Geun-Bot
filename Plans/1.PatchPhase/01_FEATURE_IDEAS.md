# 추가 기능 아이디어

상태: **F-01~09를 1.1.0~1.1.5 개발 후보에 반영·부분 시험, 전체 인수 미완료**. 현재 결과는 [계열 현황](STATUS.md)과 [시험표](TEST_MATRIX.md)를 따른다. 아래는 편성 당시 제안·차이 분석이며 현재 등록 명령의 완성 목록이 아니다. 기존 `/주시`6명령·재생 버튼·자동 퇴장·별칭/태그·곡 제안·목록 교환·되돌리기를 새 기능으로 중복 계산하지 않는다.

## F-01 — 상황별 도움말

현재 [도움말](../../bot/src/changgeun/discord_adapter/client.py)의 `help_command`는 고정 사용법과 소스/prefix 설정을 보여준다. 실제 DB 주시 상태와 관리자 명령 안내는 충분히 연결되지 않았다.

제안은 일반 사용자에게 조회·곡 제안, DJ에게 재생/편집, 서버 관리자에게 주시 설정을 안내하는 것이다. 현재 채널의 미등록·서버 꺼짐·봇 권한 부족·운영자 기능off를 구분한다. “이 채널을 쓰려면 관리자에게 `/주시 추가`를 요청해줘”처럼 다음 한 단계를 제시한다. 다른 채널의 비공개 이름/설정은 사용자 권한 없이 보여주지 않는다.

검증: 미주시 채널에서 도움말을 어디까지 허용할지 명시하고, 관리자 전용 정보 비노출·현재 역할 재검사·Jev0회·설정 변경0을 확인한다. 일반 음악 명령의 허용 채널을 함께 확장하지 않는다.

## F-02 — 길어지는 조회 결과

[현재 응답 처리](../../bot/src/changgeun/discord_adapter/client.py)는 목록/대기열/검색 결과를 문자열로 합치고1900자를 넘으면 전체 내용을 `list.txt`로 전달한다. 긴 결과를 받는 경로는 이미 있으며, 추가할 차이는 파일을 열지 않고 Discord 안에서 페이지별로 보고 선택하는 편의다. 제안함은 조회25건 제한이 있으므로 이후 항목 탐색도 별도로 확장한다. [주시 목록](../../bot/src/changgeun/discord_adapter/watch.py)의 페이지 구현을 참고해 항목 수와 실제 문자열 길이를 함께 제한한다.

표시 번호는 화면의 snapshot에 결합하고, 편집 선택은 안정적인 entry ID·버전으로 전달한다. 페이지를 넘기는 동안 대기열이 바뀌면 갱신을 안내해 다른 곡을 조작하지 않게 한다. 내보내기는 기존 파일 전달 경로를 유지하고 너무 긴 본문 미리보기만 요약한다.

검증: 긴 한글 제목·빈 목록·다수 항목·페이지 중 삭제/이동·타인 버튼·최신 권한·항목 누락/중복을 확인한다. 페이지 조회에 Jev를 호출하지 않는다.

## F-03 — 승인 만료 항목 선택

현재 만료된 곡은 순서와 함께 남고 `승인 만료`로 표시되며 새 DJ의 명시 재생 요청으로 재승인할 수 있다. 추가할 것은 새로운 승인 규칙이 아니라 **기존 항목을 골라 요청하는 화면**이다.

“만료된3번 항목 재생 요청”처럼 단건만 선택한다. 최신 DJ·음성·채널/주시 세대·entry ID/버전을 확인하고 기존 항목을 재사용한다. 이미 처리한 버튼은 중복 재생/큐 복제를 만들지 않는다. 끄기/제거 후 다시 켜기만으로 옛 승인을 살리지 않는다. 일괄 재승인은 별도 범위로 보류한다.

근거: [승인 정책](../../bot/src/changgeun/application/watch.py), [공통 실행기](../../bot/src/changgeun/application/executor.py), [재생 입력](../../bot/src/changgeun/discord_adapter/client.py). 실제 음성 인수는 R-03과 연결한다.

## F-04 — 실패 이유와 다음 행동

현재 공통 실패 안내에 [R-02·R-08](03_STABILITY_AND_ACCEPTANCE.md)의 오류 분류를 연결한다. 요청자에게 모호한 대상을 고를지, 허용 채널을 사용할지, 음성 권한을 확인할지, 슬래시 명령으로 전환할지 안내한다.

최근 요청의 안전한 상태 조회를 검토하되 일반 대화 원문이나 외부 API 응답을 새로 수집하지 않는다. “승인 만료”를 미디어 고장으로 표시하지 않고 “재생 준비 성공”을 실제 음성 시작으로 오표시하지 않는다. 자동 재시도 대신 사용자가 다음 행동을 선택한다.

## F-05 — 현재곡 화면 보강

현재 `/현재곡`에는 제목과 일시정지·계속·넘기기·정지 버튼이 있다. 여기에 준비/재생/일시정지 상태, 볼륨, 반복 모드, 다음 유효 항목, 안전한 원본 영상 참조를 추가한다.

처음에는 명령/상태 전환 시 갱신을 검토한다. 주기적 메시지 수정은 별도 부하 측정 후 도입한다. 재생 경과 시간은 pause/resume을 포함해 정확히 계측할 수 있을 때만 제공하고 시간 이동 버튼은 함께 넣지 않는다. 만료된 버튼과 최신 역할·음성 상태를 재검사한다.

## F-06 — 이름 대신 선택

현재 일반 목록/곡 명령은 문자열을 받아 resolver가 찾으며, `/주시 제거`에는 자동완성이 있다. 저장 목록과 등록 카탈로그에 선택 UI를 확장해 동명 곡을 제작자/길이 같은 안전한 정보로 구별한다.

조회 범위는 현재 서버와 사용자에게 허용된 자료로 제한한다. 삭제/이름 변경 뒤 오래된 선택을 적용하지 않는다. 자동완성은 입력 편의 기능이며 권한·버전 검사를 대체하지 않는다. 검색할 때마다 Jev나 YouTube 외부 검색을 호출하는 방식은 피하고, 등록 자료부터 사용한다.

## F-07 — 관리 이력과 사용량

현재 `watch_change_events`에 감사90일을 보관하지만 관리자 조회 명령은 없다. 예를 들어 `주시 이력` 화면에서 변경 시각·행동·결과를 페이지로 보여주는 것을 검토한다. Manage Guild 최신 검사와 요청자 전용 응답을 적용하며 일반 대화 기록은 추가하지 않는다.

Jev 처리 수·실패 분류·남은 개발 호출 예산을 보여주는 진단은 J-01 계측 뒤 별도로 검토한다. 서버별 집계와 중계 전체 예산을 혼동하지 않고 실제 통화 비용을 모르면 금액을 표시하지 않는다. 봇 계정에 중계 원장/hosted 키 읽기 권한을 주는 대신 필요한 집계만 반환하는 인증된 조회 경계를 설계한다.

## F-08 — 진행 요청 취소

원문 수정/삭제·주시 변경·확인 화면 취소는 이미 일부 요청을 무효화한다. 추가 제안은 **아직 처리 중인 자연어 응답에 요청자 전용 취소 버튼을 제공**하는 것이다.

취소와 커밋의 순서를 원자적으로 대조한다. 이미 완료한 편집은 “취소”라고 표시하지 않고 기존 되돌리기 가능 여부를 안내한다. 전송된 hosted 계산 자체의 중단을 보장하거나 예약 호출을 환불하지 않는다. 늦은 결과로 새 실행을 만들지 않는 기존 계약을 유지한다.

## F-09 — 최근 완료곡

현재 `playback_history`는 성공적으로 종료된 곡을 기록하고 목록 생성의 최근 제외 조건에 사용한다. 이를 제한된 사용자 조회와 새 재생 요청에 연결한다.

실패/중단 곡을 완료곡처럼 표시하지 않고 조회 건수·보존 범위를 정한다. 재요청은 최신 음원 지원 여부와 DJ/음성 권한을 검사해 새 승인을 받는다. 청취자 명단·개인 청취 습관·대화 원문을 추가 수집하지 않는다.

근거: [음성 실행](../../bot/src/changgeun/discord_adapter/runtime.py), [목록 생성](../../bot/src/changgeun/application/generation.py).

## 큰 확장은 분리 검토

시간 이동 재생, 자연어 복합 명령의 순차 실행, 개인 추천, 여러 서버/여러 음성방, DJ 역할·일반 명령 허용 채널 변경은 권한·데이터·재생 계약을 넓힌다. 위 작은 편의 개선과 한 번에 묶지 않고 사용자 요구와 별도 인수 범위를 먼저 정한다.
