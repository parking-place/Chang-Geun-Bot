# 1.1.2 — 권한 사전 검사·후보 조회·자동완성

- 상태: **PLANNED — 문서만 작성, 구현·시험·배포 미실행**
- 범위: **J-04, J-05, J-06, F-06**
- 목적: 확실한 거절의 유료 판단을 줄이고 자료 조회·후보 품질을 개선하며, 저장 목록과 등록 곡을 정확히 선택하게 한다.
- 공통 기준: [실행 규칙](../EXECUTION_RULES.md), [항목 배정](../ITEM_COVERAGE.md), [상태](../STATUS.md), [시험표](../TEST_MATRIX.md).

## 현재와 바뀔 점

현재 자연어의 첫 사전 검사는 조회 권한을 기준으로 하며 실제 행동 권한은 첫 판단 뒤 확인한다. 초기 후보 생성과 각 단계 신선도 확인에서 전체 snapshot을 읽고, 이름 부분 일치/전체 곡·별칭 순회 뒤 앞10개 후보를 사용한다.

일반 목록/곡 명령은 문자열을 resolver에 전달하고 `/주시 제거`만 자동완성을 제공한다. 이 버전은 이미 명백한 권한 거절을 앞당기고 조회 범위를 줄이며, 정확한 이름·별칭 우선 후보와 등록 자료 자동완성을 추가한다. 자연어의 Jev 판단 단계를0회 실행 경로로 바꾸지 않는다.

| ID | 이 버전의 책임 | 제외·후속 경계 |
| --- | --- | --- |
| J-04 | 단일 행동/동일 권한 후보의 명백한 사전 거절 | 혼합 권한 후보의 일괄 거절, 권한 검사 캐시 제외 |
| J-05 | 후보 생성용 자료와 단계 전 최소 버전/세대 조회 분리 | 검증 없이 DB 병렬화·쓰기 트랜잭션 경계 변경 금지 |
| J-06 | 정확한 이름/별칭 우선·후보 상한/충돌 처리 | 오타 유사도만으로 자동 실행·모든 구문 확장 제외 |
| F-06 | 현재 서버의 허용된 저장 목록·등록 곡 자동완성 | 입력마다 Jev/YouTube 검색, 새 추천 기능 제외 |

## 선행 의존성

1. [1.1.0](../1.1.0/README.md)의 동적 출처 회귀·오류 분류·J-01 기준 계측을 사용한다. R-01 미해결 상태에서 새 사전 권한 경로를 추가하지 않는다.
2. [1.1.1](../1.1.1/README.md)의 채택 결과를 기준 후보에 명시한다. 미채택 최적화를 활성화했다고 가정하지 않는다.
3. 작은/큰 카탈로그·긴 큐·별칭 충돌·동명이곡·한글/혼합 대소문자 fixture와 정답 후보 집합을 먼저 만든다.
4. 목록/큐/현재곡·주시 출처의 버전과 안정적 ID를 어느 단계에서 확인할지 기존 실행기 계약과 맞춘다.
5. 후보 생성은 의미 판단 결과에 영향을 준다. 개발 품질 비교를 통과한 뒤 후보를 고정하며1.1.6의 독립 최종 성적을 이 버전 SHA에 소급하지 않는다.

## 사용자·API 계약

- 입증된 동적 prefix 정책과 최신 actor로 사전 검사한다. 일반 사용자 조회/곡 제안과 권한이 다른 후보를 오거절하지 않는다.
- 첫/후속 판단과 커밋·음성 시작의 최신 권한·주시 세대·대상 버전 검사를 유지한다. 조회 최적화가 승인 재사용의 근거가 되지 않는다.
- 정상 자연어는 기존 Jev 단계로 의미를 확인한다. API1.2·최대3dispatch·전체12초/단계4초·활성1/대기4·retry0·Jev Only를 유지한다.
- 후보는 서버의 실제 자료만 사용하고 정확한 이름/별칭·부분 일치의 안정적 순서를 정의한다. 상한 때문에 충돌을 숨기거나 정답을 임의 대체하지 않는다.
- 자동완성은 Jev0회·외부 검색0회이며 현재 서버와 사용자에게 허용된 자료만 보여준다. 제작자/길이 등 안전한 구별 정보만 덧붙인다.
- 선택값은 안정적 내부 ID에 연결하되 사용자에게 불필요한 ID를 표시하지 않는다. 선택 뒤 삭제/이름 변경·권한 회수는 실행 시 다시 확인한다.
- 자동완성 콜백은 편의 입력일 뿐 승인/확인이 아니다. 기존 일반 명령 허용 채널을 확대하거나 주시 설정을 변경하지 않는다.
- 지원할 명령 옵션·표시 길이/후보 개수·응답 시간의 상한은 설계 단계에서 현재 Discord 계약과 대조해 고정한다. 아직 등록된 옵션처럼 안내하지 않는다.

## 측정과 채택 판단

J-04는 거절 유형별 신규 dispatch를, J-05는 SQL/읽은 행/메모리/지연을, J-06은 정답 후보 포함률과 최종 계획 정확도를 각각 비교한다. 입력을 더 많이 거절해서 얻은 호출 감소를 개선으로 표시하지 않는다.

최적화가 효과 없거나 편차 안이면 해당 변경은 기준 유지로 판정하며 성능 개선 PASS라고 쓰지 않는다. 후보 변경이 정확도·위험 계획·명확화율을 악화시키면 조회/자동완성의 독립 변경만 남길 수 있고 최종 범위를 상태/항목 배정에 기록한다.

품질 비교의 입력·정답·카탈로그 크기·순서·prompt/threshold와 최대 호출 수를 미리 잠근다. 개발 자료를 수정한 결과는 개발 성적으로만 표시하고 독립 held-out의 정답을 보며 후보 규칙을 조정하지 않는다.

## 완료·중단·복귀 조건

- 개발 완료: 범위4항목의 채택/기준 유지 이유, P112 전건의 필요한 자동·실제 증거, 옵션 사용법·exact candidate와 복귀 자료를 남긴다.
- 정식 출시: 해당 후보의 의미/대상/확인 필요 품질과 전체 필수 출시 게이트가 충족되어야 한다. 후속1.1.6 결과를 과거 SHA 검증으로 대신하지 않는다.
- 중단: 권한 오거절/우회, 정답 후보 대체·개인/서버 정보 노출, 오래된 선택 실행, 호출 증가 은폐·성능/품질 회귀가 있으면 인수를 멈춘다.
- 복귀: 사전 검사·검색/옵션 변경의 의존 관계를 기록하고 이전 wheel/설정으로 전환한다. 스키마 호환이 없으면 이전 DB 묶음을 사용하고 최신 원본은 보존한다.
- 중계 원장·tombstone·epoch·예산을 초기화하지 않는다. 복귀 후 같은 요청의 중복 실행과 자동 음성 재생이 없음을 확인한다.
