## 목표

일반 멤버에게 곡 제안 경로를 제공하면서 직접 목록·대기열 편집 권한은 주지 않는다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

- proposals의 pending/approved/rejected 상태와 제안자·입력 참조·처리 DJ·대상 목록/큐를 관리하는 action을 작성한다.
- 일반 멤버의 제출·조회 권한과 DJ의 승인/거절 권한을 분리한다. 제출은 실제 목록/큐를 바꾸지 않는다.
- 승인 시 최신 DJ/채널/대상 version/소스 유효성/중복/최대 수량을 공통 실행기로 검사한다.
- 공개 제안 버튼과 두 DJ의 동시 승인에서도 승인 1회·실제 추가 1회가 되도록 트랜잭션/요청 중복 기록을 작성한다.
- 자연어 제안/승인 후보와 한국어 상태 메시지를 등록하고 원문/개인정보 수집은 최소화한다.

## 산출물

- 곡 제안·제안함·승인/거절 명령/버튼과 영속 상태·감사 기록.
- P-05~06 시험 코드와 만료/삭제 대상/중복 승인 처리표.

## LXC 검증

- P-05: 일반 멤버 제출 후 목록/큐 불변·비DJ 승인 거절·DJ 승인에서만 추가를 DiscordBotLXC에서 검증한다.
- P-06: 동시 중복 승인·재시작 후 재전송·승인 중 DJ 해제/대상 삭제를 시험한다.
- T-03~05와 N-11·18~20을 회귀하고 자연어 제안의 호출/확인 정책을 DiscordBotLXC의 봇·중계에서 run별로 검증한다. provider/profile_id/config hash는 최초 요청에 고정하며 다른 프로필 응답·같은 요청의 재전송이 추가 승인/추가를 만들지 않아야 한다.

설치·빌드·lint·타입검사·단위/mock 시험을 포함한 제품 실행은 위 LXC에서만 수행한다. 로컬은 코드/문서 작성과 읽기 검토만 한다. [증거 양식](../EVIDENCE_TEMPLATE.md)에 실제 revision·실행 서버·결과를 남긴다.

## 통과 기준

- [ ] 승인되지 않은 제안이 재생이나 목록에 자동 반영되지 않는다.
- [ ] 동시/중복 승인에서도 한 번만 추가하며 권한/대상 확인 실패 시 상태 변경이 없다.
- [ ] 필수 시험의 실행 증거가 있으며 NOT_RUN/SKIPPED/실패를 PASS로 표시하지 않았다.

## 중단·후속 처리

제안 처리 권한을 일반 편집 권한과 혼합하지 않는다. 처리 불가 참조는 실패/보류로 표시하고 가짜 성공을 반환하지 않는다.

통과 후 [버전 목차](README.md)와 [STATUS](../STATUS.md)를 갱신한다. 계획 문서 작성만으로 이 단계를 완료 처리하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
