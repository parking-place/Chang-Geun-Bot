## 목표

모델이 조건을 판별하더라도 곡 선택은 실제 카탈로그의 필터·규칙으로 수행한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

- 포함/제외 태그·운영자 표기 제작자·곡 수·총 길이·최근 재생 제외 조건의 스키마를 등록한다. 최대 생성 100곡·최근 제외 7일을 기본으로 한다.
- 실제 DB 필터 → 영상 ID 중복 제거 → 최근 재생 제외 → 재현 가능한 seed 선택 → 미리보기 → 확인 흐름을 작성한다.
- 조건에 맞는 곡이 부족하면 실제 수량을 표시하고 조건 완화/적은 수량 저장을 사용자가 선택하게 한다. 외부 검색이나 가상 곡으로 채우지 않는다.
- 20곡 이상 일괄 추가에는 수량·중복·실패 미리보기와 확인을 적용한다. 목록 생성 미리보기 정책은 소량에도 유지한다.
- 자연어 조건을 확정할 수 없으면 입력/선택 UI로 전환하며 추가 모델 질문·자유 문자열 생성으로 보완하지 않는다.

## 산출물

- 목록 생성 서비스·조건 설정 UI·seed/최종 선택 ID 감사 기록.
- P-03~04 데이터/시험 코드와 generation action의 권한/확인 정책.

## LXC 검증

- P-03: 동일 snapshot/조건/seed의 동일 결과와 태그 제외·영상 중복·최근 재생·길이 제약을 DiscordBotLXC에서 검증한다.
- P-04: 후보 부족·20곡 경계·100곡 상한·확인 전 상태 변경을 시험한다. DiscordBotLXC의 봇·중계에서 Jev API의 조건 해석 후 판단·질문·요청별 provider 호출 누계 각각 ≤3과 DJ 재검증을 확인한다.

설치·빌드·lint·타입검사·단위/mock 시험을 포함한 제품 실행은 위 LXC에서만 수행한다. 로컬은 코드/문서 작성과 읽기 검토만 한다. [증거 양식](../EVIDENCE_TEMPLATE.md)에 실제 revision·실행 서버·결과를 남긴다.

## 통과 기준

- [ ] 실제 등록된 ID만 저장하며 필수 확인 전에는 DB 목록/큐 변경이 없다.
- [ ] 부족한 수량을 숨기지 않고 현재 snapshot 버전이 변경되면 재확인한다.
- [ ] 필수 시험의 실행 증거가 있으며 NOT_RUN/SKIPPED/실패를 PASS로 표시하지 않았다.

## 중단·후속 처리

지원 불가 조건을 모델 상식으로 추측하지 않는다. 정책 변경은 조건 스키마·도움말·보충 시험에 함께 반영한다.

통과 후 [버전 목차](README.md)와 [STATUS](../STATUS.md)를 갱신한다. 계획 문서 작성만으로 이 단계를 완료 처리하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
