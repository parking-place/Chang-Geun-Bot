## 목표

같은 개발 세트에서 `jev-api`의 지원 한국어 구문·후보·프롬프트를 개선하고 각각 N-01–36 안전 회귀를 통과한다. [추론 프로필](../INFERENCE_PROFILES.md)에 따라 결과·임계값·측정 한계를 분리하며 개발 데이터나 mock 결과를 0.9.0 실제 held-out 성적으로 대신 보고하지 않는다.

## 로컬 코드 작업

- 평가 데이터/채점 도구/모델 응답 fixture를 작성하고 개발 세트와 최종 평가 세트의 ID·파일·사용 목적을 분리한다.
- 구현한 개발전용 `python3 scripts/test_profile.py --profile jev-api --suite korean-eval`로 동일 소스·입력·정답·후보·seed·초기 snapshot을 run별 독립 DB/큐·원장·증거 경로에서 실행하도록 작성한다. 정지·drain·불명 요청 tombstone·새 run/세션으로 전환하며 개발·mock·최종 결과를 합산하지 않는다.
- hosted에는 합성/익명 fixture의 최소 원문/후보만 전송하고 계획 요청 수×최대 단계 수와 준비 호출에 맞는 run 한도를 사전 설정한다. 20회 smoke 예시 한도를 대규모 평가에 그대로 적용하지 않는다.
- 명세의 최초 최종 평가 최소 200문장, 권장 명확 120/모호·비명령·부정 60/우회·교란 20 구성을 0.9.0 준비 계약으로 기록한다.
- 띄어쓰기·오타·존댓말·반말·수사·따옴표·짧은 제목·새 곡명/목록명을 개발 세트에 포함한다.
- 의도·대상·확인 필요·최종 실행 계획을 별도로 채점한다. 불필요한 확인을 자동 해석 성공으로 세지 않는다.
- Jev API의 동일 개발 세트에서 1/2/3단계 정책을 비교하고 3단계는 진입 조건을 충족한 요청에만 사용한다. 반복 실행의 선택 ID/확률/지연의 완전 일치를 통과 조건으로 삼지 않는다.
- 프로필·단계별 해석 성공·불필요 확인·잘못된 실행·공급자 dispatch·지연·조기 종료·진입 이유를 집계한다.
- raw probability/confidence를 정확도 백분율로 표시하거나 검증 없이 정확도와 직접 비교하지 않는다. Jev API 개발 세트로 threshold/prompt를 독립 보정하고 held-out 전에 프로필/설정 해시에 고정한다.
- 기본 결과가 미달이면 별칭·후보·지원 구문을 먼저 개선한다. 자동 fallback은 넣지 않는다.
- 모델/프롬프트 변경은 새 설정 해시/run에서 검증한다.
- 0.5.0 계약 N-16/17/26/27/29/33/35/36을 포함한 전체 N 시험과 T 핵심 기능 회귀를 묶는다.
- 최종 held-out 내용에 맞춘 프롬프트 조정을 금지하고 변경 시 별도 새로운 평가 세트를 준비한다.

## 산출물

- 공통 개발 데이터/채점 도구·run별 고정 prompt/threshold·N 회귀 목록과 LXC 결과.
- 프로필/run/설정 해시·의도/대상/확인/최종 계획·1/2/3단계별 품질·실패율과 미확인 항목 보고서.

## LXC 검증

- [B-09·B-12](../TEST_MATRIX.md)를 이 단계의 필수 인수로 삼아 독립 복제·프로필/run별 증거·별도 품질/성능/manifest·미공개 revision 표시·점수 비합산을 확인한다. B-05·B-06·B-07·B-11의 예산/기한/전송 회귀도 평가 실행에 포함한다.
- DiscordBotLXC에서 설치·빌드·lint·타입 검사·채점 도구/기능 시험을 실행하고 DiscordBotLXC의 중계의 Jev API 실제 프로필과 각각 연결한다.
- N-01–36을 Jev API 실제 프로필에서 실행하되 mock·오류 주입·실제 공급자 증거를 분리한다.
- run별 개발 세트의 명확한 지원 명령 의도/대상 95% 이상을 목표로 개선하고 미달 구문·오류 원인을 원문/비밀 없는 보고서에 기록한다.
- hosted는 같은 입력 규모·단계 경로의 왕복 지연·호출량·오류율을 측정하고 미공개 내부 token/forward/revision은 미확인으로 둔다.
- DiscordBotLXC 재생 중과 미재생, 동시 1개/순간 4개를 비교하며 timeout·취소·실패 비율을 제외하지 않는다.
- 3/5/7초 p95 목표의 최종 검증은 0.9.0의 준비 호출5회·경로별 최소 100개와 held-out 시험으로 남긴다.

## 통과 기준

- 전체 안전 회귀 통과: 무확인 위험 실행·권한 우회·잘못된 항목 수정·취소/만료 뒤 실행 0건.
- 개발 평가와 held-out, Jev API 실제 프로필과 mock을 분리하고 품질·불필요 확인·오류율·경로 지연·계측 한계를 누락 없이 보고한다.
- Jev API에서 개발 세트 95% 목표 미달 시 원인/지원 축소/개선안을 기록하고 해당 경로 완료나 버전 전체 DONE·출시 PASS를 선언하지 않는다.

## 중단·후속 처리

Jev API의 필수 시험이 미실행·실패이면 해당 단계를 완료하지 않는다. mock·개발 소규모 시험으로 실제 품질·장시간 인수를 대체하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
