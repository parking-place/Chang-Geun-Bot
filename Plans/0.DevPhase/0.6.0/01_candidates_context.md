## 목표

자유 문자열 생성 대신 원문·규칙·실제 데이터로 소수 후보를 구성한다. 사용자별 최근 문맥과 현재곡/대기열 snapshot, [선택 프로필](../INFERENCE_PROFILES.md)을 판단 시작에 고정하여 오해석·시험 데이터 혼합을 실행으로 연결하지 않는다.

## 로컬 코드 작업

- 호출 여부·허용 채널·사용자 cooldown 2초·입력 상한을 확인하고 1단계 전에 request ID·공통 deadline을 생성한다.
- 봇이 고정한 provider/profile_id/config_hash와 게이트웨이 ready의 일치를 확인하고 요청에 결합한다. 입력 원문이나 hosted 키의 유무로 공급자를 선택하지 않는다.
- 멘션 기본 허용, 일반 wakeword 기본 비활성 정책을 적용한다. 설정된 호출 경계를 넘어 모든 대화를 분석하지 않는다.
- 원문과 표시 제목은 그대로 보존한다. 검색용 문자열만 Unicode·공백·영문 대소문자를 정규화한다.
- 문장부호를 무조건 삭제하지 않고 제목 충돌과 별칭 모호함을 실제 후보로 남긴다.
- URL·Discord 멘션·명시적 목록명·등록 별칭·숫자를 규칙으로 추출한다.
- `세 곡`, `스무 곡` 등의 수사 파서를 작성하고 곡명 숫자와 수량의 문맥 차이를 시험 코드로 표현한다.
- 새 목록명은 따옴표/명시적 구문에서 안전하게 추출되는 경우만 받는다. 검색어 분리 실패는 입력창으로 보낸다.
- 문맥 키를 `(guild_id,text_channel_id,user_id)`로 두고 TTL 기본 120초를 적용한다.
- 시험 문맥/DB/원장 namespace를 프로필과 run/세션별로 분리한다. 설정 비교는 같은 seed·fixture·초기 snapshot을 독립 복제하고 이전 실행의 현재곡·대기열·확인 토큰을 이어 쓰지 않는다.
- 답장한 봇 검색 결과·현재곡·해당 사용자에게 표시한 최근 항목을 근거 출처와 함께 후보화한다.
- 다른 사용자·다른 채널/서버·만료된 문맥을 합치지 않는다. 동일 별칭 복수 후보는 선택 메뉴로 보낸다.
- 현재곡·항목 ID·숫자 위치·목록/대기열 버전을 snapshot에 묶고 단계 사이 현재곡을 조용히 교체하지 않는다.
- candidate set ID와 서버 보유 계획을 저장하고 후보 수 최대 12개를 적용한다. 미구현 P1 행동은 실행 후보로 만들지 않는다.
- hosted에는 필요한 원문·최소 후보 설명·불투명 후보 ID만 전달한다. Discord 사용자/guild/채널 ID·전체 대화·DB·내부 토큰은 보내지 않으며 합성/익명 평가 fixture를 기본으로 한다.

## 산출물

- 호출·상한·정규화·수사 파서·후보 생성·문맥 저장·snapshot 코드와 시험 코드.
- 원문/검색 문자열 분리 정책, 후보 근거 출처, 미지원 구문/UI 안내 목록.
- 사용자별 문맥 TTL·candidate set·버전 snapshot·프로필/run 격리 계약과 hosted 최소 전송 목록.

## LXC 검증

- [B-04·B-08·B-09·B-11](../TEST_MATRIX.md)의 프로필 일치·이전 세션 재사용 차단·동일 fixture 독립 복제·최소 외부 전송을 후보/문맥 경로에서 검증한다.
- DiscordBotLXC에서 설치·빌드·lint·타입 검사·규칙/문맥 단위/mock 시험을 실행한다.
- N-02 현재곡 ID, N-03 세 번째 항목 snapshot, N-08 만료 문맥, N-09 다른 사용자, N-10 동일 별칭을 시험한다.
- N-12 제목의 주입 문자열과 N-15 상한 초과·말미 부정어가 데이터/축약 안내로 처리되는지 확인한다.
- 띄어쓰기·존댓말·반말·따옴표·오타·짧은 제목·숫자가 있는 제목을 개발 데이터로 시험한다.
- DiscordBotLXC의 중계 공통 게이트웨이에서 Jev API 실제 프로필의 후보/입력 상한·clarify 스키마와 확인 가능한 token 상한을 검사한다. hosted token 산정 방식을 검증할 수 없으면 미확인으로 남기고 임의 추정으로 상한 통과를 선언하지 않는다.
- Jev API 프로필에 동일 seed·fixture·초기 snapshot을 적용하고 독립 저장소·새 run/세션·이전 문맥 재사용 차단을 검증한다. 모드 전환은 테스트 서비스 정지·drain·불명 요청 tombstone 뒤에만 수행한다.
- 중간 검색·후보 생성이 공통 12초에 포함되는지 확인하며 느린 작업에서 기한을 멈추지 않는다.

## 통과 기준

- 후보 ID는 실제 데이터에서만 나오며 문맥 혼합·오래된 snapshot의 자동 대체가 0건이다.
- 상한 입력을 임의 잘라 실행하지 않고 검색어/대상 불명확은 UI로 전환한다.
- 원문·제목 보존과 숫자/수량 규칙, run별 데이터 격리/최소 전송의 증거가 DiscordBotLXC의 봇·중계에 남는다.

## 중단·후속 처리

추출이 불안정하면 지원 구문을 좁히고 사용자 입력창을 제공한다. 별도 번역·자유 생성 모델을 붙여 해결하지 않는다. 문맥 근거가 없는 후보는 다음 단계 모델에 추측시키지 않고 확인으로 종료한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
