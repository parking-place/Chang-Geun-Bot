## 명령 해석 범위

접두어를 제거한 문장을 기존 `/부탁`·멘션과 같은 `Pipeline`에 보낸다. 접두어용 별도 자유 생성 에이전트나 별도 실행기는 만들지 않는다. 모델은 봇이 실제 데이터로 만든 후보만 고르고, 해석 결과는 `ActionPlan`을 거쳐 공통 실행기가 수행한다. 실행되지 않은 것을 성공으로 답하지 않는다.

2026-09-28 소스에는 목록 재생·현재곡 목록 추가·빈 목록 생성·목록/대기열 조회·일부 대기열 편집·기본 제어·입퇴장 후보가 있다. 구조화 명령의 모든 기능이 자연어에서도 지원되는 상태는 아니다. 버전의 지원 행동표를 고정하고 다음을 분류한다.

| 분류 | 대표 문장 본문 | 1.0.2 인수 범위 |
| --- | --- | --- |
| 필수 조회 | `목록 보여줘`, `대기열 알려줘`, `지금 무슨 곡이야` | 실제 목록/대기열/현재곡 조회; 현재곡 자연어 후보 보완 |

누락된 필수 후보는 실제 구조화 동작과 같은 인자 검증·실패 동작을 먼저 확보한 뒤 추가한다. 목록 전체 URL의 자동 재생처럼 범위가 큰 요청은 1.0.1 지원 범위·미리보기·확인을 함께 따른다. 조건 생성·되돌리기 등 P1 전체를 무조건 자연어 지원이라고 소개하지 않는다. 각 행동에 지원 예문·반례·역할·확인·대체 명령을 기록하며 필수 항목을 미지원 처리한 채 출시하지 않는다.

## 권한·문맥·추론 계약

- 채널 접수 허용은 DJ 권한을 주지 않는다. 조회와 변경 권한은 원래 action에 따라 결정한다. 가능한 권한 거절은 추가 추론 전에 종료하고, 실행/확인 직전에는 최신 역할·서버·텍스트/음성 채널·대상·버전·generation을 다시 확인한다.
- 삭제·대량 변경·덮어쓰기·음성 이동 등 기존 확인 기준을 유지한다. 공개 버튼의 클릭자·요청자·실제 DJ·서버·채널·TTL·계획 해시를 검사하며 다른 사용자의 클릭으로 실행되지 않는다.
- 문맥은 `(guild, channel, user)`·TTL 120초·근거 snapshot으로 격리한다. 다른 채널에서 같은 사람이 한 발화도 자동 참조하지 않는다. 호출되지 않은 대화나 답장 대상의 전체 본문을 문맥으로 수집하지 않는다.
- 부정·대조 문장과 존댓말·띄어쓰기·수사·목록명 숫자·제목 속 명령문을 구분한다. `틀지 말고 목록만 보여줘`는 조회이며 `비우고 다음 곡 넘겨줘`는 복합 동작으로 종료한다.
- 실제 provider는 `jev-api` 하나다. API 1.2·고정 config/prompt/threshold·최대 3단계/3질문/3 dispatch·전체 12초·단계 4초·3단계 잔여 1초를 유지한다. 접수 대기·권한 갱신·후보를 위한 메타데이터 검색을 포함하여 기한 안에 ActionPlan과 즉시 실행 가능한 경로의 승인을 확정하거나 선택/확인 UI를 제시한다. `clarify` 이후 추가 재질문 호출이나 자동 retry/fallback은 없다.
- 유효 요청 신원은 2단계의 영속 매핑을 사용한다. hosted 내부 forward·미공개 model revision은 null/unavailable이다. `mock`은 지정 LXC의 격리 계약 시험이며 실제 Discord에는 활성화하지 않는다.

## 해석·사용자 선택·미디어 기한 구분

자연어의 12초는 봇이 자동으로 판단하고 계획을 만드는 기한이다. 검색 결과 선택 UI와 위험 작업 확인 UI는 각각 최대 60초의 요청자 전용 후속 토큰으로 대기할 수 있다. 이 대기를 원래 자연어 요청의 자동 추론 시간에 합산하지 않으며, 원래 기한을 연장하거나 만료 후 Jev를 추가 호출하지도 않는다. 사용자의 명시적인 선택/확인이 새 후속 행동을 시작한다. 토큰은 원래 요청·고정 후보/계획·사용자·채널·TTL에 묶고 최신 권한·대상·버전·generation·원문 취소 여부를 다시 검증한 후 한 번만 소비한다. 만료되거나 대상이 바뀌었으면 자동 재해석 없이 새 요청을 안내한다. 현재 ActionPlan의 만료 시각을 단순히 늘리는 것으로 이 계약을 구현하지 않는다.

실행 승인 후 현재 재생 항목의 미디어 준비에는 [1.0.1 소스 계약](../1.0.1/README.md)의 **대기·추가 시도 포함 총 25초, 누적 소스 해석 15초·누적 첫 오디오 준비 10초**를 적용한다. 각 단계는 남은 총시간으로 제한하며 추가 시도로 시계를 초기화하지 않는다. 아직 차례가 오지 않은 음악 대기열의 대기 시간과 자연어 판단·사용자 선택 대기는 이 준비 시계에 포함하지 않는다. 준비 완료 때 현재 entry·작업 소유권·generation·권한을 다시 확인하고 정지·스킵·퇴장·취소 뒤 늦은 오디오를 시작하지 않는다. 이 미디어 작업을 이유로 Jev를 재호출하지 않으며 해석 지연과 실제 오디오 시작 지연을 별도로 기록한다.

## 검증과 통과 기준

C-10은 일반 사용자·DJ·역할 해임·음성 이동·채널 제거·대상 버전 변경을 해석/확인/커밋 경계마다 주입한다. C-11은 위험 요청 확인·타인 버튼·중복 버튼·60초 토큰 경계·원문 삭제 후 버튼·공개 응답 삭제 후 버튼을 검증한다. C-12는 필수 행동표의 정답 action·실제 대상 ID·변경 결과와 미지원 반례를 고정한다. C-13은 두 사용자×두 채널·120초 경계·삭제된 목록·현재곡 전환의 문맥 회귀다. C-14는 1/2단계 조기 종료·조건부 3단계·4회 차단·429/timeout/취소·늦은 결과와 run 예산을 검증한다. 자연어 12초 종료 후 유효한 60초 후속 토큰의 명시 클릭은 최신 검증을 거쳐 처리되며 추가 Jev 호출은 0인지, 미디어 25초/15초/10초 기한은 별도로 누적·취소되는지도 대조한다.

잘못된 대상 변경·권한 우회·무확인 위험 실행·중복 실행·기한 만료 후 실행은 허용하지 않는다. 실제 Jev 해석 품질은 [5단계](05_acceptance_and_rollout.md)에서 개발 세트와 분리하여 판정한다. 실제 음성 동작과 해석 계획만 생성한 평가를 합산하지 않는다.

## 2026-09-28 개발 기록

[고정 후보와 부분 실행 증거](../../../evidence/public/youtube-prefix-20260928.md)를 따른다. 단위/mock·실제 API·첫 PCM·Discord 사용자 청취를 구분하며 아래 필수 인수 조건은 유지한다. 부분 성공만으로 이 단계나 전체 버전을 VERIFIED/DONE으로 표시하지 않는다.

주소 입력은 `https://youtube.com/watch?v=...`와 `youtube.com/watch?v=...`, `www.youtube.com/...`, `m.youtube.com/...`, `youtu.be/...`를 같은 안정 video ID로 처리한다. 본문에서 ID의 대소문자를 보존하고 잘못된 host·HTTP·인증/port·복수 URL은 임의 영상이나 이전 목록으로 대체하지 않는다.
