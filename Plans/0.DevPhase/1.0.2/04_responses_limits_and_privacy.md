## 응답 계약

접두어 입력은 일반 메시지다. 그 자체에는 interaction token·ephemeral·interaction defer가 없다. 현재 `MentionEntry`의 호환 인터페이스를 응답 포트로 정리하고, 일반 메시지는 공개 답장/전송·수정, 슬래시/버튼은 interaction 응답을 사용한다. 공개 응답에 비밀값·원문 전체·내부 에러를 넣지 않는다. 버튼을 클릭해 새 interaction이 생긴 뒤의 거절 안내는 그 interaction에서 비공개 응답을 사용할 수 있다. [Discord Message](https://docs.discord.com/developers/resources/message), [Interaction 응답](https://docs.discord.com/developers/interactions/receiving-and-responding), 확인 2026-09-28.

정상 접수 표시 목표는 1초 이내다. 공개 응답 하나를 접수 → 확인/결과로 갱신하고 재시도·단계별로 메시지를 늘리지 않는다. typing은 선택적인 표시이며 durable 접수 완료나 interaction defer로 세지 않는다. 명령 원문이 삭제되면 새 답장 링크 없이 필요 최소 결과만 처리하고, reply 실패를 이유로 실행을 다시 하지 않는다.

응답 원장에 최초 응답 메시지 ID와 전송 상태를 요청과 연결한다. 전송 전 실패는 기존 요청 상태에 따라 처리하되, 전송 성공 여부가 불명확하면 무조건 다시 보내지 않는다. 응답 메시지 삭제·수정 실패·403·429·네트워크 유실에도 DB/음성 효과는 재실행하지 않는다. 결과를 이미 커밋한 뒤 응답 실패가 발생하면 실행 실패로 위장하지 않고 결과 상태와 응답 오류를 분리한다. 원문 편집·삭제의 취소는 2단계 계약을 따른다.

자동 멘션은 `allowed_mentions` 제한으로 끄고 답장 작성자를 ping하지 않는다. 제목·사용자 입력은 Markdown/멘션 escape 후 길이를 제한한다. 확인 버튼은 공개임을 전제로 타인의 조작을 실행 계층에서 거절한다. 여러 채널의 동일 재생 상태는 기존 패널을 제한 빈도로 갱신한다.

## 접수 부하와 비용

파서 불일치·허용 채널 밖·빈/긴 입력은 Jev dispatch 0회다. 접수 cooldown은 서버 내 사용자 단위 2초를 기본으로 하여 여러 허용 채널을 번갈아 보내도 우회되지 않게 한다. 동시에 진행 가능한 자연어 요청은 사용자당 1개, 전체 접수 대기는 최대 4개로 제한한다. 실행 중인 요청은 임의의 새 요청으로 교체하지 않으며, 초과 요청은 짧은 대기 안내 또는 무응답 제한으로 끝낸다. 같은 사용자에게 제한 안내는 10초에 최대 1회로 묶는다. 이 값들은 제품 기본 설계값이며 LXC 부하 검증 전 측정 결과가 아니다.

공통 gateway의 worker 1·활성 dispatch 1·대기 4와 서버 접수 제한을 함께 계측한다. 봇의 자동 판단 큐에서 기다린 시간도 최초 수신 시점부터 자연어 기한 12초에 포함하며, 대기 초과를 새 request ID로 자동 재전송하지 않는다. 명시적인 검색 선택·위험 확인 UI 대기는 각 60초 후속 토큰과 최신 검증을 사용하고, 승인 후 미디어 준비는 별도 25초/15초/10초 계약을 따른다. [3단계 시간 계약](03_korean_commands_and_execution.md)에 따라 세 시간을 별도 기록한다. 여러 채널은 하나의 서버 음성 세션을 공유한다. 공통 실행기의 낙관적 버전/트랜잭션·음성 generation으로 경합을 해결하고 마지막 입력이 이전 확인을 묵시적으로 덮어쓰지 않는다.

run별 provider 예산 사전 예약·소모·잔여량을 유지하며 오류/취소/재시작은 환불하지 않는다. 테스트 규모×최대 3회와 준비 호출을 사전 산정한다. 반복 run 생성이나 후보 변경으로 소모한 예산을 초기화하지 않는다. 실제 외부 비용은 확인된 계정 정보로만 보고하고 내부 forward 추정값을 비용 근거로 만들지 않는다.

## 최소 정보와 보존

Jev에는 접두어 제거 후 필요한 명령 본문·익명 후보 설명·불투명 요청 ID만 보낸다. Discord 메시지/사용자/서버/채널 ID, 전체 대화·첨부·본문과 무관한 답장·역할 목록·토큰은 보내지 않는다. 사용자가 본문에 넣은 식별자·비밀값의 최소화/거절 처리를 시험하고, 필요한 곡명·URL의 전달 범위와 제공자 보존 정책을 관리자 안내에 명시한다. 수신 가능한 모든 내용이 외부 전송되는 것으로 오해하지 않게 안내한다.

일반 대화·거절 채널 원문은 저장하지 않는다. 자연어 원문 로그는 기본 비활성, 선택 수집은 별도 안내·익명화·72시간 이내 삭제다. 운영 로그 7일·변경 감사 90일·문맥 TTL 120초 계약을 유지한다. 메시지 중복 방지에는 원문 대신 식별자 매핑·해시·상태를 쓰고 접근을 제한한다. SDK 메시지 캐시는 비활성 또는 필요한 최소로 제한하며 raw edit/delete를 처리한다. 삭제·만료는 백업 복원 뒤에도 적용한다.

## LXC 검증과 통과 기준

C-09에서 외부 요청 캡처·로그·캐시·만료·백업 복원으로 최소 정보 계약을 검증한다. C-15에서 두 채널×여러 사용자·초당 반복·순간 4개/초과·재생 중 부하·429/예산 소진을 주입한다. C-16에서 공개 응답·typing·확인 버튼·전송 유실·삭제·권한 회수·중복 이벤트·결과 커밋 후 예외를 검증한다. 입력 하나의 효과와 응답 상태를 분리 집계하며 중복 실행·명령을 통한 ping·내부 비밀 노출·무제한 큐 증가가 0이어야 한다.
