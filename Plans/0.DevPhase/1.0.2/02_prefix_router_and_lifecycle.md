## 파서 계약

메타데이터로 서버·채널·작성자·메시지 종류를 통과한 새 `MESSAGE_CREATE`에만 파서를 적용한다. 일반 사용자 기본 메시지와 일반 사용자 답장 메시지를 허용하며, 전달된 메시지 snapshot·첨부·임베드·인용 대상의 내용을 따라가 명령으로 읽지 않는다. 답장도 현재 작성 본문이 접두어로 시작해야 한다.

| 입력 | 결과 |
| --- | --- |
| `!!창근아 노동요 목록 틀어줘` | 뒤 문장 한 요청 접수 |
| `!!창근아` 또는 접두어 뒤 공백만 | 사용 예 한 번; Jev 0회 |
| `!!창근아` 다음 개행 뒤 `목록 보여줘` | 개행을 구분자로 인정하고 한 요청 접수 |
| `!!창근아\t목록 보여줘`에서 `\t`가 실제 탭 | 탭을 구분자로 인정 |
| ` !!창근아 목록 보여줘`, `안녕 !!창근아 정지` | 시작 위치 불일치; 무응답·Jev 0회 |
| `!!창근아노동요 틀어줘`, `!!창근아님 안녕` | 구분자 없음; 무응답·Jev 0회 |
| `!!창근아, 목록 보여줘`, 전각 `！！창근아` | 정확한 접두어 경계 불일치; 무응답·Jev 0회 |
| 인용 기호·코드블록 뒤 호출어, 접두어 안 제로폭 문자 | 무응답·Jev 0회 |
| 두 줄에 재생과 삭제를 각각 요청 | 한 요청의 복합 동작으로 분리 안내; 부분 실행 금지 |

CRLF만 LF로 변환하고 접두어 뒤 앞뒤 ASCII 공백·탭·개행을 제거한다. 본문 내부를 임의로 이어 붙이거나 NFKC로 유사 접두어를 허용하지 않는다. 본문 길이는 접두어 제거 후 Unicode 코드포인트로 500까지이며, 초과는 끝의 부정어를 잘라 해석하지 않는다. 본문 속 두 번째 호출어를 재귀 실행하지 않는다. 본문이 실제 봇 멘션으로도 시작하는 혼합 입력은 이중 라우팅하지 않고 한 입력 안내로 종료한다.

## 접수·중복·취소

현재 `Pipeline.interpret()`가 호출마다 UUID를 생성하므로 메시지 이벤트 재전달을 그대로 넘기면 호출과 실행이 중복될 수 있다. 접수 계층에서 `(guild_id, channel_id, message_id)`의 유일키를 영속 저장하고 외부 전송용 무작위 불투명 request ID와 원문 해시·설정 세대·상태를 한 트랜잭션으로 결합한다. Discord ID 자체를 Jev request ID로 보내지 않는다. 모든 판단 단계·ActionPlan·확인·실행·응답이 이 요청을 사용하도록 인터페이스를 보완한다.

상태는 접수·진행·확인 대기·완료·취소·실패·결과 불명으로 구분한다. 중복 수신은 기존 요청을 조회하며 신규 추론·확인 토큰·실행·공개 응답을 만들지 않는다. 같은 ID의 본문 해시가 바뀌면 새 요청으로 취급하지 않는다. Gateway Resume의 이벤트 재전달과 프로세스 재시작에도 원장을 사용한다. 과거 메시지 이력을 읽어 재실행하지 않으며, 처음 관측한 생성 시각이 30초보다 오래된 이벤트는 미접수로 기록한다. 이 30초는 재전달 필터이며 명령의 전체 12초 기한을 늘리지 않는다. [Discord Gateway Resume](https://docs.discord.com/developers/events/gateway#resuming), 확인 2026-09-28.

수정·삭제 이벤트는 새 명령을 생성하지 않는다. 이미 접수된 메시지의 수정·삭제가 커밋 전에 관측되면 취소 표식을 원자 기록하고 대기·추론 결과·확인 버튼을 무효화한다. 이벤트가 늦게 도착해 이미 커밋한 변경을 자동 undo하지 않으며, 이 한계를 도움말에 알린다. 메모리 캐시 밖의 raw edit/delete와 bulk delete도 ID로 처리한다. 수정된 본문을 다시 해석하려면 사용자가 새 메시지를 보내야 한다.

추론과 DB 커밋 사이에 취소·정책 세대·최신 역할·대상 버전을 다시 확인한다. 재시작·복원 후 진행/결과 불명 요청은 종료 상태로 보존하고 재전송하지 않는다. 봇 접수 기록과 gateway tombstone·호출 예산의 복원 순서를 연결한다. 접수 식별 기록은 원문 없이 감사 보존 정책 90일에 맞추고, 만료 이후에도 생성 시각 필터로 오래된 입력의 재실행을 막는다.

## LXC 검증과 통과 기준

- C-03: 위 문법표·Unicode·탭·CRLF·여러 줄·혼합 호출을 표 기반으로 검증한다.
- C-04: 빈 본문과 501자 이상 본문은 입력을 자르지 않고 안내하며 Jev 0회로 종료한다. 1자·500자 본문은 길이 검사에서 허용하고, 이후 내용·후보 검증에 따라 처리한다. 정상 지원 문장은 길이 경계 때문에 차단하지 않으며 초과 본문의 말미 부정어를 잘라 실행하지 않는다.
- C-06: 수신 전/추론 중/확인 중/커밋 후 수정·삭제·bulk delete 경쟁에서 잘못된 재해석·자동 undo가 없는지 검증한다.
- C-07: 같은 이벤트 동시 두 번·Resume·재시작·백업 복원·커밋 후 응답 유실을 주입한다. 신규 provider dispatch·DB 효과·음성 효과는 요청당 원래 한 경로만 허용한다.
- C-08: `/부탁`·실제 봇 멘션·접두어를 하나의 입력 분류기로 구분하며 메시지 하나의 이중 진입을 차단한다. 기존 구조화 입력의 권한·중복 제어도 회귀한다.

영속 중복 방지와 취소 원자성이 입증되기 전에는 실제 여러 채널 접수를 활성화하지 않는다. 메모리 집합만으로 재시작 안전을 PASS 처리하지 않는다.
