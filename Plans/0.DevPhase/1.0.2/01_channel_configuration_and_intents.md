## 목표와 설계

운영자가 고른 여러 채팅 채널에서만 접두어 명령을 받는다. Discord가 본문을 전달할 수 있는 권한과 봇이 명령을 처리할 채널 설정은 별개로 검증한다.

새 설정의 제안 이름은 `commands.prefix.enabled`, `commands.prefix.value`, `commands.prefix.allowed_text_channel_ids`다. typed loader·파서와 LXC 회귀를 구현했고 설정 예시/runbook에 연결했다. 기본값은 비활성, 값은 정확히 `!!창근아`, 채널 목록은 빈 목록이다. 활성화 시 채널을 하나 이상 명시해야 하며, 각 ID는 등록 서버의 실제 일반 텍스트 채널이자 공통 `allowed_text_channel_ids`의 부분집합이어야 한다. 전체 채널을 의미하는 와일드카드·카테고리·이름 매칭은 받지 않는다.

초기 설정은 제한된 배포 설정으로 관리한다. 시작 시 타입·중복·서버 소속·삭제된 채널·채널 유형·유효 권한을 검사하고, 하나라도 불일치하면 접두어 기능을 비활성으로 표시한다. 기존 정상 설정을 조용히 확대하지 않는다. 재설정은 접수 중지 → 진행 접두어 요청·확인 무효화 → 검증된 설정 교체 → 새 세대 시작 순서로 한다. 채널 제거·권한 회수는 실행 직전에도 재확인한다. 런타임 설정 UI를 제공한다면 서버 관리 권한과 감사 기록을 요구하며 DJ 역할만으로 허용 채널을 넓힐 수 없다.

## Discord 접근 계약

`GUILD_MESSAGES`는 이벤트 수신, `MESSAGE_CONTENT`는 일반 메시지 본문 접근에 사용한다. Developer Portal의 해당 앱 상태에서 Intent 사용 자격·토글·필요한 승인을 확인하고 코드의 Intent 설정도 일치시킨다. 고정 서버 수를 승인 기준으로 가정하지 않는다. privileged intent 미승인 연결 오류·비어 있는 본문을 정상 명령 없음으로 감추지 않고 접두어 준비 상태에 남긴다. 멘션 예외로만 성공한 시험은 멘션 없는 접두어 수신 증거가 아니다. [공식 Gateway 문서](https://docs.discord.com/developers/events/gateway#message-content-intent), 확인 2026-09-28.

특히 `4014`는 해당 Gateway 연결 전체가 닫히는 오류이므로 접두어만 비활성화하면 슬래시·멘션이 계속 수신된다고 가정하지 않는다. 봇 관리자가 접두어 기능을 끄고 미승인 Message Content Intent를 제외한 설정을 검증한 뒤 통제된 재연결로 구조화 명령 수신을 복구한다. 설정을 바꾸지 않은 무한 재접속을 차단하고, 마지막 오류·시도 횟수·복구 상태를 원문 없이 기록한다. 이 복구는 본문 접근을 우회하거나 접두어를 몰래 다른 방식으로 활성화하는 절차가 아니다.

Intent는 채널별 본문 전달 필터가 아니다. 봇이 수신할 수 있는 이벤트 중 앱의 채널 허용 목록을 먼저 검사하여 허용되지 않은 내용은 파서·로그·Jev·문맥 저장소에 전달하지 않는다. 봇 역할·채널 overwrite의 `VIEW_CHANNEL`, `SEND_MESSAGES`를 최소 권한으로 구성하고, 원문에 답장하는 경로에는 `READ_MESSAGE_HISTORY` 필요 여부를 실제 시험한다. 본 계획은 관리자 권한을 요구하지 않는다. 쓰기 권한이 없어 결과를 알릴 수 없는 채널은 명령 실행 전 거절한다. [공식 Permissions](https://docs.discord.com/developers/topics/permissions), 확인 2026-09-28.

서버 구성원의 참여 여부·역할·음성 상태 갱신은 기존 공통 권한 경로를 사용한다. 접두어 도입을 이유로 전체 멤버 목록이나 과거 채팅 수집을 추가하지 않는다. 실제 채널·역할 ID와 포털 화면은 제한 증거에만 보관하고 공개 계획에는 넣지 않는다.

## 산출물과 LXC 검증

- typed 설정·시작 검증·prefix 준비 상태·관리자용 점검 안내, 기존 예시의 미구현 `allow_plain_wakeword`/`wakewords` 처리 방침을 함께 정리한다. 과거 설정값만으로 새 기능이 자동 활성화되지 않게 마이그레이션한다.
- C-01: 비활성 기본값·활성+빈 목록·중복 ID·다른 서버·비텍스트 채널·공통 목록 밖·삭제 채널·설정 변경 경합을 격리 LXC에서 시험한다.
- C-02: 실제 멘션 없는 본문 수신을 확인한다. Intent 꺼짐·준비 실패 진단, `4014`의 연결 종료·재접속 폭주 차단·관리자 비활성화 후 해당 Intent 없이 재연결·구조화 명령 복구를 시험한다. 자동 포털 변경·우회 접근은 하지 않는다.
- C-05: 등록 두 채널과 미등록 한 채널, 별도 서버·DM·스레드·포럼·봇·웹훅·시스템 메시지의 접수 여부를 검사한다. 거절 입력의 Jev dispatch·DB 변경은 0이다.

설정 검증과 실제 수신은 별도 증거다. 실제 앱의 Intent 준비나 해당 채널 접근이 확인되지 않으면 이 단계는 VERIFIED가 될 수 없다. 제품 실행·시험은 지정 LXC에서만 한다.
