## 독립 평가

기존 개발 37문장과 분리하여 접두어·채널·실제 상태를 포함한 개발 세트를 만들고, 별도 작성자의 held-out 200문장 이상을 고정한다. 최소 구성은 명확한 지원 요청 120, 모호함·비명령·부정 60, 우회·교란 20이다. 입력 문법만 보는 C 시험과 문장 해석 품질을 구분한다. 역할·채널·음성·DB snapshot·정답 action·대상 ID·확인 여부·예상 외부 호출 범위를 각 사례에 결합한다.

띄어쓰기·존댓말/반말·오타·수사·숫자 제목·따옴표·여러 줄·동일 이름·저장 목록/대기열 대조·현재곡·120초 문맥·원문 수정/삭제·채널 사이 경쟁을 포함한다. 아직 구현하지 않은 동작은 명확한 지원 요청의 분모에서 조용히 제거하지 않는다. [필수 행동표](03_korean_commands_and_execution.md)를 평가 전에 고정하고 필수별 사례 수와 미지원 안내 정답을 공개한다.

C-17 합격 기준은 다음과 같다.

- 명확한 지원 요청 120개 이상에서 **최종 action·대상·인자·필요 확인이 모두 맞는 비율 95% 이상**. 불필요한 확인은 자동 해석 성공으로 세지 않는다. 현재 요구되는 확인을 제공한 것은 감점하지 않는다.
- 권한 우회·잘못된 대상 변경·부정문 반대 실행·복합 요청 일부 실행·무확인 위험 실행·중복 실행·취소/기한 뒤 실행 **0건**.
- 봇·설정·prompt·threshold·provider/API·후보·데이터 hash를 고정하고 개발/mock/held-out 결과를 분리한다. held-out 결과로 prompt를 보정했다면 새 독립 세트로 재인수한다.
- 실제 Jev 평가의 호출 수·실패·429·timeout·clarify·단계별 해석을 모두 보고한다. mock 선택 결과나 내부 확률을 실제 정확도로 세지 않는다.

성능은 준비 5회와 실제 발생 가능한 1/2/3단계 경로별 최소 100요청을 예산에 포함한다. 1/2/3단계 p95 3/5/7초·전체 12초 목표, 접수 표시 1초 목표와 실제 음성 시작 시간을 구분한다. 경로를 만들기 위해 불필요한 추가 판단을 넣지 않는다. 달성하지 못한 경로와 실패 요청도 보고한다.

## 실제 Discord 인수

C-18은 고정 candidate로 일반 텍스트 허용 채널 두 곳 이상과 미허용 채널 한 곳, DJ/일반 사용자 두 역할에서 수행한다. 실제 채널 ID·사용자 ID·키·원문은 제한 증거에만 둔다.

1. 실제 봇 멘션 없이 `!!창근아` 요청을 보내고 본문 수신·정확한 한 번 접수·한국어 결과·슬래시/멘션 병행을 확인한다. 미허용 채널과 스레드에서는 Jev 호출 0을 대조한다.
2. 승인 시험음으로 조회·목록 재생·일시정지·계속·넘기기·정지·음량·목록 편집·대기열 확인 UI·권한 거절을 시험한다. API의 ActionPlan 성공과 실제 음성 청취/조작 결과를 별도로 남긴다.
3. 1.0.1 소스 게이트가 통과했다면 같은 prefix 경로의 YouTube 링크 재생·다음 추가·재생 불가 사유와 혼합 목록 동작을 추가 인수한다. 미통과를 승인 시험음 PASS로 대체하지 않는다.
4. 연속 최소 8시간 실제 음성 재생과 여러 채널의 접두어 입력을 혼합한다. 재생 끊김·메모리/큐·호출 예산·재연결·수정/삭제·역할 변경·제공자 장애·403/429를 기록한다. 장애 주입으로 끊긴 시험 구간을 이어 붙여 연속 8시간으로 계산하지 않으며, 중단된 실행과 이후 새 연속 시험의 증거를 분리한다. 단위/mock 장시간 루프로 대체하지 않는다.
5. 기능 비활성화·허용 채널 제거·본문 접근 실패·고정 후보 rollback·백업 복원에서 이전 요청·확인·응답을 재실행하지 않고 구조화 조작과 기존 재생 상태 정책을 유지하는지 확인한다.

사용자 조작·실제 청취가 필요한 항목은 실행 사실과 결과 확인을 함께 남긴다. 과거 1.0.0 시험음 청취 기록을 새 prefix/새 소스의 인수 기록으로 복사하지 않는다.

## 단계적 적용과 완료 판정

접두어 비활성 상태로 새 설정/DB 마이그레이션 호환성을 검증하고 백업·동일 revision 증거를 고정한다. 지정 시험 서버의 한 채널에 먼저 적용하고, 인수 후 선택한 여러 채널로 확대한다. rollback은 접수 중지·진행 요청/확인 종료·원장/tombstone 보존·검증된 이전 설정/후보로 복귀하는 절차다. 역마이그레이션 미검증 상태에서 예전 코드만 덮어쓰지 않는다. 운영 선택 채널은 실제 적용 단계에서 제한 설정으로 받아 검증한다.

실행 명령·설정 이름·운영자의 Portal 작업 안내는 구현과 지정 LXC 증거가 생긴 뒤 runbook에 추가한다. 이 계획에는 미구현 명령을 사용 가능한 도구로 적지 않는다. 제품 `VERSION`·태그·DONE은 1.0.0 → 1.0.1 → 1.0.2 승격 순서와 전체 필수 게이트를 만족한 뒤에만 만든다.

산출물은 지원 문장/미지원 안내, C-01~18·영향 T/N/B 결과, 고정 manifest, 실제 두 채널/권한/음성 증거, 독립 품질·성능·8시간 보고서, 개인정보/보존 안내, 장애/rollback 기록이다. 하나라도 필수 미실행·실패라면 해당 단계와 버전의 인수 완료를 선언하지 않는다.
