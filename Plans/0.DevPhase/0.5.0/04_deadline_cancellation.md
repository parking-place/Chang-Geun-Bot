## 목표

모든 판단 단계가 하나의 deadline을 공유하고 취소·퇴장·만료 뒤 늦은 결과가 실행되지 않게 한다.

## 로컬 코드 작업

- 초기 공통 `request_deadline_ms=12000`, `stage_timeout_ms=4000`, `third_stage_min_remaining_ms=1000`을 설정한다.
- 봇의 공통 시간 시작은 1단계 전 판단 절차 시작 시점으로 정의한다. 전처리·중간 후보·검색·문맥·큐 대기도 포함한다.
- monotonic 경과시간으로 운영 기한을 관리하고 API에는 모든 단계에서 같은 만료 시각을 전달한다.
- 서버 실효 기한을 원래 요청 기한·서버 상한·현재 단계 제한 중 가장 이른 값으로 계산한다.
- 단계별 실효 제한 `min(남은 공통 시간, 단계 제한)`을 사용하며 후속 단계에서 기한을 초기화/일시정지하지 않는다.
- 3단계 진입 전에 실제 잔여 시간·예산을 확인한다. 1초는 시작 조건이며 완료시간 보장이 아님을 반영한다.
- 게이트웨이 동시 dispatch 1개·대기 최대 4개를 강제하고 초과 요청은 429로 빠르게 돌려보낸다.
- 큐 대기 중 만료·취소를 해제하고 실행 중 취소는 결과 폐기 상태로 전이시킨다.
- 취소만으로 다음 CPU 계산을 중첩 실행하지 않는다.
- hosted는 전송 취소/timeout이 외부 계산 중단을 보장하지 않는다. 진행 중 transport가 정리될 때까지 게이트웨이 슬롯을 유지하고, 정리 뒤에도 외부 실행 불명 상태를 tombstone으로 보존한다. 외부 계산의 동시 1개를 관측했다고 주장하지 않는다.
- hosted timeout·응답 유실 뒤 재전송/대체 프로필 호출은 0회다.
- 정지한 작업 watchdog과 제한된 서비스 재시작 정책을 정의하고 실행 불명 상태는 원장 복구 규칙을 적용한다.
- 판단 종료 후 외부 검색·음성 연결·사용자 확인은 별도 명령 상태로 관리하되 취소/generation과 확인 만료를 재검증한다.
- 시험 설정·후보 변경은 테스트 봇/게이트웨이 정지·유입 차단·drain 및 불명 요청 tombstone 기록 뒤 새 run/세션에서만 허용한다. 외부 계산 중단 확인을 전환 완료 증거로 꾸미지 않는다.

## 산출물

- 공통/단계 기한 계산, 큐·계산 취소 상태, 늦은 결과 폐기 코드와 시험 코드.
- deadline·취소·슬롯 점유·큐 수·504/429·결과 폐기의 운영 지표.

## LXC 검증

- [B-07·B-08](../TEST_MATRIX.md)의 공통 deadline·취소/후발 결과·설정·후보 변경 drain과 실행 세대 분리를 검증한다. hosted 외부 계산 중단 여부는 관측 불가로 보존한다.
- DiscordBotLXC의 중계에서 설치·lint·타입 검사·가짜 시간/계산 mock 시험과 Jev API 실제 프로필 지연 시험을 분리 실행한다.
- N-28의 3단계 잔여 부족, N-29의 공통/단계 초과, N-17의 지연·OOM을 시험한다.
- DiscordBotLXC에서 T-15 늦은 검색과 퇴장, N-30 늦은 대상·권한 변경, timeout/취소 뒤 실행 0건을 확인한다.
- 동시 1개와 순간 4개, 대기 최대 초과를 나눠 시험하며 대기 시간도 deadline을 소비하는지 확인한다.
- hosted 지연/응답 유실을 주입해 취소 뒤 추가 dispatch·예약 환불·늦은 결과 실행이 모두 0회인지 확인한다. 실제 외부 계산 중단은 미확인으로 남긴다.
- 전처리·중간 검색 지연을 넣어 단계별 시간 초기화와 숨은 기한 연장을 탐지한다.

## 통과 기준

- 모든 단계가 같은 공통 기한을 유지하고 초과·취소·퇴장 뒤 결과 실행이 0건이다.

## 중단·후속 처리

늦은 실행·기한 연장·게이트웨이 슬롯 중첩이 발생하면 해당 경로의 다음 버전을 차단한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
