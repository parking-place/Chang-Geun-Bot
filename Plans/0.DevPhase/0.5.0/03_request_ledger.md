## 목표

서비스 재시작과 동시 요청에도 같은 판단을 다시 실행하지 않고, Jev API 프로필에 요청당 최대 3단계·3질문·공급자 dispatch 3회를 강제한다. [추론 프로필](../INFERENCE_PROFILES.md)의 분리·전환 계약을 원장이 보장하며 이 기능을 추후 안정화로 미루지 않는다.

## 로컬 코드 작업

- DiscordBotLXC의 중계에서 run별 시험 원장 저장소를 분리하고 봇 DB·운영 원장을 공유하거나 조회하지 않는다. mock/Jev API 실제 프로필의 결과·실행불명 기록을 섞지 않는다.
- run별 원장 안에서 `(request_id, stage_index)`를 중복 키로 두고 profile ID/provider/설정 해시·run ID·본문 해시·candidate set·공통 만료·단계 상태·공급자 호출 누계·결과 참조를 저장한다.
- 첫 요청의 profile ID/provider/설정 해시를 요청 수명 동안 고정하고 후속 단계의 변경을 409로 거절한다. 프로필을 바꿔 같은 활성 판단을 이어가지 못하게 한다.
- 최초 1단계 접수 시 서버가 공통 만료와 설정 상한을 확정한다. 클라이언트 카운트와 남은 시간으로 상한을 늘리지 않는다.
- 1→2→3 순서·이전 단계 유효 완료·요청 비종료 상태를 검사한다. 1→3·병렬 후속 단계·종료 뒤 추가 단계를 거절한다.
- 시작·중복 판정·예산 예약을 하나의 원자적 저장 경로로 작성한다. 동시에 도착한 요청이 예산을 각각 승인받지 않게 한다.
- 같은 키·같은 본문은 캐시 결과 재사용 또는 진행 중 실행 합류만 허용한다. 같은 키·다른 본문은 409다.
- dispatch 전에 공급자 호출 예산을 원자적으로 예약한다. 전송 시작·성공 여부가 불명확한 경우에도 예약을 환불하지 않으며 hosted timeout/429/5xx/네트워크 실패를 재호출 근거로 사용하지 않는다.
- hosted에는 요청당 예산과 별도로 run 전체 dispatch 한도를 원자 예약한다. 예정 요청 수×최대 단계와 준비 호출이 한도를 넘으면 runner 시작을 거절하며 실패·취소도 환불하지 않는다. smoke 예시 20회는 평가 규모에 맞춰 명시 조정한다.
- 유효하지 않은 응답 뒤 자동 대체 단계·다른 프로필/fallback·새 숨은 request ID를 붙이지 않는다.
- 예약/실행/완료/실패/취소/만료 상태 전이와 재시작 시 복구 분류를 명시한다.
- 재시작 후 실행/전송 여부가 불명확한 항목은 tombstone과 503·안전 실패로 종료한다. 같은 판단을 재실행하지 않고 hosted가 외부에서 계산을 계속하는지 확인할 수 없다는 상태를 보존한다.
- 원장 보존 기간은 요청 deadline과 중복 방지 기간을 포함하도록 정한다. 만료된 요청 ID를 새 요청으로 부활시키지 않는다.
- 원문 대신 최소 메타데이터·해시·필요한 결과를 보관하고 원장 로그/보존 정책을 적는다.
- 새 숨은 request ID로 동일 명령을 다시 판단하거나 다중 worker 경로로 예산을 우회하지 못하게 한다.
- 시험 설정·후보 변경 전 테스트 봇/게이트웨이 유입을 중지하고 drain한다. 불명 요청 tombstone을 남긴 뒤 run별 DB·원장·증거와 새 run ID/세션을 선택하며 이전 요청/문맥/확인 토큰을 이어 쓰지 않는다. 실행 중 hot switch를 제공하지 않는다.

- 단계 건너뛰기·동시성·중복·재시작·예산 환불 금지 시험 코드.

## LXC 검증

- [B-05·B-06·B-08·B-11](../TEST_MATRIX.md)의 예산·중복/불명 재실행 차단·시험간 전환/tombstone·run 한도 원자 예약을 검증한다. B-08 복원/롤백 확장은 0.8.0에서 추가 인수한다.
- DiscordBotLXC의 중계에서 설치·lint·타입 검사·원장 단위/mock 시험과 Jev API 실제 프로필 통합 시험을 분리 실행한다.
- N-27 같은 3단계 중복, N-33 1→3 및 병렬 후속 요청, N-35 실행 도중 재시작/재전송을 시험한다.
- 같은 키 다른 본문·연장된 만료·종료된 요청·만료 ID 재사용을 거절하는지 확인한다.
- dispatch 전후 원장 장애와 hosted 응답 유실을 주입하여 불명확 상태를 성공 또는 미전송으로 추측하지 않는지 검사한다.
- 동시 호출의 원장 상태·공급자 dispatch·run별 usage를 대조한다. hosted 추정 forward를 실제 누계에 넣지 않는다.
- 진행 중 프로필 변경 거절·정지/drain 뒤 새 run 분리·이전 결과/문맥/토큰 재사용 차단과 tombstone 보존을 검증한다.

## 통과 기준

- Jev API 실제 프로필의 단계 순서/중복/동시성/재시작 시험 통과, 요청당 공급자 dispatch 누계 3회 이하.
- 같은 키/본문 재전송의 추가 dispatch 0회이며 불명확 실행/전송 상태의 자동 재실행과 예약 환불은 0회다.
- run별 원장·봇 DB 경계, 전환/보존 정책, 원자적 예약을 증거로 확인한다.

## 중단·후속 처리

누계 불일치·중복 실행·순서 우회·불명확 상태 재실행이 하나라도 생기면 버전 게이트를 차단한다. 원장 보정으로 호출 수를 축소해 보고하지 않고 원인을 수정한 뒤 DiscordBotLXC의 중계에서 해당 경쟁 시험을 다시 수행한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
