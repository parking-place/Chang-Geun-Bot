## 목표

- 메타데이터 취득과 Discord 오디오 전송을 별도 기능으로 평가한다.
- 전송 권한과 선택한 경로의 플랫폼 정책이 확인된 음원만 실재생 시험에 사용한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 작성·읽기 검토만 한다. 의존성 설치·검사·시험·build·음성 probe는 LXC에서 실행한다.

- MetadataProvider·SearchProvider·PlaylistImporter·AudioSourceResolver·AudioPlayer 인터페이스를 각각 정의한다.
- 원본 영상 참조와 별도 허용 음원 매핑을 구분한다. 원본 링크 보유를 오디오 전송 허가로 취급하지 않는다.
- youtube_audio_enabled 기본 false와 기능별 metadata/search/import/audio 활성화 조건을 설정한다.
- 운영자 제공 별도 음원의 제공 출처·전송 권한·사용 범위·수명·등록 ID 기록 형식을 작성한다. 실제 비밀 주소/서명 URL은 일반 Plans에 넣지 않는다.
- 실행 시점 공식 정책 검토에 필요한 근거·날짜·경로·제약과 대안 기록을 설계한다. 업로더 동의만으로 플랫폼 정책 충족을 선언하지 않는다.

## 산출물

- 소스별 기능/정책/권한/실측 상태의 결정 기록 양식.
- 분리된 제공자/오디오 인터페이스와 기본 비활성 설정 소스.
- 실재생 시험용 권한 확인 음원 준비 기준 및 미지원 한국어 응답.

## LXC 검증

- DiscordBotLXC에서 설정/인터페이스 단위시험과 미지원 소스 차단을 수행한다.
- 개발 검증 담당자는 선택 경로의 공식 정책·콘텐츠 전송 권한을 확인하고 근거를 기록한다.
- 확인되지 않은 소스가 resolver에 도달하거나 임시 재생 주소가 DB/로그에 남는지 검사한다.

## 통과 기준

- 메타데이터 사용 가능과 음성 재생 가능 상태가 독립적으로 기록된다.
- 1.0.0은 승인 음원 재생·YouTube 링크/목록 관리로 확정됐다. 직접 YouTube 오디오는 출시 범위에서 제외하고 false로 유지한다. 승인 음원의 권한·기술 인수는 계속 필수다.
- 소스 불확실성은 허용으로 추정하지 않고 명시적인 미지원 상태와 대안을 제공한다.

## 중단·후속 처리

- 적합한 실재생 시험용 소스가 없으면 오디오 활성화 gate를 닫는다.
- 사용자 결정이 필요한 소스 경로·기능 축소는 구체적인 검토 기록을 만든 뒤 처리하며 가짜 재생 성공으로 대체하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
