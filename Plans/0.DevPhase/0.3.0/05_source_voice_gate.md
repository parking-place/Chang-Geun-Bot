## 목표

- 기술·정책·권한이 모두 확인된 경로만 다음 버전의 AudioSourceResolver로 넘긴다.
- 유튜브 참조 가능과 직접 오디오 재생 완료를 혼동하지 않는 최종 기능 표를 만든다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 작성·읽기 검토만 한다. 의존성 설치·검사·시험·build·음성 probe는 LXC에서 실행한다.

- source별 metadata/search/import/audio 상태·미지원 안내·구성 default를 정리하고 gate 결과와 연결한다.
- 재생 직전에 임시 입력을 취득하고 DB에 영구 저장하지 않는 resolver 계약과 만료/실패 처리를 작성한다.
- 권한이 확인된 별도 음원 mapping은 원본 링크/출처와 분리하며 youtube 직접 전송 구현을 대체했다고 표시하지 않는다.
- 0.4.0에 전달할 실제 지원 source·오디오 생성/종료/취소 이벤트·generation·권한 재검증 계약을 정리한다.
- 직접 YouTube 오디오는 1.0.0 범위에서 제외하고 false로 유지한다. 승인 음원 경로의 출처·권한·기술 인수를 기록한다.

## 산출물

- 소스 기능 활성화/미구현/미검증 표와 근거 기록.
- DiscordBotLXC의 DAVE·UDP·실재생 probe·입장 정책 인수 결과.
- 0.4.0 AudioSourceResolver/AudioPlayer 연결 계약과 중단 조건.

## LXC 검증

- DiscordBotLXC에서 설정 default·미지원 source 차단·임시 주소 DB/로그 누출 시험을 실행한다.
- 03단계 실재생과 04단계 실제 voice 결과를 교차 확인하고 필요한 실패 원인만 재검증한다.
- T-12 증거와 DAVE/권한/소스 gate 증거를 공통 템플릿으로 작성한다. 운영 토큰/채널은 사용하지 않는다.

## 통과 기준

- 실측 DAVE·허용 소스·접근 정책이 모두 통과한 경로가 1개 이상 있어야 0.4.0 실재생을 활성화한다.
- YouTube 직접 오디오는 1.0.0 범위 제외/비활성이며 승인 음원·링크/목록 관리의 필수 인수를 통과해야 한다.
- 소스 대안으로 제품 요구를 충족하는지에 대한 결정은 근거와 승인 상태로 기록하고 임의로 전체 출시 완료를 주장하지 않는다.

## 중단·후속 처리

- 어느 필수 gate든 실패하면 메타데이터/목록 기능만 유지하고 실재생 활성화를 중단한다.
- 문서 작성·mock 성공은 실측을 대신하지 않는다. 실제 실재생 인수와 핵심 재생 T 시나리오는 0.4.0이다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
