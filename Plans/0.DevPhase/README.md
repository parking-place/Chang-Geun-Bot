# 창근이 개발 계획: 0.0.0 → 1.0.3

작성일: 2026-09-27. 기준은 [개발 명세 1.3](../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md)과 `.private/ServerInfo`·`.private/Jev-API-key`다. 문서 버전1.3과 제품 버전은 서로 다른 번호다. 2026-09-28 추가한 [후속 범위 결정](../../docs/decisions/0006-youtube-and-prefix-roadmap.md)이 1.0.1 YouTube 직접 재생과 1.0.2 지정 채널 호출 계획에 적용된다.

현재 저장소에는 명세·계획과 bot/inference 구현, 설정·원격 동기화·설정·후보 변경 도구가 있다. 지정 LXC에서 부분 검증과 시험 서버 사용자 조작을 수행했으며 [STATUS](STATUS.md)와 [실행 기록](../../evidence/public/execution-20260927.md)에 범위·제한을 남긴다. 아래 계획의 전체 인수는 아직 완료 전이다. 비공개 원본과 기존 서비스를 보존하며 격리 개발 경로를 사용한다.

## 작업 원칙

- 로컬에서는 제품 코드·테스트 코드·설정·배포 스크립트·문서를 작성하고 읽어 검토한다.
- 설치, import 확인, lint, 타입 검사, 빌드, 단위시험, mock 시험, 통합시험, 모델 실행, DB·음성 시험은 모두 **DiscordBotLXC**에서 수행한다. Git 메타데이터 관리·문서 파일 생성과 링크 검토는 로컬 문서 작업에 해당한다.
- `jev-api`에서는 게이트웨이가 외부 Jev API를 호출한다. 통합시험은 두 서버의 같은 소스 revision을 사용한다.
- 초기 서비스는 Discord 서버 1개·동시 음성채널 1개다. 다중 서버 운영, 웹 관리 화면, 음성 인식, 외부 LLM fallback은 1.0.0 범위에서 제외한다.
- 슬래시·버튼·자연어는 공통 실행기와 권한 검사기를 사용한다. 모델은 실제 동작을 실행하지 않는다.
- 각 버전의 단계는 01 → 05 순서로 수행한다. 앞 단계 통과 증거 없이 뒤 단계를 완료 처리하지 않는다. 독립적인 코드 초안은 병행할 수 있으나 검증 의존성을 생략하지 않는다. Jev API 필수 안전 게이트와 단계별 실제 증거를 갖춰야 전체 버전을 완료할 수 있다. 0.0.0/01은 문서 계약만 검토하는 단계이므로 REVIEWED로 통과하고, 02에서 최소 원격 실행 환경을 준비한 뒤 LXC 검증을 시작한다.

## 테스트 프로필

[INFERENCE_PROFILES](INFERENCE_PROFILES.md)가 선택·설정·전환·비교 시험의 공통 계약이다. 프로필 선택 도구는 `--profile jev-api`로 설정·의존성·격리 DB/원장·결과 경로를 선택한다. 자동 계약시험은 `mock`, 실제 시험은 명시 선택한다. `--dry-run`은 호출 없이 설정을 점검한다. [설정/프로필 템플릿](../../deploy/README.md)과 loader·선택 runner를 구현했다. 현재 지원 suite/검증한 명령은 [runbook](../../docs/REMOTE_DEVELOPMENT.md)에 기록하며 계획된 대량 평가를 실행 완료로 간주하지 않는다. 키 유무에 따른 자동 선택, 장애 시 자동 fallback, 실행 중 hot switch는 허용하지 않는다.

## 진행과 차단 처리

단계를 시작하면 STATUS를 IN_PROGRESS로 바꾸고, 산출물 작성 후 CODE_READY로 표시한다. 지정 LXC의 증거가 있어야 VERIFIED, 해당 버전 게이트가 통과해야 DONE으로 바꾼다. 문서 전용 0.0.0/01의 REVIEWED는 제품 시험 PASS와 구분하며, 버전 전체의 원격 증거는 05에서 확인한다. 시험을 못 돌린 상태·skip은 PASS가 아니다. 실패 시 해당 단계를 고치고 영향받은 회귀 범위만 다시 시험한다.

0.0.0의 탐색은 0.3.0 DAVE/소스·0.5.0 모델/API 검증을 대신하지 않는다. 승인 음원으로 음악봇을 개발할 수 있지만, 이를 YouTube 직접 재생 완료로 표시하지 않는다. 2026-09-27 사용자 승인으로 1.0.0은 승인 음원 재생과 YouTube 링크·목록 관리로 범위를 확정했다. 승인 음원 인수나 한국어 안전 기준이 미충족이면 전체 출시는 차단한다.

서버 주소·SSH 키 경로·실제 Discord ID·비밀값은 공개 계획으로 복사하지 않는다. 접속 기준은 `.private/ServerInfo`에서 확인하며, 실행 증거도 비밀값을 제거한 뒤 보관한다. 1.0.1/1.0.2 계획에서는 공식 YouTube·Discord·yt-dlp 문서를 확인하고 각 계획에 출처와 확인일을 남겼다. 실제 계정 설정·버전·정책 적용은 구현 시 다시 확인한다. 키 자료의 존재는 실제 호출 성공을 뜻하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.

## 후속 버전의 진행 순서

1.0.1/1.0.2는 현재 IN_PROGRESS다. 사용자 구현 요청에 따라 별도 개발 후보에 미디어·접두어를 적용하고 부분 LXC 검증을 수행했다. [새 실행 증거](../../evidence/public/youtube-prefix-20260928.md)를 따른다. 독립 작업은 병행할 수 있으나 정식 승격은 1.0.0 → 1.0.1 → 1.0.2 순서다. 1.0.1 소스 조건이 미확정이면 1.0.2 채널/문법/권한을 승인 음원으로 시험할 수 있지만 YouTube 명령 인수를 완료한 것으로 표시하지 않는다.

## 1.0.3 주시 채널 관리 계획

앞서 후속 작업으로 남긴 채널 설정 명령을 [결정0007](../../docs/decisions/0007-watch-channel-management.md)과 [1.0.3의5단계](1.0.3/README.md)로 구체화했다. 관리자용 `/주시`6명령은 Jev0회이며 정적 음악 명령 채널과 동적 prefix 정책을 분리한다. 사용자 구현 요청으로 1.0.3은 IN_PROGRESS다. [관리 명령·영속 정책·자동 회귀 증거](../../evidence/public/watch-channels-20260928.md)를 추가했고 전체 W 실제 인수는 남아 있다. 이전 버전 인수 상태를 유지하고 정식 승격은 1.0.0 → 1.0.1 → 1.0.2 → 1.0.3 순서를 따른다.

2026-09-28부터 OpenJevLXC에 새 작업을 수행하지 않는다. 현재 실행 위치는 [환경 계약](ENVIRONMENT.md)과 [결정0008](../../docs/decisions/0008-single-lxc-jev-api.md)이 우선한다.
