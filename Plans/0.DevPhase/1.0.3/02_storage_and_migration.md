# 1.0.3 Phase 2 — 서버별 영속 설정과 초기 이관

- 상태: **IN_PROGRESS — 개발 봇 적용·자동 회귀·사용자 부분 인수 통과, 전체 W 인수 미완료**
- 선행: [Phase 1](01_commands_and_permissions.md)의 명령·권한 계약
- 실행: DB migration·동시성·백업 시험은 지정 LXC의 격리 DB에서 수행한다.

## 저장 계약

`0006_watch_channels.sql`과 별도 설정 서비스로 구현했다. 기존 0001~0005 checksum은 유지한다. 아래는 구현 계약이며 고장·실제 환경 전체 인수는 계속 진행한다.

| 설계 테이블/필드 | 책임 |
| --- | --- |
| `watch_settings(guild_id, enabled, revision, enable_generation, seed_applied, updated_at)` | 서버 켜짐/꺼짐·낙관적 버전·전체 승인 세대·최초 이관 완료 |
| `watch_channels(guild_id, channel_id, registered, channel_generation, updated_at)` | 채널별 등록과 제거/재등록 세대. 최소 tombstone을 남겨 예전 승인을 구분 |
| `watch_change_requests(guild_id, interaction_id, actor_id, body_hash, result, created_at)` | 관리 명령의 중복 변경 방지. 원문 대화·interaction 토큰 저장 금지 |
| `watch_change_events(...)` | 변경자·동작·대상·이전/이후 revision·확인/요청 참조·시각·영향 수의 감사 기록 |
| 기존 요청/확인·`audio_admissions` 추가 필드 | 서버가 확인한 진입 경로·주시 세대·승인 무효화 상태 |

복합키에는 guild를 포함한다. 설정과 큐 승인 조회를 위한 index를 설계한다. 다른 설정이 JSON 전체를 교체해도 주시 상태를 지울 수 없도록 기존 `guild_settings.settings_json`과 분리한다. 운영 로그7일·변경 감사90일을 유지하고, 현재 큐/요청이 참조하는 세대 tombstone은 감사 보존 만료만으로 삭제하지 않는다.

## 최초 이관과 재시작

1. 기존 제한 설정에서 guild와 prefix 목록을 읽되 실제 Discord guild/channel 연결을 검증한 후 서버별 초기값을 한 번만 저장한다. 최초 후보 전환 때 기존 `일반`, `discord-bot-test` 선택과 켜짐을 이어가는 것이 목표다. 조회 실패·잘못된 채널·상한 초과를 조용히 버리거나 다른 서버에 넣지 않는다. 이관 미완료를 진단하고 접두어만 차단한다.
2. `seed_applied`와 초기 행을 한 트랜잭션으로 저장한다. 이관 재시도·다중 기동에도 중복이 생기지 않는다. `seed_applied=false`인 동안 목록/점검만 허용하고 추가/제거/켜기/끄기는 `초기 설정 이관 필요`로 거절한다. 운영자가 제한 초기값·접근 실패를 수정한 뒤 지정 LXC에서 이관을 재시도하며, 이관 완료 전 사용자 변경과 자동 이관이 서로 덮어쓰지 못하게 한다. 이관 완료 후 DB가 기준이며, 새 candidate나 제한 파일의 옛 값으로 DB를 덮어쓰지 않는다.
3. 빈 등록 목록은 유효한 영속 상태다. 마지막 제거는 `enabled=false`와 함께 저장한다. 나중에 하나를 추가해도 자동으로 켜지지 않는다. `켜기`는 등록≥1·정상 채널≥1·운영자 허용/본문 접근 준비를 모두 확인한다.
4. 1.0.3 loader는 운영자 기능 허용과 DB 활성 상태를 분리한다. 기존 `prefix.enabled=true`이면 파일의 채널 목록이 항상 비어 있지 않아야 한다는 제약을 그대로 유지해 동적 빈 상태를 막지 않는다. 기존 파일 목록은 이관용이며 공통 text allowlist의 자동 확장에 사용하지 않는다.

## 기존 재생 승인 출처 이관

기존 `audio_admissions`에는 진입 경로/주시 세대가 없다. request ID를 메시지 요청 원장·명령 기록과 결합하여 출처를 입증한다. 현재 주시 채널에 속했다는 사실이나 ID 문자열 모양만으로 prefix/슬래시/멘션이라고 추측하지 않는다. 원장에 결합되는 prefix 승인은 초기 등록/권한 검증이 성공한 채널의 새 세대로 옮긴다. 다른 출처도 저장된 증거로 입증된 경우에만 승계한다.

입증 불가·승인 행 누락은 `legacy_unknown`과 새 승인 필요 상태로 보존하고 자동 시작 대상에서 제외한다. 곡/큐 순서는 유지하며 새 유효 DJ 요청으로 재승인한다. 이 영향은 배포 전 preview와 인수에 포함한다. 이관을 온라인 hot reload로 실행하지 않고 후보 전환의 정지/백업/재시작 경계를 사용하며, 재시작 후 자동 음성 재생은 하지 않는다.

## 원자적 변경과 고장

검증된 관리자·기대 revision·동작·대상으로 트랜잭션을 열어 중복 요청 확인 → 기대 revision 검사 → 설정 변경 → 관련 요청/확인/승인 무효화 → revision/세대 갱신 → 감사/결과 기록을 커밋한다. 네트워크·Jev·미디어 준비 동안 DB 쓰기 잠금을 유지하지 않는다. 부하 제한과 최신 권한 조회는 트랜잭션 밖에서 수행하되 커밋 직전 관리자 검증 결과의 짧은 유효기한을 검사한다.

커밋 전 실패는 변경0, 커밋 후 응답 유실은 변경을 재실행하지 않는다. 메모리 캐시 갱신 실패 시 오래된 목록으로 계속 접수하지 않고 DB 재적재 전 해당 서버의 prefix를 차단한다. 처리 경계의 최신 DB 검사는 캐시 알림의 성공 여부에 의존하지 않는다. 재시작 시 pending 확인/요청을 무효화하되 설정·감사·중복 식별 기록은 유지한다.

| ID | 필수 시험 |
| --- | --- |
| W-05 | 기존 두 채널 최초1회 이관·재시작/후보 변경 유지·수동 빈 목록/꺼짐 보존·기존 SQL checksum 유지 |
| W-06 | 두 관리자 동시 변경·revision 충돌·확인 중 변경·no-op·중복 interaction 효과1회 |
| W-07 | 커밋 전/후 crash·응답 유실·DB 잠김/손상·캐시 적재 실패·이관 중 재시작/변경 차단의 상태 일관성 |
| W-08 | guild 격리·개수20 경계·삭제/재등록 세대·기존 승인 출처/legacy_unknown·다른 settings 변경과 독립·과거 요청/승인 재사용0 |
