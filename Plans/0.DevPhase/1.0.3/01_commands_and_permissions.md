# 1.0.3 Phase 1 — 주시 명령과 관리자 권한

- 상태: **IN_PROGRESS — 개발 봇 적용·자동 회귀·사용자 부분 인수 통과, 전체 W 인수 미완료**
- 선행: [버전 계약](README.md), [결정0007](../../../docs/decisions/0007-watch-channel-management.md)
- 담당: DiscordBotLXC의 명령 어댑터·관리자 권한 서비스. 외부 판단은 필요하지 않다.

## 작업

1. `/주시` 그룹의 `추가`, `제거`, `목록`, `켜기`, `끄기`, `점검`을 길드 전용으로 정의한다. 명령 설명은 “`!!창근아` 반응 채널 관리”로 통일하고, 모든 응답을 interaction의 비공개 응답으로 보낸다. 일반 메시지에 ephemeral 기능이 있다고 표시하지 않는다. 초기 이관 실패 중에는 목록/점검만 제공하고 변경은 명시 오류로 거절한다. 이관 실패 복구는 Phase 2의 제한 설정 점검/이관 재시도 절차를 따른다.
2. 명령 기본 노출 권한을 서버 관리로 제한하고, 실제 실행 시 서버 소유자/최신 Manage Guild를 다시 확인한다. DJ만 가진 사용자, 다른 서버의 관리자, 역할 캐시가 불확실한 사용자에게 변경을 허용하지 않는다. 확인 버튼·페이지·채널 선택에도 요청자·서버·만료·권한을 결합한다.
3. 관리 경로는 정적 명령 채널이나 주시 채널이 아닌 곳에서도 작동하되, 등록 guild의 접근 가능한 일반 텍스트 채널에서 이 여섯 동작만 허용한다. 기존 `fresh_actor`의 채널 검사를 전역 해제하지 않는다. 음악 동작과 DJ 예외를 얻는 관리용 ActionPlan을 만들지 않는다.
4. `추가`·`점검`의 명시 `채널`은 Discord 채널 선택 옵션으로 일반 텍스트 채널만 받는다. **추가는 생략 시 현재 채널, 점검은 생략 시 등록 목록 전체**다. 추가에서는 사용자와 봇의 대상 채널 접근·봇의 보기/보내기/답장에 필요한 읽기 권한을 필수 검사한다. 점검은 관리자와 호출 위치의 권한을 검사한 뒤 대상 봇 권한 부족을 진단 결과로 표시하며, 부족하다는 이유로 점검 자체를 거절하지 않는다. 채널명으로 전체 서버를 추측하거나 카테고리를 확장하지 않는다.
5. `제거`의 `채널`은 저장된 등록 목록 자동완성을 사용하고, 저장된 ID 또는 정확한 채널 멘션을 검증한다. 삭제되거나 봇이 접근할 수 없는 등록 항목도 관리자가 제거할 수 있어야 한다. 임의 이름 문자열·다른 guild의 항목은 거절한다. UI 표시는 `#이름`, 이름 확인 불가 시 `삭제됨/접근 불가`와 구별 가능한 최소 식별 표시다.
6. 추가/켜기는 즉시 변경한다. 제거/끄기는 변경 전 영향과 60초 확인을 제공한다. 중복 추가·없는 항목 제거·같은 활성값 설정은 no-op이며 설정 버전을 올리거나 진행 요청을 취소하지 않는다. 확인 중 다른 설정 변경이 있으면 새 현황으로 다시 확인하고 예전 확인을 자동 적용하지 않는다. 표시한 요청/곡 수는 현재 예상치이며 확인 때까지 새로 접수된 같은 범위도 포함한다. 완료 응답에 실제 취소/승인 무효화 수를 제공한다.

주시 설정 동작은 별도 관리 서비스에서 검증·트랜잭션 처리한다. 기존 `SETTINGS_UPDATE` JSON 전체 교체나 음악 ActionPlan의 일반 인자 통과로 처리하지 않는다. 여섯 관리 명령은 Jev 장애·예산 소진에도 사용할 수 있어야 한다.

## 산출물과 시험

| ID | 필수 시험 |
| --- | --- |
| W-01 | 여섯 명령 등록·채널 생략/선택·중복 no-op·길드 전용·개인 응답·Jev0회 |
| W-02 | 소유자/Manage Guild 허용; DJ 단독/nonadmin/다른 guild/권한 조회 실패 거절; 확인 전 관리자 해임 |
| W-03 | 미주시·공통 목록 밖 채널에서 관리 복구; 같은 위치의 일반 슬래시·멘션은 기존 정책 유지 |
| W-04 | 일반 텍스트 선택·동일 이름 ID 구분·DM/스레드/포럼/공지/음성/다른 guild 거절; 삭제된 등록 항목 제거 |

실제 명령 표시와 서버 측 권한 검사를 각각 검증한다. 테스트 통과 전 명령을 운영 runbook의 사용 가능한 기능으로 옮기지 않는다. 다음: [Phase 2](02_storage_and_migration.md).

## 2026-09-28 구현 기록

사용자 구현 요청으로 소스/자동 회귀와 실제 개발 배포를 완료했다. 목록·점검·끄기·켜기/접두어 동작을 사용자가 정상으로 확인했다. [지정 LXC 증거](../../../evidence/public/watch-channels-20260928.md)에 실제 통과 범위와 남은 W 인수를 기록한다. 이 단계의 모든 필수 실제 시험이 완료됐다는 뜻은 아니다.
