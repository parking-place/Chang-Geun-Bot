# 1.0.3 — `!!창근아` 주시 채널 관리 명령

- 작성일: 2026-09-28
- 상태: **IN_PROGRESS — 개발 봇 적용·자동 회귀·관리 동작 사용자 부분 인수 통과, 전체 W 인수 미완료**
- 목표: Discord 안에서 창근이가 `!!창근아`에 반응할 채팅 채널을 추가·제거하고, 반응을 켜거나 끄고, 설정과 문제를 확인한다.
- 선행: [1.0.2 접두어 입력](../1.0.2/README.md), 공통 권한·실행기·메시지 원장. 이전 버전의 미완료 인수는 유지한다.
- 범위 결정: [0007 — 주시 채널 관리](../../../docs/decisions/0007-watch-channel-management.md). 자연어 판단은 계속 [Jev API Only](../INFERENCE_PROFILES.md)다.

## 사용자 명령 계약

아래 여섯 명령을 **1.0.3 개발 봇에 구현·적용**했다. [실행 증거](../../../evidence/public/watch-channels-20260928.md)의 부분 인수와 남은 전체 조건을 따른다. `/주시`는 길드 전용 슬래시 명령 그룹이며, 여섯 명령 모두 서버 소유자 또는 현재 `서버 관리(Manage Guild)` 권한 보유자만 사용할 수 있다. DJ 역할만으로 채널 설정을 바꾸지 못한다. 응답은 요청자에게만 보이며 Jev 호출은 0회다.

| 구현 명령 | 동작 | 주요 응답/조건 |
| --- | --- | --- |
| `/주시 추가 채널:#일반` | 일반 텍스트 채널 한 곳 등록; 채널 생략 시 현재 채널 | 이미 등록됐으면 변경 없이 안내. 서버 주시가 꺼져 있으면 목록만 저장하고 `/주시 켜기` 안내 |
| `/주시 제거 채널:#일반` | 등록한 채널 한 곳 해제; 채널 생략 시 현재 채널 | 저장 목록에서 선택하며 삭제된 채널도 제거 가능. 마지막 채널이면 주시도 꺼짐 |
| `/주시 목록` | 등록 채널과 반응 상태 조회 | 켜짐/꺼짐, 채널별 정상·권한 부족·삭제됨, 총 개수 표시 |
| `/주시 켜기` | 저장된 채널에서 접두어 반응 시작 | 등록 채널과 사용 가능한 채널이 각각 하나 이상 필요. 실제 가능 채널만 반응 |
| `/주시 끄기` | 해당 서버의 접두어 반응 중지; 채널 목록 보존 | 재생 중인 곡은 유지. 미완료 요청과 아직 시작하지 않은 관련 재생 승인은 무효화 |
| `/주시 점검 채널:#일반` | 선택한 채널의 등록·접근·본문 수신 준비 상태 진단 | 채널 생략 시 등록 목록 점검. 설정 변경·공개 시험 메시지·Jev 호출 없이 결과 표시 |

초기 사용 예는 `/주시 추가 채널:#일반` → `/주시 추가 채널:#discord-bot-test` → 필요하면 `/주시 켜기` → 각 채널에서 `!!창근아 목록 보여줘`다. `일반`, `discord-bot-test`는 사용자가 이전에 선택한 초기 채널이며 실제 ID를 공개 문서에 넣지 않는다.

켜기·추가는 작은 단일 변경으로 바로 처리한다. 제거·끄기는 영향 채널, 취소할 요청 수, 시작 전 승인 무효화 대상 수를 먼저 보여주고 요청자 전용 60초 확인을 받는다. 확인 버튼에서는 최신 관리자 권한과 설정 버전을 재검사한다. 화면의 영향 수는 현재 예상치이며 확인 때까지 접수된 같은 채널/서버 범위의 항목도 포함하고, 완료 응답에는 실제 수를 표시한다. 이미 꺼졌거나 없는 채널을 제거하는 요청은 확인 없이 “변경 없음”으로 끝낸다. 전체 초기화·한 번에 전체 교체는 이 버전 범위가 아니다.

## 주시의 의미와 권한 경계

“주시”는 선택한 채널의 **새 메시지 중 정확히 `!!창근아`로 시작하는 명령만 처리**한다는 뜻이다. 일반 대화 수집·과거 메시지 검색·음성 녹음·DM·스레드/포럼·공지·카테고리 전체 구독은 포함하지 않는다. 호출어와 한국어 해석 문법은 1.0.2 계약을 유지한다. 채널 설정을 자연어로 바꾸는 기능은 포함하지 않는다.

주시되지 않은 채널에서도 관리자가 `/주시 추가`를 사용해 처음 등록할 수 있어야 한다. 이를 위해 **여섯 관리 슬래시만** 등록된 서버의 접근 가능한 일반 텍스트 채널에서 별도 관리자 검사를 거쳐 실행한다. 일반 재생·목록·멘션 명령까지 허용하는 예외가 아니다. 초기 DB 이관이 실패한 경우에는 목록/점검만 열고 이관을 복구한 뒤 변경을 허용한다. Discord 명령 노출 설정과 앱 실행 권한 검사는 함께 적용한다.

기존 `commands.allowed_text_channel_ids`는 일반 슬래시·멘션 경로의 기준으로 유지한다. 1.0.3 주시 목록은 별도 prefix 정책으로 관리한다. 주시 추가가 공통 텍스트 허용 목록·DJ 역할·음성채널 권한을 수정하지 않는다. 신규 주시 채널에서도 prefix 요청은 같은 공통 실행기에 도달하지만, 서버가 기록한 요청 출처와 최신 주시 권한을 검증한 후에만 해당 채널을 인정한다. 모델이나 사용자가 전달한 `origin` 문자열만으로 이 예외를 얻을 수 없다.

## 영속 상태와 적용

SQLite의 서버별 주시 설정을 실행 기준으로 삼는다. 기존 제한 설정은 최초 한 번 초기값으로 이관하고, 이후에는 명령으로 저장한 상태를 재시작/후보 변경 후에도 유지한다. 의도적으로 빈 목록이나 꺼짐을 저장한 상태를 예전 파일 값으로 되살리지 않는다. 기존 재생 승인의 출처는 요청 원장으로 입증된 것만 이관하고, 입증할 수 없으면 큐를 보존한 채 새 DJ 승인을 요구한다. `guild_settings.settings_json` 전체 교체와 충돌하지 않는 전용 테이블을 사용한다.

배포 설정의 `commands.prefix.enabled`는 1.0.3에서 운영자의 기능 허용 스위치로 정의하고, DB의 서버별 켜짐/꺼짐과 구분한다. 운영자가 기능을 막았거나 Gateway 본문 접근이 준비되지 않았으면 `/주시 켜기`는 이를 우회하지 못한다. 정상 준비 상태에서 채널 추가·제거·서버 켜기·끄기는 봇 재시작 없이 적용한다. `/주시 켜기`로 Developer Portal 설정을 변경하지 않는다.

서버당 등록 상한은 초기 설계값 20개, 목록 표시는 페이지당 10개다. 채널 이름 변경은 ID 기반 등록을 유지한다. 삭제·권한 상실은 해당 채널만 차단하고 다른 정상 채널은 계속 반응한다. 권한이 돌아오면 최신 검증 뒤 새 메시지를 받을 수 있지만, 차단 전에 무효화한 요청이나 승인을 재생하지 않는다.

## 제거·끄기와 진행 중인 작업

설정 버전 검사, 설정 변경, 관련 미완료 요청/확인과 시작 전 재생 승인 무효화, 감사 기록을 하나의 DB 트랜잭션으로 처리한다. 이후 메모리의 추론·미디어 준비 작업도 취소한다. 취소에 늦은 결과가 도착하더라도 실행 직전 DB 상태 검사에서 거절한다. 설정 revision은 관리자 변경 충돌에 사용하고 요청/승인 유효성은 해당 채널·활성 세대로 검사한다. 다른 채널 추가처럼 무관한 변경은 진행 요청이나 이미 승인된 큐 항목을 무효화하지 않는다.

이미 재생을 시작한 현재 곡과 같은 스트림의 일시정지/계속은 유지한다. 아직 시작하지 않은 해당 prefix 출처 큐 항목은 곡·순서를 보존하되 `승인 만료`로 표시하고 자동 시작 대상에서 제외한다. 전부 만료되면 재생은 대기 상태가 되며 미디어 오류 횟수에는 합산하지 않는다. 다른 채널·슬래시·멘션 출처 항목은 유지한다. 반복 재생은 새 시작이므로 만료된 승인으로 다시 시작하지 않는다. 재등록/켜기로 예전 승인을 살리지 않으며 유효한 채널의 새 DJ 요청으로 재승인한다.

제거/끄기 확인 화면과 완료 응답에 위 영향을 평문으로 알린다. 음악을 즉시 멈추려면 기존 명령 채널의 `/정지`를 사용한다. 설정 변경을 이유로 저장 플레이리스트·곡을 삭제하지 않는다.
