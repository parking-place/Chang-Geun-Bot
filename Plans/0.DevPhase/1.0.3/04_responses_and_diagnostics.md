## 응답 문구와 정보

아래는 구현 목표 문구다. 채널 이름은 멘션을 발생시키지 않게 표시하고 실제 성공/실패 상태로 렌더링한다.

| 상황 | 응답 예 |
| --- | --- |
| 켜진 서버에 추가 성공 | “이제 #일반에서 `!!창근아`에 반응할게.” |
| 꺼진 서버에 추가 성공 | “#일반을 등록했어. 지금은 주시가 꺼져 있어. `/주시 켜기`로 시작해줘.” |
| 제거 확인 | “#일반에서는 더 이상 반응하지 않게 할까? 현재 기준 요청 1개를 취소하고 시작 전 2곡의 승인이 만료될 예정이야. 확인 전 추가된 이 채널의 요청/곡도 포함해. 지금 곡은 계속 재생해.” |
| 끄기 완료 | “주시를 껐어. 채널 목록은 보관했어. 현재곡은 계속 재생하고, 아직 시작하지 않은 주시 요청 곡은 새 재생 요청이 필요해.” |
| 마지막 채널 제거 | “등록된 채널이 없어 주시도 껐어. 채널을 추가한 뒤 `/주시 켜기`로 다시 시작해줘.” |
| 준비되지 않은 활성화 | “메시지 본문을 받을 준비가 안 되어 주시를 켜지 못했어. `/주시 점검`에서 원인을 확인해줘.” |

관리 요청은 즉시 비공개 접수 응답 후 검사/결과를 갱신한다. 영향 수는 확인 화면에서 예상치, 완료 응답에서 커밋 시점의 실제 수를 표시한다. 확인60초, 목록 페이지도 요청자/서버에 묶고 권한 회수 후 비활성화한다. 응답 유실·403·429로 설정 변경을 재실행하지 않는다. 성공 여부가 불명확하면 `/주시 목록`으로 저장 상태를 확인하도록 안내한다.

## 준비 상태 분리

서버 활성값, 운영자 허용, Gateway 본문 접근 준비, 채널별 상태를 구분한다. 채널 상태는 최소 `정상`, `삭제/찾을 수 없음`, `다른 유형`, `보기 부족`, `보내기 부족`, `답장 읽기 부족`, `조회 일시 실패`를 포함한다. 채널 하나의 실패를 모든 채널의 `prefix_ready=false`로 취급하지 않는다.

`/주시 점검`은 선택한 채널 또는 등록된 최대20개만 제한된 동시성으로 검사한다. 설정 등록·권한 변경·메시지 전송·과거 대화 조회·Jev 호출을 하지 않는다. Intent는 코드 설정, 마지막 Gateway 오류/연결 상태와 관측 가능한 본문 접근 증거를 표시하고, 봇이 Portal 토글을 직접 읽거나 고칠 수 있다고 주장하지 않는다. 확인할 수 없는 상태는 `확인 필요`로 남긴다. 4014 복구는 1.0.2의 통제된 비활성/재연결 계약을 유지한다.

채널 삭제/갱신·역할/권한 변경·재접속을 재검증 계기로 처리한다. 변경 감지와 각 접수/실행 경계의 권한 검사를 함께 사용한다. 임시 조회 실패 동안 해당 채널에서 새 요청은 받지 않고, 다른 정상 채널은 계속 처리한다. 점검 응답은 확인 시각을 포함해 오래된 캐시 결과를 현재 정상으로 표시하지 않는다.

## 한도와 보존

등록20개·페이지10개는 초기 제품 한도다. 관리 조회/변경/점검 전체는 서버 내 사용자당2초 간격, 점검은 서버당 동시에1개·최대20채널의 유한 작업으로 제한한다. 초과 입력은 짧은 개인 안내로 끝내며 Jev를 호출하지 않는다. 명령 입력의 유한 대기 기한과 Discord rate limit 대응을 LXC에서 검증한다.

명령 실행과 감사 기록에는 guild/channel/actor 식별자와 설정 diff가 필요하지만 공개 로그·공개 evidence에는 식별자를 제거한다. 관리 interaction 토큰·일반 대화 원문·키는 DB/감사/오류에 넣지 않는다. 관리 명령은 외부 추론으로 보내지 않는다. 기존 채널 외의 일반 대화는 수집하지 않는다.

## 2026-09-28 구현 기록

사용자 구현 요청으로 소스/자동 회귀와 실제 개발 배포를 완료했다. 목록·점검·끄기·켜기/접두어 동작을 사용자가 정상으로 확인했다. [지정 LXC 증거](../../../evidence/public/watch-channels-20260928.md)에 실제 통과 범위와 남은 W 인수를 기록한다. 이 단계의 모든 필수 실제 시험이 완료됐다는 뜻은 아니다.
