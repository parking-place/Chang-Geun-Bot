# 1.0.3 Phase 5 — 실제 채널 인수와 배포·복원

- 상태: **IN_PROGRESS — 개발 봇 적용·자동 회귀·사용자 부분 인수 통과, 전체 W 인수 미완료**
- 선행: Phase 1~4의 구현과 필수 지정 LXC 증거; 정식 승격 시 이전 버전 필수 게이트
- 실행 위치: DiscordBotLXC의 DB/권한/Discord/음성, DiscordBotLXC의 중계의 Jev 호출 원장 대조

## 실제 사용자 인수

주시 채널2개와 미주시 일반 텍스트1개, 서버 관리자/DJ만 보유/일반 사용자, 삭제 가능한 격리 시험 채널을 준비한다. 실제 IDs와 인증값은 제한 증거에만 둔다. 사용자 본인 조작·청취와 자동시험을 구분한다.

1. 미주시·공통 명령 목록 밖 채널에서 관리자가 `/주시 추가`를 사용한다. 추가된 두 채널에서는 실제 봇 멘션 없이 `!!창근아 목록 보여줘`가 동작하고, 미주시 채널·DM·스레드·일반 대화에서는 접두어 해석 호출0임을 원장과 대조한다.
2. DJ 단독/일반 사용자의 관리 명령과 타인의 확인 버튼을 거절한다. 관리자 해임·확인 중 설정 변경·두 관리자 동시 변경에서도 권한 우회/중복 변경0을 확인한다. 관리6명령의 Jev dispatch는0이어야 한다.
3. 요청 처리/확인/미디어 준비 중 채널 제거와 전체 끄기를 실행한다. 새 접수·늦은 결과가 효과를 내지 않고, 해당 prefix의 시작 전 큐 항목만 승인 만료로 보존되는지 확인한다. 현재곡의 실제 청취와 pause/resume, 다른 출처 항목의 자동 다음곡, 전부 만료됐을 때 대기를 각각 확인한다.
4. 마지막 채널을 제거하고 봇을 재시작한다. 빈 목록/꺼짐을 유지하며 미주시 채널에서 관리 명령으로 복구할 수 있어야 한다. 다시 등록·켜기로 과거 메시지/확인/만료 승인이 재실행되지 않아야 한다.
5. 채널 이름 변경·삭제·권한 회수·복구·재접속에서 채널별 상태와 점검 결과를 대조한다. 한 채널이 실패해도 다른 정상 채널의 새 접두어 요청이 작동해야 한다. Jev 장애 중에도 `/주시`는 동작한다.

## 자동 회귀·부하 목표

W-01~20 전체와 영향받는 C-01~16/18, Y-10~16, T/N/B/O 권한·DB·복원 회귀를 동일 고정 후보에 연결한다. 관리 명령의 추론0회 때문에 새 한국어200문장 평가를 관리 기능 시험으로 대체하거나 점수에 합산하지 않는다. NLP/후보/실행 권한에 영향을 준 변경은 해당 한국어 회귀와 이전 버전의 독립 품질 게이트를 그대로 재검증한다.

합성 동시성 시험은 두 관리자·두 prefix 채널에서 설정 변경과 실행 커밋의 순서를 바꿔 최소100회 반복한다. 무단 변경·중복 효과·취소 후 시작·다른 출처 큐 손실은0건이어야 한다. 실제 Discord에서 100회 설정 메시지를 무작정 전송하지 않고 모의 경합 시험과 실제 핵심 인수를 구분한다.

등록20개·점검1개 동시 작업·재생 중 정상 명령을 함께 검사한다. 비공개 접수 표시1초, 변경 커밋 후 새 정책 반영1초는 초기 계측 목표이며 완료 성적이 아니다. 이전1.0.1/1.0.2의 미통과 실제8시간·품질·재생 안정성 게이트를 승계하고, 라우팅/미디어 취소에 영향이 있는 새 후보로 필요한 장시간 시험을 다시 수행한다. 과거 후보 PASS/FAIL을 새 후보의 성적으로 옮기지 않는다.

## 배포와 rollback

이관 전 소스/wheel/설정 hash·스키마·주시 snapshot·일관 DB 백업·이전 바이너리/이전 DB 묶음을 보관한다. 별도 candidate/run에서 migration·초기 이관·승인 출처 backfill/legacy_unknown·꺼짐/관리 복구를 검증하고 실제 등록 채널을 확대한다. 현재 사용자 선택은 첫 이관에만 사용한다. 계획 문서만으로 봇을 재시작하거나 현재 채널을 바꾸지 않는다.

현 DB loader는 모르는 migration 버전을 거절한다. 따라서 1.0.3 새 DB를 1.0.2 바이너리에 직접 연결하거나 기존 SQL을 되돌려 checksum을 맞추지 않는다. 롤백 도구는 검증된 이전 바이너리/이전 DB를 묶어 복귀시키고, 새 DB·감사·설정 snapshot은 보존한다. 신버전에서 바꾼 설정 중 복귀 대상에 포함되지 않는 범위와 시점을 운영자에게 명시한다.

이전 DB로 돌아가며 새 메시지 중복 기록이 사라져 과거 요청이 재실행되지 않도록 재기동 접수 cutoff·원장/tombstone·확인 무효화와 허용된 호환 이관 절차를 검증한다. gateway 원장·남은 호출 예산은 초기화하지 않는다. rollback은 자동 음성 재접속/재생을 하지 않는다. 실제 실행법은 구현·LXC 증거가 생긴 후 운영 runbook에 추가한다.

## 완료 판정

산출물은 명령 도움말·관리자 안내, source/candidate/config/schema/settings revision, W 및 영향 회귀 결과, 실제 사용자 인수, 초기 이관/복원/rollback 보고서다. 미실행/실패를 남긴 채 VERIFIED/DONE·제품 VERSION·태그를 만들지 않는다. 현재는 개발 후보 적용·자동 회귀·사용자 부분 인수를 기록한 IN_PROGRESS다. 전체 W 인수와 앞선 미완료 게이트는 유지한다.

## 2026-09-28 구현 기록

사용자 구현 요청으로 소스/자동 회귀와 실제 개발 배포를 완료했다. 목록·점검·끄기·켜기/접두어 동작을 사용자가 정상으로 확인했다. [지정 LXC 증거](../../../evidence/public/watch-channels-20260928.md)에 실제 통과 범위와 남은 W 인수를 기록한다. 이 단계의 모든 필수 실제 시험이 완료됐다는 뜻은 아니다.
