## 목표

- 0.1.0을 도메인/저장 기반 완료로만 판정하고 실제 봇 완성과 구분한다.
- 0.2.0에서 재사용할 카탈로그·목록·권한·확인 fixture와 오류 계약을 고정한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬에서는 아래 코드·문서 작성과 읽기 검토만 한다. 설치·lint·타입검사·시험·build는 LXC에서 수행한다.

- 격리된 테스트 guild·actor·DJ·동명이인 목록·중복 영상·다른 업로드·빈 목록 fixture를 작성한다.
- 저장 목록→대기열 복사 후 원본/사본 독립, current/queue 분리, 현재곡 포함 저장 계약의 선행 시험을 작성한다.
- 재시작 시 미완료 확인 무효화·요청 완료 결과 보존과 settings/playlist 복원 절차를 작성한다.
- 저장소·policy·실행기를 FakeDiscordGateway/MockJevAdapter/FakeAudioSource와 교체할 인터페이스를 검토한다.
- 0.2.0 전용 fixture 카탈로그를 계획하고 외부 메타데이터/실제 음성은 아직 비활성이라는 기능 표기를 작성한다.

## 산출물

- 도메인·저장·권한·중복 시험 소스와 fixture.
- T-01·02·03·05·06·07·08·09·10·20 관련 선행/최종 구분표.
- 0.1.0 검증 기록과 0.2.0 입력 계약·미구현 목록.

## LXC 검증

- DiscordBotLXC에서 해당 버전 단위·mock·저장 통합시험·lint·타입검사를 수행한다.
- 시험 DB만 사용하는지 확인하고 실패 케이스에서 실제 운영 데이터나 Discord 음성에 접근하지 않는다.
- 프로세스 재시작·확인 만료·동시 편집을 포함한 증거를 공통 템플릿으로 기록한다.

## 통과 기준

- 필수 도메인/저장 시험이 모두 통과하고 기능 범위별 미구현·미검증 항목이 명시돼 있다.
- 실제 Discord/음성·hosted Jev API 시험의 대체물로 mock PASS를 사용하지 않는다. 프로필을 바꿔도 도메인 권한·확인·ID·중복 정책은 같다.
- 0.2.0 담당 단계가 도메인 타입과 오류 코드를 재해석 없이 사용할 수 있다.

## 중단·후속 처리

- 저장·정책·중복·격리 실패가 남으면 0.1.0 승인과 0.2.0 변경 연결을 보류한다.
- 시험 도구·명령은 실제 프로젝트 구성 후 확정한다. 존재하지 않는 스크립트의 실행 성공을 문서에 만들지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
