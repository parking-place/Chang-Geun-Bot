# 1.0.1 Phase 3 — 명령·대기열·음성 재생 연결

- 상태: **IN_PROGRESS — 개발 후보·부분 LXC 검증; 전체 인수 전**
- 선행: [Phase 2](02_youtube_resolver.md)의 소스 해석/취소 경계.
- 구현 위치: `discord_adapter/client.py`·`runtime.py`, `application/executor.py`, 재생 상태와 필요 DB migration. gateway가 미디어를 읽거나 실행하지 않는다.

## 작업

1. `/재생`의 곡(영상 URL 포함)·검색어·목록 중 하나만 받는 계약과 상호배타 검증을 추가한다. 공식 검색의 최대5개 결과에서 사용자가 선택한 video ID를 요청자 전용60초 선택 토큰으로 연결한다. 선택 뒤 최신 DJ·채널·큐 버전을 다시 검사한다. 조회만 한 결과는 재생하지 않는다.
2. `approved_audio` 전용 하드코딩과 client의 동기 resolve 사전검사를 공통 재생 가능 판정으로 바꾼다. 이 판정은 네트워크 재생 성공을 보장하지 않으며 실제 획득은 해당 항목의 재생 차례 직전에 runtime에서 수행한다. 목록 전체의 임시 미디어 주소를 미리 추출하지 않는다. 승인 음원과 YouTube가 섞인 목록도 항목별로 판정한다. 미리 확인된 재생 불가 항목이 있으면 목록 전체를 자동으로 일부 실행하지 않고 제외 항목/이유를 보여준 뒤 요청자가 확인한 재생 가능 부분만 원자적으로 추가한다. 취소하면 큐 변경0이다.
3. 신규 URL은 공식 메타데이터로 검증해 안정 참조로 등록하고 공통 ActionPlan/executor에서 원자적으로 큐에 반영한다. `source_type=youtube` 기존 DB·내보내기/가져오기를 유지하며 승인 음원으로 위장 변환하지 않는다. 재생·큐·저장 목록의 변경 범위와 중복 정책을 보존한다.
4. 큐 항목별 origin request·요청자/승인자·admission 시점과 재생 작업 소유권을 기록하도록 migration/계약을 추가한다. 목록에서 파생된 항목과 승인된 제안에도 소유권을 연결한다. RESOLVING→PLAYING 전에 current entry ID·작업 소유권·세대·취소·음성 연결·권한을 재검사한다. 다른 곡을 큐 끝에 추가하는 변화는 현재 작업을 무효화하지 않는다. resolver 결과는 승인된 재생 작업에만 결합하며 오래된 callback이 다음 항목을 건드릴 수 없다.
   자동 다음곡/반복도 해당 entry의 유효한 승인 주체·guild/채널 정책을 검사한다. 한 DJ의 권한 상실은 그 소유 작업에만 적용하고 타인의 큐를 지우지 않는다. 자동 진행은 새로운 사용자 조작과 구분해 원 요청자의 음성채널 체류를 매곡 요구하지 않으며, 사용자 제어 요청에는 기존 동일 음성채널 정책을 적용한다.
5. 일시정지는 같은 stream을 유지하고 계속은 재개한다. 정지 뒤 계속은 기존 계약대로 현재 항목을 처음부터 다시 해석/재생한다. 수동 스킵·반복·퇴장은 기존 상태기계와 실패 횟수 의미를 유지한다. 임의 위치 탐색은 후속 범위다.
6. 일반 검색→선택→재생, 저장 목록→재생, Jev가 만든 기존 재생계획 모두 공통 실행기를 사용한다. 새 자연어 문법/호출어는 [1.0.2](../1.0.2/README.md)에서 확장한다.

## LXC 시험과 통과

- **Y-09:** 실제 링크·공식 검색 선택·기존 저장 목록 각각에서 매핑 없는 YouTube 재생; 선택하지 않은 검색결과 실행0, 구조화 명령 Jev호출0.
- **Y-10:** 승인 음원/YouTube 혼합 큐의 순서·entry ID·중복·repeat·skip·pause/resume·stop/leave; 저장 목록 불변.
- **Y-11:** 비DJ·다른 음성채널·DJ 해임·만료/타인 버튼·큐 경쟁에서 무단 실행0. 일반 멤버 요청은 기존 제안 정책만 적용.
- **Y-12:** 재생목록 URL 가져오기 확인, 대량 추가 확인, 부분/삭제 영상의 제외 미리보기·확인 부분추가/취소0변경, 기존 export/reimport 순서·참조 보존. 검색/추출로 목록 전체가 몰래 추가되지 않음.

유효 URL·검색 선택을 실제로 들은 증거와 사용자 명령 응답 결과를 각각 남긴다. 승인 시험음 청취만으로 YouTube 재생을 판정하지 않는다. 다음: [Phase 4](04_failure_security_and_recovery.md).

## 2026-09-28 개발 기록

[고정 후보와 부분 실행 증거](../../../evidence/public/youtube-prefix-20260928.md)를 따른다. 단위/mock·실제 API·첫 PCM·Discord 사용자 청취를 구분하며 아래 필수 인수 조건은 유지한다. 부분 성공만으로 이 단계나 전체 버전을 VERIFIED/DONE으로 표시하지 않는다.

주소 입력은 `https://youtube.com/watch?v=...`와 `youtube.com/watch?v=...`, `www.youtube.com/...`, `m.youtube.com/...`, `youtu.be/...`를 같은 안정 video ID로 처리한다. 본문에서 ID의 대소문자를 보존하고 잘못된 host·HTTP·인증/port·복수 URL은 임의 영상이나 이전 목록으로 대체하지 않는다.
