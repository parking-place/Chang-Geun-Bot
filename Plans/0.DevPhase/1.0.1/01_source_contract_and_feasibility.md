# 1.0.1 Phase 1 — 소스 계약과 직접 재생 타당성

- 상태: **IN_PROGRESS — 개발 후보·부분 LXC 검증; 전체 인수 전**
- 선행: [버전 범위](README.md)와 [결정0006](../../../docs/decisions/0006-youtube-and-prefix-roadmap.md); 1.0.0 재생 기준선은 별도 인수.
- 검증: DiscordBotLXC, 기존 서비스와 분리한 시험 경로. Jev gateway는 소스 추출에 사용하지 않는다.

## 작업과 산출물

1. 공개 유한 VOD/Shorts, 검색 선택, 기존 저장 목록의 `youtube` 참조를 범위로 고정한다. 인증·연령/지역/결제 제한·DRM·라이브는 오류 종류와 안내를 정의한다. 개별 승인 음원 매핑을 필수로 요구하지 않는다.
2. 공식 메타데이터 API와 실제 오디오 획득 어댑터를 분리한다. 직접 추출 후보로 yt-dlp를 조사하고 대체 중계 서비스를 검토할 경우 운영 주체·데이터 흐름·의존성·사용 조건을 같은 기준으로 비교한다. 단순 iframe 링크를 Discord 음성 재생 완료로 처리하지 않는다.
3. 선택 방식에 적용되는 플랫폼 조건과 콘텐츠 전송 권한의 확인 근거·확인일·미확정 항목을 남긴다. 개발자 정책은 승인 없는 저장/캐시와 오디오 분리·백그라운드 재생 등을 제한하므로 “공개 영상”, “API 키 보유”, “재생 probe 성공”만으로 운영 허용을 확정하지 않는다. 사용자에게 재생 목표를 승인 음원 범위로 바꿔 승인하도록 재질문하지 않고 미해결 기술/운영 항목을 기록한다.
4. `PlayableSource`의 안정 참조(source type/video ID)·만료·취소·cleanup·일시 오류/영구 오류 계약을 설계한다. 실제 URL과 인증 헤더는 일시적 런타임 데이터로만 둔다. 모델 출력이 소스 주소나 실행 인자를 지정할 수 없다.
5. 영상 길이30분·항목 준비 총25초(대기/추가시도 포함)·누적resolve15초/startup10초·동시1/대기4·추가시도1회·연속실패3개 한도와 키/프로세스 경계를 ADR/설정 명세에 고정한다. 수치는 출시 전 실측하는 초기 정책값이다.

## LXC 검증과 시험

- **Y-01:** 승인 음원 매핑이 없는 시험 VOD의 메타데이터→실제 오디오 획득→Discord DAVE 청취를 분리 기록한다. 시험 항목의 사용 근거를 먼저 기록하고 첫 청취는 시험 채널에서 수행한다.
- **Y-02:** 공식 Data API 정보와 실제 재생 가능 상태를 구분한다. 지원하지 않는 소스·제한 영상은 명확한 실패이고 링크 저장 여부와 재생 여부가 혼동되지 않는다.
- **Y-03:** yt-dlp 채택 시 후보의 Python·FFmpeg/ffprobe·JS runtime·EJS 구성/정확 버전·해시·라이선스·소스 출처를 고정한다. 모델 패키지·브라우저 쿠키·사용자 extractor plugin 없이 격리 환경에서 준비한다.

실제 설치·import·probe는 LXC에서만 수행한다. 실패·제한 영상은 별도 기록하고 임의로 자격정보를 추가하거나 요청을 반복해 통과시키지 않는다.

## 통과와 후속

소스/오류/한도 계약과 adapter 선택 이유, 원격 기술 증거, 플랫폼 조건의 적용 판정이 있어야 이 단계를 통과한다. 기술·운영 판정이 다르면 각각 상태를 기록한다. 미확정 사항이 있어도 독립적인 resolver/상태기계 초안은 작성할 수 있지만 실제 전송 허용을 추정하거나 출시 완료를 선언하지 않는다.

공식 근거 확인일: 2026-09-28. [YouTube Data API](https://developers.google.com/youtube/v3/getting-started), [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [yt-dlp README](https://github.com/yt-dlp/yt-dlp#readme). 도구가 YouTube를 지원한다는 사실은 플랫폼 허용을 증명하지 않는다.
