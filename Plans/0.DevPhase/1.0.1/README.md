## 사용자가 얻게 될 기능

미리 승인 음원 파일을 등록하지 않아도 공개 YouTube 영상 URL, 검색으로 선택한 영상, 저장 목록의 YouTube 항목을 Discord 음성채널에서 들을 수 있게 한다. 재생 중인 큐에 추가하고 일시정지·계속·스킵·정지·반복·퇴장을 기존 명령으로 제어한다. 영상 화면 송출은 이 버전 범위가 아니다.

| 입력/상황 | 목표 동작 |
| --- | --- |
| `/재생 곡:<영상 URL>` | 해당 영상 한 곡을 선택하고 공통 권한·음성 정책에 따라 재생/큐 추가 |
| `/재생 검색어:<한국어 제목>` | 공식 메타데이터 검색 최대5개 → 사용자가 선택한 영상만 재생; 첫 결과 자동선택 없음 |
| `/재생 목록:<저장 목록>` | 저장된 YouTube 항목과 승인 음원을 순서대로 재생; 저장 목록과 큐는 분리 |
| watch URL에 `v`와 `list`가 함께 있음 | 영상 한 곡만 처리; 재생목록 전체는 기존 가져오기/확인 흐름 사용 |
| 재생목록 전용 URL | 목록 가져오기·곡 수 미리보기로 안내; 한 곡 입력에서 전체 자동추출 금지 |
| 비공개·삭제·로그인/지역/연령 제한·유료·DRM·진행 중 라이브 | 사유를 안내하고 미재생; 접근 제한 우회 없이 종료 |

URL은 `youtube.com/watch`, `youtu.be`, `youtube.com/shorts`, 기존 지원 `embed` 형식을 영상ID로 정규화한다. Shorts도 유한 길이의 공개 영상이면 같은 경로로 처리한다. URL 시작 시각은 1.0.1에서 적용하지 않고 처음부터 재생한다고 안내한다. 실시간 방송·예정 프리미어는 제외하고 방송 종료 후 일반 VOD는 지원 조건에 따라 판정한다.

## 초기 설계 한도

다음은 실제 계측으로 확인할 계획값이다. 신규 설정 이름과 기본값은 Phase 1에서 계약화하고 Phase 5 manifest에 고정한다.

- 기본 기능 플래그 off, 준비된 후보에서 명시 활성화. 인증 쿠키·브라우저 세션·프록시 전환·사용자 플러그인 자동 로드 없음.
- 영상 길이 최대30분, 길이 미확정은 재생 전 거절. 가져온 긴 영상 링크는 보존할 수 있지만 재생 가능 상태는 따로 표시한다.
- 소스 해석 동시1개·대기최대4, 현재 항목이 재생 대상으로 승격되어 준비를 접수한 시점부터 대기·추가시도 포함 총25초, 누적 해석 최대15초·누적 첫 오디오 준비 최대10초. 단계마다 남은 총시간으로 절삭하며 재시도로 시계를 초기화하지 않는다. 아직 차례가 오지 않은 일반 음악 큐 대기는 이 준비 기한에 포함하지 않는다. 대기열 포화는 즉시 안내한다.
- 곡당 재해석/재접속 합산 추가1회 이내, 3곡 연속 실패 시 중단. 인증·정책·지원 불가 오류는 재시도하지 않는다. FFmpeg·HTTP·extractor의 숨은 재시도까지 합산한다.
- 일반 메타데이터와 안정 video ID만 DB/백업에 저장. 미디어 URL/헤더는 해당 재생 세대 메모리에서만 사용하고 정지·종료·만료 시 폐기한다.

이 미디어 시간 계약은 자연어 해석의 12초/4초 상한과 다르다. NL은 기한 내 자동 판단과 ActionPlan 생성, 즉시 실행 승인 또는 선택/확인 UI 제시까지 끝낸다. 사용자 선택/확인은 요청자 전용 최대60초 후속 토큰으로 받고 최신 권한·대상·취소 여부를 다시 검사한다. 이 대기는 원 추론 기한을 늘리지 않으며 추가 Jev 호출을 허용하지 않는다. 승인 후 미디어 작업을 별도 추적한다. 큐 변경은 원자적 버전 검사로 적용하고, 미디어 준비 완료 때는 현재 entry·작업 소유권·generation·권한을 다시 검사한다. 해석 중 무관한 큐 끝 추가만으로 현재곡을 취소하지 않는다. 1.0.1 슬래시 경로는 Jev 호출0회이며 1.0.2 자연어에서도 재시도를 이유로 Jev를 다시 호출하지 않는다.

## 완료 기준과 외부 조건

승인 음원 매핑이 없는 실제 공개 영상이 청취 가능하고 모든 재생 제어·취소·재시작·복원 시험을 통과해야 한다. 링크만 저장하거나 로컬 시험음을 재생한 결과로 완료 처리하지 않는다. 기능 Y-01~18, 영향받는 T/N/P/O/B, 신규 소스가 포함된 연속8시간 시험과 고정 후보 배포·롤백 증거를 요구한다.

Data API는 메타데이터, IFrame Player는 웹 내장 재생 API다. Discord로 영상 오디오를 보내는 별도 어댑터의 사용 조건을 대신 충족하지 않는다. 현행 YouTube 개발자 정책의 오디오 분리·백그라운드 재생 등 제한을 Phase 1에서 실제 채택 방식에 대조해 근거와 미해결 사항을 기록한다. 기술적으로 재생되는지와 운영 채택 가능한지는 별도 판정한다. 전송 방식이 미확정이면 계획·구현 초안을 계속할 수 있으나 출시 PASS는 만들지 않는다. [공식 Data API](https://developers.google.com/youtube/v3/getting-started), [IFrame Player](https://developers.google.com/youtube/iframe_api_reference), [개발자 정책](https://developers.google.com/youtube/terms/developer-policies)

## 2026-09-28 개발 기록

[고정 후보와 부분 실행 증거](../../../evidence/public/youtube-prefix-20260928.md)를 따른다. 단위/mock·실제 API·첫 PCM·Discord 사용자 청취를 구분하며 아래 필수 인수 조건은 유지한다. 부분 성공만으로 이 단계나 전체 버전을 VERIFIED/DONE으로 표시하지 않는다.

주소 입력은 `https://youtube.com/watch?v=...`와 `youtube.com/watch?v=...`, `www.youtube.com/...`, `m.youtube.com/...`, `youtu.be/...`를 같은 안정 video ID로 처리한다. 본문에서 ID의 대소문자를 보존하고 잘못된 host·HTTP·인증/port·복수 URL은 임의 영상이나 이전 목록으로 대체하지 않는다.
