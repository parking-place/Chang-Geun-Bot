## 목표

- DJ가 실제 Discord 구조화 명령으로 저장 목록을 관리한다.
- 곡 ID와 목록 항목 ID를 구분하며 지정한 항목·순서만 변경한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 작성·읽기 검토만 한다. 모든 설치·정적 검사·시험·build·Discord 실행은 LXC에서 한다.

- /목록 생성·보기·이름변경·복사·삭제와 설명 편집을 도메인 실행기로 연결한다. 활성 정규화 이름 중복은 거절한다.
- /곡 추가·제거·이동은 실제 playlist_entry ID로 실행한다. 동일 영상 기본 중복 거절, 명시 허용 시 새 항목 ID를 생성한다.
- 목록 복사 시 새 목록/항목 ID를 생성하고 원본 수정과 독립시킨다. 플레이리스트 불러오기를 원본 공유 참조로 설계하지 않는다.
- 전체 삭제·이름 충돌 덮어쓰기·대량 변경은 필요한 확인/미리보기 정책을 연결하고 삭제는 논리 삭제로 처리한다.
- 긴 목록은 페이지 처리하고 목록·항목 ID/수량·수정 시각·순서·운영자 정보가 확인 가능하도록 응답을 작성한다.

## 산출물

- 슬래시 목록/곡 편집 핸들러·조회 UI·복사 동작.
- 구조화 항목 선택·명시적 중복 허용 옵션과 확인 미리보기.
- 논리 삭제·삭제 이름 재사용/향후 복원 충돌 정책 문서.

## LXC 검증

- DiscordBotLXC의 실제 테스트 Discord에서 빈 목록 생성→재시작→3곡 추가→순서 이동→특정 항목 제거를 실행한다.
- 같은 정규화 이름 생성/저장, 같은 영상 중복 추가, 다른 업로드 추가, 명시적 중복 허용을 비교한다.
- 복사 후 원본/사본을 각각 수정하고 확인 없는 전체 삭제·권한없는 수정 시도에서 DB 불변을 검사한다.

## 통과 기준

- T-01·02·06이 실제 Discord/DB 증거와 함께 통과한다. 이름 충돌 시험은 T-10 선행 검증이며 대기열 저장 최종 시험은 0.4.0이다.
- 중복곡이 있는 목록에서 명시한 entry만 제거하고 남은 다른 entry는 유지한다.
- 논리 삭제와 복사가 원본 데이터·운영 보존 정책을 침해하지 않는다.

## 중단·후속 처리

- 순서/ID 오류·자동 덮어쓰기·확인 누락이면 해당 명령을 비활성하고 수정한다.
- 가져오기·내보내기·되돌리기·삭제 복원과 복사 충돌 강화는 0.7.0에서 완성한다. 재생 연동은 0.4.0이다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
