## 목표

- Jev 없이 구조화 목록 편집이 사용 가능한지 버전 범위에 맞게 인수한다.
- fixture 검증과 실제 외부/음성 검증의 경계를 명확히 남긴다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 작성·읽기 검토만 한다. 모든 설치·정적 검사·시험·build·Discord 실행은 LXC에서 한다.

- 도움말·설정·검색·목록 명령·컴포넌트의 지원/미구현 표를 최종 정리한다.
- T-01·02·03·05·06 시나리오를 실제 fixture DB와 Discord actor 조합으로 추적하는 시험 소스를 작성한다. T-10은 이름 충돌 선행 시험으로 구분한다.
- 호출되지 않은 일반 대화, 다른 봇·웹훅·DM·허용되지 않은 채널 메시지를 무시하는 필터를 작성한다.
- /부탁·멘션의 실제 자연어 실행, 외부 URL 등록, 입장·재생·대기열 제어는 다음 버전 의존으로 남기고 가짜 완료를 제거한다.
- 0.3.0 제공자/음성 어댑터가 기존 카탈로그·공통 실행기와 연결할 이벤트/상태 계약을 정리한다.

## 산출물

- 구조화 기능별 인수 체크와 테스트 fixture/소스.
- Discord 앱·명령 설정 및 안전한 기능 활성화 상태 문서.
- 0.2.0 실행 증거와 0.3.0 선행/미검증 항목 목록.

## LXC 검증

- DiscordBotLXC에서 현재 버전 lint·타입검사·단위/mock·DB 통합·실제 Discord 시험을 수행한다.
- 서버 재시작 후 목록/설정 보존과 미완료 확인 무효화를 확인하되 T-20 전체 재생 복원 PASS로 표시하지 않는다.
- 증거에 guild/user 식별자를 필요한 수준으로 최소화하고 토큰·접속 비밀값을 제거한다.

## 통과 기준

- 현재 지원 범위의 T-01·02·03·05·06과 이름 충돌 선행 시험이 통과하고 누락/실패가 없다. T-10 대기열 저장 최종 시험은 0.4.0에 남긴다.
- Jev API가 미연결인 상태와 게이트웨이/API 장애 중에도 동일 구조화 기능이 동작하고 실제 시험은 지정 LXC에서 실행됐다. 공급자 장애 주입은 추론 연동 후 회귀하며 현재 미구현 시험은 PASS로 세지 않는다.
- 외부 소스·DAVE·대기열·자연어 미완료가 버전 기록에 명시되어 있다.

## 중단·후속 처리

- 핵심 목록·권한·확인 실패 시 0.2.0 gate를 닫고 수정 후 관련 시험을 다시 수행한다.
- 다음 단계는 0.3.0 실제 메타데이터·허용 소스·DAVE·입장/퇴장이다. 0.2.0을 전체 음악봇 완성으로 표시하지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
