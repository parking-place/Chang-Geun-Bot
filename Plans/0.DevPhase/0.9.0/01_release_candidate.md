- 검증 호스트: `DiscordBotLXC`의 봇·별도 계정 중계
- 상태: **PLANNED — 필수 인수 전**
- 추론 계약: [프로필 선택·시험 실행](../INFERENCE_PROFILES.md), [개발 명세 v1.3](../../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md), 내부 API schema `1.2`.

## 목표

- 모든 출시 증거를 한 불변 후보와 재현 가능한 원격 환경에 묶는다.
- 개발 데이터와 최종 평가 데이터, 테스트와 운영 컨텍스트를 분리한다.

## 로컬 코드 작업

- 공통 후보 SHA·bot/gateway 및 provider별 잠금 파일·API schema `1.2`·provider/profile_id/config_hash·프롬프트/임계값·안전 정책을 기록한다. hosted는 어댑터/API 버전·요청/반환 모델·측정시각·고정 불가 한계를 기록한다.
- T-01~T-20, N-01~N-36, P-01~P-12, O-01~O-08, B-01~B-12와 명세 §19 체크리스트의 시험 추적표를 run별로 작성한다. 각 B 시험의 상세 기대 결과·담당 단계는 공통 시험 매트릭스를 따른다.
- 최종 한국어 평가 데이터·채점 규칙·fixture·seed·원본 snapshot을 개발 세트에서 분리해 고정하고 Jev API 고정 후보에 적용한다. Jev API prompt/threshold는 개발 세트에서 보정한 뒤 평가 전에 고정한다.
- 테스트 토큰·guild·음원·DB/큐·원장·service·복원·증거 경로를 운영 및 다른 시험 run과 분리한다. 설정 비교는 독립 snapshot 복사본에 순차 실행하고 같은 Discord/운영 DB 변경을 두 번 적용하지 않는다. hosted 송신 fixture는 합성/익명화하며 최소 후보만 포함한다.
- 목표·PASS·FAIL·미실행·미검증 상태를 구분하고 실패 제외 통계를 금지한다.

## 산출물

- Jev API 후보의 RC manifest·동일 SHA 검증표·알려진 제한·필수 미해결 목록. hosted endpoint/인증/모델·단가·한도·외부 보존 정책의 확인 근거와 시각을 포함하며 비밀값은 제외한다.
- 비밀값 없는 시험 환경 스냅샷과 시험 ID·명세 요구사항 추적표.
- 최종 평가·부하·복원 실행 계획과 비식별화된 증거 저장 구조.

## LXC 검증

- DiscordBotLXC의 봇·중계: Jev API 프로필을 명시 선택해 배포된 SHA·의존성·스키마·provider/profile_id/config_hash·모델 정보·프롬프트가 해당 manifest와 일치하는지 확인한다. 불일치·프로필 미선택은 호출 전에 거절한다.
- `DiscordBotLXC`: 테스트 DB·guild·토큰·허용 채널과 운영 접근 차단을 확인한다.
- `DiscordBotLXC의 중계`: Jev API 경로의 공통 gateway·TLS·내부 인증·영속 원장·단일 dispatch를 확인한다.
- OS·Python·FFmpeg·음성 의존성·LXC 자원·동일 노드의 공유 부하를 실측한다.
- 설치·lint·typecheck·빌드·시험 등 후보 실행 확인은 LXC에서만 수행한다.

## 통과 기준

- 원격 두 서비스와 이후 증거가 같은 후보 SHA에 연결된다.
- 외부 버전·정책·소스 권한·hosted 호출/비용 한도의 구현 시점 재검증 결과가 존재한다. runner가 요청 수×최대 단계 수·준비 호출을 산정하고 실행 한도를 확보한다. 한도 부족 시험을 일부만 실행해 전체 PASS로 처리하지 않는다.
- 미제공 환경값·비밀값은 추정으로 완료 표시하지 않는다.
- 테스트·복원이 운영 DB와 운영 음성에 영향을 주지 않는다.

## 중단·후속 처리

- 환경·후보 불일치나 필수 입력 미확정이면 해당 시험을 시작하지 않는다.
- 수정은 새 SHA 후보로 발급하고 영향받는 기존 증거를 다시 확보한다.
- 고정한 후보로 Phase 2~5를 수행하며 최초 계획 작성 자체는 PASS가 아니다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
