- 모든 필수 게이트의 충족 여부로 1.0.0 준비·차단을 명확히 판정한다.

## 로컬 코드 작업

- 명세 §19 체크리스트와 run별 T/N/P/O/B 전건·한국어·성능·부하·보안 증거의 링크를 연결한다. O-05~07의 백업·복원·롤백은 Jev API에서 이 단계에서 최종 확인한다.
- 같은 SHA와 Jev API의 의존성·provider/profile_id/config_hash·스키마·prompt/threshold·모델 정보 조합을 검토하는 최종 표를 작성한다.
- 노드 밖 백업으로 분리된 시험 디렉터리·venv·서비스에 복원하는 순서를 작성한다.
- RPO 24시간·대체 실행 컨텍스트 준비 후 RTO 60분의 측정 시작/종료를 정의한다.
- 기능 제한·환경 미확정·소스 검증 실패·미실행 항목을 차단 목록으로 유지한다.

## 산출물

- 실제 복원·무결성·큐/목록 순서·DJ 설정·중복 원장·rollback 결과.
- Jev API의 독립 RC 결과표와 1.0.0에 넘길 manifest·known limitations. 지원 검증 범위는 Jev API로 유지하고 운영에 활성화할 프로필 하나를 별도 명시한다.
- 필수 게이트별 PASS/FAIL/미검증 및 변경 명세 합의가 필요한 항목 기록.

## LXC 검증

- `DiscordBotLXC`: 노드 밖 복사본을 다른 시험 DB 경로에 복원하고 내용·권한을 확인한다.
- `DiscordBotLXC의 중계`: Jev API의 시험 원장/tombstone을 복원해 불명 요청 재실행·추가 provider dispatch를 차단한다. hosted 원격 실행 종료/횟수는 복원 시험으로 증명하지 않는다.
- 양쪽: 복원된 컨텍스트에서 확인 토큰 무효화·자동 음성 재개 금지를 확인한다.
- 검증한 이전 후보·프로필 manifest·스키마 호환 조건으로 중지/drain·명시 프로필 지정·재기동·기본 기능·rollback을 시험한다. 요청 수명 중 프로필을 바꾸지 않고 신규 run/session에서도 불명 tombstone을 보존한다. 최초 출시 전이므로 이전 정식 릴리스가 존재한다고 가정하지 않는다.
- 운영 DB 덮어쓰기·운영 음성 접속·제3 LXC 생성 없이 지정 LXC에서 실행한다.

## 통과 기준

- 외부 백업 실제 복원·RPO/RTO·무결성·rollback·보안·회귀 게이트가 충족된다.
- Jev API의 필수 시험이 미실행·실패이면 해당 단계를 완료하지 않는다. mock·개발 소규모 시험으로 실제 품질·장시간 인수를 대체하지 않는다.
- 승인된 소스 범위 결정에 따라 승인 음원의 권리·매핑·기술 인수와 링크·목록 관리가 검증된다.
- 승인 음원 대안만 성공한 상태를 원래 전체 명세의 1.0.0 완료로 표시하지 않는다.

## 중단·후속 처리

- Jev API에서 필수 실패·미실행·소스 미해결·증거 불일치가 있으면 정식 운영 승격을 차단한다. 미통과 프로필을 출시 범위에서 제외하려면 명세·인수 기준의 명시적 범위 변경 결정을 먼저 남긴다.
- 변경 명세가 필요하면 원래 요구와 제외 범위·버전 의미를 검토 가능한 문서로 제시한다.
- 모든 게이트 통과 뒤 [1.0.0](../1.0.0/README.md)의 실제 배포 계획으로 진행한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
