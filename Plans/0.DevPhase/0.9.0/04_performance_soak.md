- 단계: `4 / 5`
- 선행: [Phase 3](03_korean_acceptance.md) 고정 후보의 한국어 인수 통과.
- 검증 호스트: `DiscordBotLXC`의 별도 계정 중계·봇
- 상태: **PLANNED — 필수 인수 전**
- 추론 계약: [프로필 선택·시험 실행](../INFERENCE_PROFILES.md), [개발 명세 v1.3](../../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md), 내부 API schema `1.2`.

## 목표

- 실제 DiscordBotLXC의 봇·중계에서 경로별 지연·공유 자원 경합·장시간 안정성을 측정한다.
- 제한시간 초과와 대기 압력이 안전한 미실행으로 끝나는지 확인한다.

## 로컬 코드 작업

- Jev API에서 준비 5회 후 1·2·3단계 경로별 최소 100요청을 측정한다. hosted는 명시적 초기 호출이며 hosted 준비 호출도 run 한도/비용에 포함한다. 동일 source·fixture·snapshot·seed·정책으로 독립 실행하고 점수를 합치지 않는다.
- Jev API 경로의 요청 동시 1개·순간 4개, 무재생·실제 음성 재생은 공통으로 분리한다.
- 512토큰 이하 목표 시험과 단계별 1,024토큰 상한 시험을 나눈다.
- queue/inference/total·외부 검색·음성 연결·오디오 시작 시간을 개별 집계한다.
- Jev API 프로필에서 곡 전환·자연어 요청을 섞은 최소 8시간 연속 재생과 별도 서비스/네트워크 장애 주입을 수행한다. 합쳐서 8시간으로 계산하지 않으며 강제 종료 구간은 연속 재생 시간에 포함하지 않는다. hosted의 요청 수×최대 단계 수·준비 호출에 맞춰 한도를 명시 설정하고 한도 도달/미완주는 미통과로 기록한다.

## 산출물

- 공통 LXC 제한·동일 노드 부하와 run별 모델/API·prompt/threshold·config_hash·run_id 기록. hosted는 반환 모델/API 버전·측정시각·네트워크 조건·관측 가능한 비용/usage와 미제공 값을 기록한다.
- Jev API 프로필/경로별 중앙값·p95·최댓값·오류율·취소·timeout.
- 8시간 연속 시험 타임라인·오디오 경합·RSS·OOM·재시작·대기 수 기록.

## LXC 검증

- `DiscordBotLXC`: 전체 1·2·3단계 요청과 부하 발생기를 실행하고 구조화 조회·편집 p95 및 실제 음성 전환·지연을 측정한다.
- `DiscordBotLXC의 중계`: 같은 gateway에서 선택 프로필의 판단·provider_calls·원장·대기·자원을 계측한다. 모델 단독 벤치마크는 전체 경로 지연과 구분한다.
- 양쪽: 전처리·후보 생성·대기를 포함한 공통 12초와 단계 제한을 검증한다.
- 예정 runner의 `benchmark`와 `soak` suite를 Jev API 프로필에 각각 실행해 8시간 정상 혼합 재생을 완료한다. 고정 후보/설정을 변경할 때 중지/drain·새 run/session·독립 데이터 경로·기존 tombstone 보존을 확인한다. 별도 격리 장애 시험에서 O-03·04의 음성/API 단절·서비스 재시작·강제 종료·시험 DB 부족을 주입한다.
- 부하·모델·음성·빌드·시험 실행은 원격에서만 수행하고 성공 사례만 추려 보고하지 않는다.

## 통과 기준

- Jev API에서 정상 부하 구조화 p95 1초, 준비 완료·무대기·<=512토큰 NL p95 3/5/7초 목표를 충족한다. hosted는 네트워크 지연을 포함하고 목표를 현재 서비스의 보장값으로 표시하지 않는다.
- 단계는 `min(4초, 공통 잔여시간)`이며 12초 뒤 늦은 결과 실행은 0건이다.
- 1,024토큰·순간 부하는 별도 지표로 보고하고 실패·미실행을 숨기지 않는다.
- Jev API의 8시간 동안 지속 오디오 끊김·데이터 손상·provider_calls 예산 초과가 없다.

## 중단·후속 처리

- 목표 미달은 원인·경로·선택 설정을 기록하고 원격 재측정한다.
- 현재 후보 시험에서 성능을 이유로 안전 상한·deadline·확인 정책을 완화하지 않는다. 시간 계약 변경은 명시적 명세·인수 기준 개정 후 새 후보의 Jev API 프로필 재검증으로 처리한다.
- 자원·코드·모델 변경 시 관련 품질·회귀를 반복하고 최종 복원 판정으로 진행한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
