# 1.0.0 Phase 2 — 도움말·지원 범위 확정

- 버전: `1.0.0`
- 단계: `2 / 5`
- 선행: [Phase 1](01_release_manifest.md) 검증 후보·제약 고정.
- 검증 호스트: `DiscordBotLXC`의 봇·별도 계정 중계
- 상태: **PLANNED — 필수 인수 전**
- 추론 계약: [프로필 선택·시험 실행](../INFERENCE_PROFILES.md), [개발 명세 v1.3](../../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md), 내부 API schema `1.2`.

## 목표

- 사용자가 실제 지원하는 명령·권한·재생 소스·자연어 한계를 이해하게 한다.
- 목표 수치를 실측 보장으로 오인하지 않도록 도움말과 운영 안내를 맞춘다.

## 로컬 코드 작업

- DJ 편집 권한·같은 음성채널 조건·확인/취소·일괄 변경 안내를 도움말에 반영한다.
- 저장 목록과 대기열·현재곡 범위, 정지/계속/퇴장 의미를 구체적 예로 설명한다.
- Jev API의 자연어 최대 3단계 판단/질문·request_provider_calls_total≤3·모호하면 확인·장애 시 슬래시/버튼 대체를 안내한다.
- 메타데이터 검색과 직접 오디오 재생 지원을 분리하고 실제 허용 소스를 표시한다.
- run별 실제 실측 조건·지원 입력·개인정보 보존·삭제 요청·장애 대응 방법을 작성한다. hosted 운영에서는 전송하는 최소 원문/후보 범위와 확인한 외부 보존 정책을 안내하고 내부 삭제가 공급자 삭제를 보장한다고 쓰지 않는다.

## 산출물

- 한국어 도움말·초기 설정 안내·버튼/확인 문구·release note.
- 실제 지원·미지원 소스 및 정책·권리 검증 상태와 사용 가능한 대안 안내.
- 운영 점검·삭제·백업·모델/프로필 변경·사고 문의 경로를 설명하는 문서. 테스터에게 예정 runner의 한 번의 --profile 선택·--dry-run 의미·분리 경로를 설명하고, 운영자에게는 별도 명시 프로필 지정·중지/drain·재시작·rollback을 안내한다. 일반 멤버에게 운영 provider 변경 권한을 제공하지 않는다.

## LXC 검증

- `DiscordBotLXC`: 테스트 guild에서 도움말·권한 오류·확인·소스 제한 표시를 확인한다.
- `DiscordBotLXC의 중계`: Jev API의 모델/API·정책 정보와 지표가 문서의 지원 범위와 일치하는지 확인한다. 운영에서 선택하지 않은 지원 프로필은 검증 범위와 구분 표시한다.
- 일반 멤버와 DJ로 같은 명령을 실행해 표시된 권한이 실제 동작과 맞는지 확인한다.
- Jev 장애·모호한 입력·검색 할당량 실패가 문서대로 안전한 대안을 제공하는지 확인한다.
- 도움말 변경을 포함한 lint·빌드·시험은 DiscordBotLXC의 봇·중계에서만 실행한다.

## 통과 기준

- 도움말에 없는 숨은 실행·권한 확장·임의 추측이 없다.
- 1.0.0은 승인 음원을 재생하며 YouTube는 링크/목록 관리만 지원한다고 안내한다. 직접 YouTube 오디오는 지원하지 않으며 승인 음원을 직접 YouTube 재생이라고 표시하지 않는다.
- 지연 목표와 run별 실제 측정 조건, 안전 deadline, 미지원 기능을 정확히 설명한다. hosted 가격·한도·모델 정보의 출처/확인시각과 미확정 값을 구분하고 Jev API 프로필 점수를 합산한 보장값을 제시하지 않는다.
- 문서·앱 UI 내용 변경이 후보를 바꾸면 새 SHA의 필요한 회귀를 통과한다.

## 중단·후속 처리

- 도움말과 실제 기능이 다르면 배포 전에 코드·문구·명세 중 필요한 대상을 수정한다.
- 전체 출시 범위 변경은 변경 명세의 명시적 합의 없이는 완료 기준에서 빼지 않는다.
- 후보와 안내가 일치하면 Phase 3의 실제 배포로 진행한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
