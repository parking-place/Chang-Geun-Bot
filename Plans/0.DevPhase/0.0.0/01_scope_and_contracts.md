## 목표

명세 1.3을 제품 1.0.0의 기준으로 고정하고 요구사항마다 구현 버전·시험·차단 조건을 연결한다. 이 단계는 실행 환경을 마련하기 전의 문서 계약 검토이며 제품 시험을 요구하지 않는다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

- 명세 §1~20과 비공개 서버 기록을 읽고 현재 구현 코드가 없는 초기 상태를 기준선에 남긴다.
- P0·P1 포함 기능과 Jev API 전용 실제 판단과 격리mock 시험 계약을 정리한다. P2 및 음성 인식/녹음/웹/다른 외부 LLM/동시 다중 음성은 제외한다.
- 명세의 INV 불변식을 도메인·API·실행기 계약으로 분해한다. 모델은 후보만 선택하며 실제 ID·권한·확인은 봇이 결정한다.
- 저장 목록/현재곡/대기열 및 track ID/entry ID를 구분하는 용어집과 action allowlist 변경 규칙을 작성한다.
- 시험 T/N 및 보충 P/O/E와 프로필 선택·전환 B-01~12의 책임을 TEST_MATRIX에 연결하고 단계 상태를 PLANNED로 시작한다. hosted 내부 forward는 `null`/`unavailable`로 기록한다.
- provider/profile_id/비밀값 제외 config hash는 요청 생애 동안 고정하며 불일치·자동 fallback·진행 중 hot-switch를 거절하는 계약을 명시한다.

## 산출물

- 범위 기준선, 요구사항 추적표, 미확정 입력/차단 목록, 중요한 설계 결정 기록의 양식.
- API schema 1.2·제품 버전·명세 버전의 구분 및 변경 시 회귀 범위 규칙.
- 검토한 문서 revision·검토 범위·결정/미확정 항목을 담은 문서 계약 검토 증거.

## LXC 검증

- 이 단계에서는 LXC 접속·설치·runner·제품 실행·시험을 요구하지 않는다. 후속 계약 fixture와 거절 조건을 문서로 설계한다.
- E-01 소스/전송 범위 확인과 실제 LXC 검증은 02·05단계에서 수행한다. 현재 단계에 가상의 LXC PASS를 기록하지 않는다.
- 설치·빌드·lint·타입검사·단위/mock 시험 등 향후 모든 제품 실행은 지정 LXC에서만 한다. 이 단계의 문서 읽기 검토는 로컬에서 가능하다.

## 통과 기준

- [ ] 실측/기본 설계/비공개 기록/미확정 값이 구분되며 구현 전 기능이 완료로 표시되지 않는다.
- [ ] 문서 계약 검토 증거가 있다. 검토 통과 상태 REVIEWED는 02단계의 선행 조건으로만 사용하며 제품 검증 VERIFIED와 구분한다.

## 중단·후속 처리

요구사항 충돌은 출처·영향·선택안을 결정 기록에 남긴다. 구현 편의에 맞춰 DJ 정책이나 3회 상한을 묵시적으로 바꾸지 않는다.

문서 검토 통과 후 [버전 목차](README.md)와 [STATUS](../STATUS.md)에 REVIEWED 근거를 연결한다. 계획 파일 생성만으로 검토를 통과 처리하지 않는다. [증거 양식](../EVIDENCE_TEMPLATE.md)은 문서 검토 범위에 맞게 사용하며 실제 실행 증거는 후속 단계에서 별도로 기록한다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
