## 목표

- 목록을 독립 대기열로 복사하고 새 곡 추가가 현재 상태를 예상대로 유지한다.
- 사용자가 번호로 지정한 대상은 해당 시점의 entry ID/버전으로만 변경한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 코드·문서 작성과 읽기 검토만 한다. 모든 설치·검사·시험·build·오디오 실행은 LXC에서 수행한다.

- /재생 곡 또는 목록은 끝에 추가하고 재생이 멈췄으며 PAUSED가 아닐 때 시작한다. /재생 무입력은 기존 대기열 재개 확인·빈 대기열 안내로 처리한다.
- 명시 채널/요청자 채널/선택 메뉴와 DJ·동일 음성채널·원격 정책을 공통 정책으로 연결한다.
- 목록 entry를 새 queue entry로 복사한다. 이후 queue 셔플/제거/재생과 저장 목록 편집이 서로 전파되지 않는다.
- /다음추가는 queue 앞에 삽입하고 여러 곡의 원래 순서를 보존한다. 기본 영상 ID 중복 거절·명시 허용 정책을 적용한다.
- /대기열 보기·제거·이동·비우기·전체 교체를 구현한다. 1번은 다음곡, current는 번호 없이 표시하고 비우기/교체 범위는 확인한다.

## 산출물

- queue repository/executor·목록 load·재생/다음추가 핸들러.
- entry ID/queue version 스냅샷과 번호 선택 UI.
- 현재곡·대기항목·저장 원본의 독립·범위 미리보기 fixture.

## LXC 검증

- DiscordBotLXC에서 queue 복사/순서/중복/버전 단위·DB 통합시험과 실제 테스트 Discord 명령을 수행한다.
- T-07·08·11과 재생중/IDLE/PAUSED에서 추가, 다음추가 다중 순서, 비우기의 current 유지·교체 확인을 검사한다.
- 두 DJ가 번호 제거/이동을 경합시키고 stale snapshot은 재확인되어 다른 entry가 수정되지 않는지 확인한다.

## 통과 기준

- T-07·08·11 실제 시험이 통과하며 PAUSED 중 추가가 재개를 유발하지 않는다.
- 저장 목록 변경이 복사된 queue/current에 영향을 주지 않고 대기열 편집도 원본을 바꾸지 않는다.
- 대기열 비우기는 current 유지, 전체 교체는 current 중단/변경 범위 표시와 확인 후 실행한다.

## 중단·후속 처리

- 원본 공유·번호 대체 제거·자동 재개·확인없는 비우기/교체가 있으면 관련 동작을 비활성한다.
- 자연어 번호 해석/삭제는 0.6.0에서 같은 snapshot/실행기에 연결하며 현재 버전에는 모델을 추가하지 않는다.
