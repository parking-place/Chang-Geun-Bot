## 목표

- Jev 없이 핵심 음악봇을 실제 허용 소스/Discord 환경에서 인수한다.
- 현재곡 포함 저장·한국어 패널·핵심 T 시나리오를 완성하되 최종 자연어 제품 완료와 구분한다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 코드·문서 작성과 읽기 검토만 한다. 모든 설치·검사·시험·build·오디오 실행은 LXC에서 수행한다.

- 재생 패널에 원제목/원본 링크·요청자·음성채널·다음곡·반복 상태를 표시하고 제한된 빈도로 기존 메시지를 갱신한다.
- 패널 삭제 시 재생을 유지하고 필요할 때 다시 만든다. Discord rate limit/응답 실패를 오디오 실패와 구분한다.
- /대기열 저장은 기본 current 제외·명시 포함 시 첫 항목으로 복사한다. 동일 검색 이름은 자동 덮어쓰지 않고 새 목록/범위를 선택하게 한다.
- T-07~20의 실제 시험과 T-01~03·05·06·10 구조화 회귀를 연결하고 fake/실제 결과를 별도로 기록한다.
- 현재 지원 source와 YouTube 직접 오디오의 1.0.0 범위 제외/비활성 상태, Jev API 없이 동작 가능한 기능, 남은 최종 제품 요구를 도움말/버전 기록에 표시한다. Jev API/gateway 장애에서 구조화 재생을 유지하는 회귀는 0.5.0 이후 실제 연동 증거로 보완한다.

## 산출물

- 실제 session 기반 재생 패널·queue 저장 핸들러.
- 현재곡 포함/제외·이름 충돌·패널 삭제·전체 핵심 T 시험 소스.
- 0.4.0 실제 LXC 인수 증거와 0.5.0/0.6.0 연동 계약.

## LXC 검증

- DiscordBotLXC에서 lint·타입검사·단위/mock·DB 통합·build와 실제 테스트 Discord/음성 인수를 수행한다.
- T-09·10으로 current 포함/제외/이름 충돌을 검증하고 panel 삭제/재생 유지·갱신 빈도·공개 DJ 버튼 권한을 검사한다.
- T-07~20과 기존 구조화 T 회귀를 실행한다. 실제 입력·source·버전·상태/DB 차이·오류·증거를 기록한다.

## 통과 기준

- 현재 범위 T-01~03·05~20이 통과하며 T-04 자연어는 0.6.0 미구현으로 남는다.
- 패널·저장 범위·원본/queue 분리·취소/복구 정책이 모두 실제 실행 증거로 확인된다.
- Jev 없이 핵심 기능이 동작하고 source 대안/유튜브 직접 재생 상태가 정확히 표시된다.

## 중단·후속 처리

- 필수 실제 시험이 미실행/실패면 0.4.0을 완료로 표시하지 않는다. 관련 수정 후 필요한 시험만 재실행한다.
- 0.5.0 API·0.6.0 자연어, 0.7.0 편의, 0.8.0 안정화/부하/복원과 0.9.0 RC 전까지 전체 제품 출시 완료로 표시하지 않는다.
