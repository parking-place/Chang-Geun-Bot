## 목표

- 실재생 도입 시점부터 늦은 결과·강제 퇴장·연속 실패·재시작을 안전하게 처리한다.
- 운영 안정화 전이라도 무한 재시도·자동 재입장·데이터 손실을 허용하지 않는다.

## 추론 프로필 적용

[Jev API 전용 계약](../INFERENCE_PROFILES.md)을 따른다. 실제 자연어 판단은 `jev-api`만 사용하며 봇과 TLS 중계·영속 원장은 DiscordBotLXC에서 별도 계정으로 실행한다. 현재 배치는 [환경 계약](../ENVIRONMENT.md)을 따른다. `mock`은 지정 LXC의 격리 회귀 전용이다. 구조화 명령은 추론 없이 실행하고, API 장애가 기존 재생·슬래시·버튼을 막지 않게 한다.

## 로컬 코드 작업

로컬은 코드·문서 작성과 읽기 검토만 한다. 모든 설치·검사·시험·build·오디오 실행은 LXC에서 수행한다.

- 봇 외 청취자 없음 180초·대기열 종료 IDLE 300초·PAUSED 1,800초 타이머를 구현하고 만료 직전에 상태/청취자/generation을 다시 검사한다.
- 곡별 첫 시도 후 1회 재시도, 이후 실패 기록/다음곡, 3곡 연속 실패 중단/안내 정책을 작성한다. 저장 목록에서 실패곡을 자동 삭제하지 않는다.
- 네트워크 손실 재연결은 최대 3회이며 현 세션/generation과 기한에만 허용한다. 관리자 강제 퇴장·명시적 leave/stop 취소를 재연결과 구분한다.
- 프로세스 재시작은 DB 설정/목록/queue와 중단 current를 앞에 복원하고 미완료 확인을 무효화한다. 자동 음성 입장/재생은 하지 않는다.
- late resolve/end/reconnect·중복 취소·재시작 불명 외부 실행을 폐기한다. 실패 안내와 슬래시 재개 경로를 작성한다.

## 산출물

- 유휴 타이머·재시도/연속 실패·재연결·재시작 복구 코드.
- 타이머 직전 입장·네트워크 단절·강제 퇴장·프로세스 종료 fixture.
- 보존/복원/취소 사유·연속 실패 안내·미완료 확인 정리 정책.

## LXC 검증

- DiscordBotLXC에서 T-15·17·18·19·20을 fake 시간/네트워크 시험과 실제 테스트 음성/프로세스 재시작으로 검증한다.
- 180초 직전 청취자 복귀, PAUSED 유지/장기 유휴, 3연속 source 실패·늦은 검색 완료·강제 퇴장을 검사한다.
- 재시작 뒤 current 같은 entry ID·queue 순서·목록/설정 복원과 자동 입장/재생 0건·확인 무효화를 확인한다.

## 통과 기준

- T-15·17·18·19·20이 통과하며 timeout/취소/퇴장 후 늦은 실행 0건이다.
- 타이머가 현재 사용자/상태를 잘못 판단해 퇴장시키지 않고 재시도 상한이 정확히 적용된다.
- 재시작 복원 후 DJ의 명시적 요청 전에는 오디오/음성 연결을 시작하지 않는다.

## 중단·후속 처리

- 자동 재입장·무한 실패 반복·current 손실·stale confirmation 실행이 있으면 0.4.0 gate를 닫는다.
- 8시간 재생·OOM·DB 디스크 부족·대규모 장애/복원/관측 시험은 0.8.0에서 강화한다. 이 기본 정책을 뒤로 미루지 않는다.

## Jev API 전용 인수 범위

2026-09-27 사용자 결정에 따라 실제 제공자는 `jev-api` 하나다. [전용 계약](../INFERENCE_PROFILES.md)을 따른다. 과거 로컬 모델 시험은 보존 기록이며 이 단계의 선행 조건이나 출시 게이트가 아니다. 권한·확인·데이터·최대3단계/3 dispatch·전체12초/단계4초·실패 후 추가 전송0 규칙은 유지한다. hosted 내부 forward와 미공개 model revision은 null/unavailable로 남긴다.
