[Jev API 전용 결정](../../docs/decisions/0005-jev-api-only.md)과 [명세1.3](../CHANGGEUN_DEVELOPMENT_SPEC_v1.3.md)이 기준이다. 로컬 모델 인수·양쪽 제공자 비교는 제외하며 기능·안전·품질 기준은 유지한다. 아래 수치는 계약/목표이고 현재 달성 결과가 아니다.

## 한국어 품질

Jev API 고정 후보에 개발과 독립된 held-out 최소200문장(명확120·모호/비명령/부정60·우회/교란20)을 적용한다. 신규 곡명/목록명을 포함하고 prompt/threshold·정답·fixture·snapshot/seed를 평가 전에 잠근다. 명확한 지원 명령의 의도·대상 자동 해석≥95%이며 불필요한 UI 확인은 자동 성공에 포함하지 않는다. 확인 필요·최종 ActionPlan·1/2/조건부3단계를 별도 채점한다. 권한 우회·무확인 위험 실행·경쟁 대상 오수정·취소/만료 뒤 실행은 시험에서0건이어야 한다.

개발·mock·과거 로컬 시험 성적을 최종 품질로 합산하지 않는다. Jev API 내부 forward 두 값과 미공개 model revision은 null/source=unavailable로 유지한다. 모델 confidence를 정확도 백분율로 표시하지 않는다.

## 출시 후보 고정·승격

동일 source SHA·bot/gateway lock·API1.2·DB/원장schema·Jev API endpoint/adapter·요청/반환 model·측정시각·provider/profile/config hash·prompt/threshold·fixture/held-out hash·한도를 manifest에 연결한다. 미공개 hosted model revision을 재현 가능한 로컬 pin으로 꾸미지 않는다. 비밀값은 manifest에 넣지 않는다.

1.0.0은 위 필수 증거가 연결된 동일 후보를 실제 운영 Jev API 프로필로 배포하고 smoke·지원/복구를 확인한 뒤 완료한다. 코드/의존성/설정/마이그레이션/프롬프트 변경은 영향 시험과 필요한 장시간 시험을 다시 요구한다. 공식 출시·태그·전체 DONE은 계획 변경이나 부분 시험만으로 만들지 않는다.

## 1.0.1 추가 출시 기준 — YouTube 재생

[후속 범위 결정](../../docs/decisions/0006-youtube-and-prefix-roadmap.md)에 따라 1.0.0의 소스 제한을 확장한다. 개별 승인 음원 매핑 없이 지원 공개 영상의 실제 오디오가 재생되어야 하며 메타데이터/링크 성공으로 대체하지 않는다. Y-01~18, 직접 재생 방식의 채택 근거, 공통 DJ/채널·세대·취소·URL/네트워크·임시주소 보호·복원·기능 비활성화/rollback을 인수한다.

신규 소스의 지원 영상20개 이상·재생 시작/전환100회·준비5회·성공률≥95%·준비된 음성 연결의 첫오디오 p95≤10초를 계획 목표로 둔다. 항목 준비 접수부터 대기/재시도 포함 총25초·누적 resolve15초/startup10초의 종료 상한과 성능 목표를 구분하고 오류·timeout을 제외하지 않는다. 연속8시간 혼합 재생을 새 후보에서 검증한다. 자세한 조건은 [1.0.1 Phase 5](1.0.1/05_live_acceptance_and_release.md)를 따른다.

## 1.0.2 추가 출시 기준 — 지정 채널 한국어 호출

C-01~18로 Message Content Intent·실제 봇 권한·명시 채널 목록·정확한 `!!창근아` 문법·메시지 중복·수정/삭제·공개 응답·권한 재검증을 인수한다. 비허용 채널/비호출 메시지를 Jev로 전송하지 않고 수신과 저장·처리를 구분한다. intent 장애가 기존 슬래시·버튼·음성 기능을 함께 막지 않게 한다.

Jev API Only·3단계/3dispatch·12초/단계4초, 위험 실행0·독립 한국어 최소200문장/명확한 지원 명령≥95% 및 영향 경로의 성능/장시간 기준을 유지한다. 일반 메시지에 interaction의 ephemeral/defer를 제공한다고 표시하지 않는다. 실제 복수 허용 채널과 비허용 채널에서 사용자 조작을 인수하고 [1.0.2 계획](1.0.2/README.md)의 고정 후보로 배포/rollback을 확인한다.

두 버전 모두 현재 IN_PROGRESS다. [개발 후보·부분 검증](../../evidence/public/youtube-prefix-20260928.md)을 기록하고 1.0.0을 완료 처리하지 않았으며 실제 인수 순서는 1.0.0 → 1.0.1 → 1.0.2다.

## 1.0.3 추가 출시 기준 — 주시 채널 관리

[1.0.3 계획](1.0.3/README.md)의 `/주시`6명령과 W-01~20, 영향 C/Y/T/N/B/O 회귀를 동일 후보에 연결한다. 관리자만 변경·미주시 채널에서 관리 복구·일반 슬래시/멘션 허용 범위 불변·관리 Jev0회·최초1회 이관·빈 목록/꺼짐/재시작 유지가 필수다.

설정 변경과 진행 요청/확인/시작 전 재생 승인 무효화를 원자적으로 검증한다. 허가 없는 변경·중복 효과·취소 뒤 실행·다른 출처 큐 손실은0건이어야 한다. 현재곡과 아직 시작하지 않은 항목의 처리를 실제 음성 인수에서 구분하고, 등록/켜기로 과거 승인이 되살아나지 않아야 한다.

실제 주시2채널/미주시1채널과 관리자/DJ/일반 사용자 조합, 합성 경합≥100회, 초기 이관·후보 교체·별도 DB 복원·이전 바이너리/이전 DB 묶음 rollback을 인수한다. 최초 접수 표시1초·변경 후 반영1초는 계측 목표다. 이전 버전의 독립 품질·실제8시간·미디어 안정성 미통과 항목은 계속 필수이며 관리 기능 시험으로 대체하지 않는다. 세부 조건은 [Phase 5](1.0.3/05_acceptance_and_rollout.md)를 따른다.

1.0.3은 현재 IN_PROGRESS다. [관리 구현과 자동 회귀](../../evidence/public/watch-channels-20260928.md)를 추가했으며 전체 W/이전 인수 미완료 상태로 제품 VERSION·태그·DONE을 만들지 않는다. 정식 승격 순서는 1.0.0 → 1.0.1 → 1.0.2 → 1.0.3이다.
