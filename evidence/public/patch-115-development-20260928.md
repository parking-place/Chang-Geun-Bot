`/주시 이력`은 서버 관리자에게 최근90일·최대100건의 변경 시각·행동·revision·취소/승인 만료 건수를 10건씩 개인 응답으로 보여준다. 조회와 페이지 이동마다 최신 Manage Guild/소유자와 채널 접근을 다시 확인한다. `/운영 사용량`은 현재 서버의 최근24시간 명령 기록·접두어 요청/취소·주시 변경·완료곡만 집계한다. 중계 호출 예산은 별도 인증된 읽기 전용 API로 **전체 공유 run**의 예약 수만 보여주며 서버별 소비나 실제 비용으로 귀속하지 않는다. 원문·계정/키·요청 payload는 표시하지 않는다.

접두어 진행 응답의 `요청 취소` 버튼은 원래 요청자·서버·채널·request ID를 결합한다. DB의 running/waiting 상태를 원자적으로 cancelled로 바꾸고 확인 토큰을 소비한 뒤 진행 task를 취소한다. 이미 committed/finished면 성공으로 표시하지 않는다. 응답 편집 직전에도 취소 상태를 검사해 늦은 결과가 다시 보이지 않게 했다. Jev에 이미 보낸 호출의 예약은 환불하거나 자동 재전송하지 않는다. 코드가 바뀌지 않은 뒤 추가한 100회 DB 취소/커밋 동시 경합에서 취소 성공과 커밋 성공의 중복은 0이었다. 슬래시 `/부탁`의 동일 버튼·공개 버튼 재전송/응답 유실 전건은 별도 잔여다.

**사용자 조작 확인:** 사용자가 관리자 `/주시 이력`·`/운영 사용량`의 개인 응답이 정상이고, `!!창근아` 진행 응답의 본인 `요청 취소` 버튼도 실제로 성공했다고 답했다. 타인 버튼·권한 회수·여러 채널/서버 조합을 이 답변만으로 PASS 처리하지 않는다.

**남은 인수:** 실제 비관리자/DJ의 거절·서버 격리, 취소 버튼의 Discord 경합/재전송, 주시2·미주시1채널의 모든 W-01~20 권한·음성·재연결·재시작·11~20채널·복귀, 봇/중계 이전 wheel+DB 복귀가 필요하다. 사용자 화면 결과가 확인돼도 이 모든 조건을 자동 PASS로 합치지 않는다. `VERSION`·태그·`DONE`은 변경하지 않는다.
