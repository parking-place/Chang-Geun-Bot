YouTube 작업자가 첫 PCM 이전에 판정할 수 있는 지원 제외·사용 불가 상태를 안전한 고정 코드로 전달한다. 원문 upstream 오류·signed URL은 응답/기록에 넣지 않는다. 미확정/그 외 준비 실패는 계속 보수적인 코드로 남긴다. 음성 runtime은 실패 유형별 고정 후속 행동을 최근 상태에 기록하고 `/현재곡`에 5분간 표시한다. 알림 실패가 다음 곡 전환을 막지 않게 했다. 이 분류만으로 원인을 모두 밝혀내거나 실제 성공률을 개선했다고 주장하지 않는다.

`/최근곡`은 기존 서버의 성공 종료 이력 중 최근30일·최대100개를 10개씩 보여주고, 선택 시 새로운 `TRACK_PLAY` 요청으로 DJ/채널/음성·현재 곡 지원 조건을 다시 검사한다. 이력 조회는 Jev를 사용하지 않는다. 실패·중단을 완료 이력으로 새로 기록하지 않는다. 별도 데이터 이관이나 원본 삭제는 없다.

**이전 1.1.3 실제 오류 수정:** 사용자가 만료곡 선택에서 “요청 조건이 맞지 않아 실행하지 않았어”를 보고했다. 페이지 최신 조회와 선택 실행에 같은 interaction ID를 써 요청 본문 충돌이 났다. 조회용 ID를 분리한 `patch114a` 적용 후 사용자가 만료곡 선택 정상이라고 확인했다. 사용자는 현재 완료 이력이 없다고 답해 `/최근곡`의 실제 곡 선택·청취 인수는 아직 미실행이다.

**남은 인수:** 상세 단계별 오류 주입, 실제 실패 안내·최근 완료곡 재생/청취, 권한 회수·재전송 경합과 이전 후보/DB 복귀를 각각 기록해야 한다. 95/100 첫 PCM은 Discord 음성 시작/전환·청취100회나8시간 운용을 대신하지 않는다. 이전 두 후보의93/100 실패 기록도 그대로 둔다. `VERSION`·태그·`DONE`은 변경하지 않는다.
