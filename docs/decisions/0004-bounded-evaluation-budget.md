# 0004 — 개발·최종 평가의 명시적 호출 예산

사용자가 0.0.0부터 1.0.0까지 구현·검증을 요청했다. [전용 결정0005](0005-jev-api-only.md)에 따른 Jev API 평가·경로별 부하·8시간 시험은 20회 smoke 한도와 분리한다. 평가를 수행하는 데 필요한 호출량을 먼저 산출하고 별도 고정 프로필·run에서 실행한다.

| 시험 | 최대 판단 호출 계획 |
| --- | --- |
| 한국어 개발 37문장 | 111 |
| held-out 200문장 | 600 |
| 준비 5회·1/2/3단계 각 100요청 | 605 |
| 8시간, 분당 최대 1개 AI 요청·요청당 최대 3단계 | 1,440 |
| 합계 | 2,756 |

평가 프로필의 run 상한은 **3,000 dispatch**이며 실패·취소·전송 불명도 포함한다. 20회 초과는 `eval-` profile_id와 명시 `run_purpose=development-evaluation|release-evaluation`에서만 허용한다. 일반 smoke의 20회 예산, 요청당 최대3회, 단일 전송·자동 재시도/fallback 금지, 영속 예약/tombstone은 유지한다. 같은 run의 상한 변경·원장 삭제·run 반복 생성으로 예산을 우회하지 않는다.

이는 전체 계획 실행에 필요한 제한된 시험 예산이며 새 서비스/유료 구독 구매가 아니다. 공개 단가는 [TypeSafe Jev 소개](https://typesafe.ai/blog/introducing-system-one-models-and-jev)를 확인했다. 비용은 입력 토큰량과 계정 계약에 따라 달라지므로 호출수만으로 정확한 청구액을 보장하지 않는다. 관측 가능한 입력 usage와 호출량을 기록하며 계정 가격/잔액/보존 정책이 미확인임을 유지한다.

37문장은 개발 세트다. 그 결과에 맞춰 고친 prompt·threshold는 별도로 고정한 후 새로운 held-out 평가를 수행한다. 작은 개발 probe와 synthetic transport 성공을 95% 품질·최종 p95·8시간 인수로 기록하지 않는다. 안전/품질 미달이면 반복 호출로 성공 기록을 고르는 대신 원인을 고치고 별도 revision의 회귀를 남긴다.
