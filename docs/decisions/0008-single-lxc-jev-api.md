# 0008 — OpenJevLXC 사용 종료와 Jev API 중계의 배치

- 날짜: 2026-09-28
- 상태: **채택·개발 후보 적용 및 실제 연결 검증**. 정식 출시 인수는 별도다.
- 사용자 지시: “OpenJev는 더이상 사용하지 않아. Jev API로만 실행돼”. 이후 OpenJevLXC에 새 작업을 수행하지 않는다.

## 결정

자연어 판단은 공식 hosted Jev API만 사용한다. 내부 API 1.2의 인증·후보 제한·기한·영속 호출 예산·중복 방지는 유지하며, 중계 서비스를 DiscordBotLXC에 배치한다. 같은 서버에 중계 코드를 두는 것은 로컬 모델 실행이 아니다. torch/transformers/OpenJev와 모델 가중치를 새 실행에 연결하지 않는다.

봇은 `changgeun-dev`, 중계는 별도 `changgeun-gateway` 계정으로 실행한다. 중계는 loopback `127.0.0.1:8443`의 TLS만 받는다. hosted 키는 root 소유0600 환경 파일을 systemd가 중계에만 전달하며 봇 계정의 읽기 거절을 확인했다. 내부 토큰과 개발 인증서는 분리한다. 개발 인증서는30일 유효이며 갱신·운영 PKI 인수는 별도다. 기존 privileged LXC를 재생성하지 않는다.

## 기존 데이터와 새 실행

이전 서버가 응답하지 않아 최신 원장 전체 이관을 검증할 수 없었다. 기존 원본 DB·원장·예산·서비스·후보는 삭제하거나 수정하지 않았다. 인증된 과거 암호화 백업을 별도 보존 경로에 복원했고 해당 요청 tombstone을 새 중계에 이어받았다. 이 백업을 최신 원장 전체라고 표시하지 않는다.

새 실행은 고정 epoch `single-lxc-20260928`, 별도 프로필 `eval-jev-api-single-lxc-v1`과 config hash를 사용한다. 과거 run을 재사용해 예산을 덮어쓰지 않으며 재시작/봇 후보 교체 때 새 원장을 만들지 않는다. 개발 평가 한도는3000 dispatch이고 계정 전체의 실제 한도/비용/과거 누계는 확정되지 않았다. 새 토큰과 설정 binding으로 새 실행을 분리한다. 예산 소진 시 중단하며 원장 삭제/새 run 반복으로 우회하지 않는다.

## 적용과 검증

봇 `dev20260928k`, 중계 `dev20260928l`을 적용했다. 봇328·설치 중계41회귀, 실제 내부 TLS/Jev3단계·캐시 재사용, 실제 Discord 관리6명령·초기2채널 등록을 확인했다. 사용자가 목록·점검·끄기 확인·접두어 무응답·켜기 후 반응을 정상으로 확인했다. [실행 증거](../../evidence/public/watch-channels-20260928.md)의 한계를 유지한다.

현재 작업의 실행 위치는 이 결정과 [환경 계약](../../Plans/0.DevPhase/ENVIRONMENT.md)이 우선한다. 결정0002/0005와 이전 실행 보고의 두 서버 구성은 당시 기록으로 보존한다. 이전 서버에 의존하는 과거 재현/복원 절차를 현재 명령처럼 실행하지 않는다.
